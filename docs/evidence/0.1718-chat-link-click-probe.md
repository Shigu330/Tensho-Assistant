# 0.1718: what the game's chat sends on a click on a player's name, a probe in developer mode (X-715)

English first, then French.

## English

### Why

The user's choice of 21/11 around 11:30 (D-202 b): before deciding whether Tensho should imitate the game chat's own way of opening the
menu of a player far away (`docs/evidence/0.1688-chat-player-menu-far.md`), measure what the game's chat sends when a player's name is
clicked, without sending anything to the game.

### What the probe does (developer mode only, read-only)

- `LogViewer.HandleLinkClick(LinkData*)` (FFXIVClientStructs' signature, `MemberFunctionPointers.HandleLinkClick` checked first) is
  watched by a hook enabled only while developer mode is on (checked once a second), until the probe's 40 lines are used. The detour copies
  the link's fields, then always calls the game's own function with what it was given; it writes nothing and calls nothing else of the
  game. Nothing is read while Tensho is cut (PvP, ranked contents).
- One line per click (« Chat link probe, click N »): the link's type (and the type the chat panel sends on, type + 10, as read in 0.1688),
  its id, index and group, its three values, and whether its text is in the panel (the text itself is never read).
- When the game then opens a menu from its chat (Dalamud's `IContextMenu`, read only), one line (« menu after click N ») says what the menu
  aims at: content id, home world, object in range, length of the name; and which of the click's values match them (a half of the content
  id, the home world, the object id). A menu of the chat with no click just before is said too (a right click may go another way).
- Never a name, never a whole identifier (other players' data): values from −99 999 to 99 999 as they are (types, indexes, worlds), larger
  ones by their last three hexadecimal digits; the comparison is made in memory and only named.

### The in-game test that measures (T-0.1718-1)

In developer mode, click a player's name in the game's own chat, with the left button then the right one: a player near you, a player far
away on your world, a player of another world. The « Chat link probe » lines of the log (dalamud.log) then say what the chat sent each
time and whether the values name the player (a content id) or only a place in the game's log.

### The decision that follows (D-203)

- a (applied until then): keep it so: near you, the game's menu of that character; far away, the line in the game's own chat.
  For: nothing fragile, never another player's menu. Against: far away, the game's chat is still needed.
- b: imitate the event measured, only if the measure shows values that name the player for sure, with a check at each opening (the
  menu's target compared with the player wanted, the menu closed otherwise). For: the game's whole menu for a player far away, other
  worlds included. Against: an internal unnamed event that a game update can change without a sign; a risk of opening another player's
  menu (« Report » included); to check again after each game update.

# 0.1718 : ce que le chat du jeu envoie au clic sur le nom d'un joueur, une sonde en mode développeur (X-715)

L'anglais d'abord, puis le français.

## Français

### Pourquoi

Choix de l'utilisateur du 21/11 vers 11 h 30 (D-202 b) : avant de décider si Tensho doit imiter la façon du chat du jeu d'ouvrir le menu
d'un joueur loin (`docs/evidence/0.1688-chat-player-menu-far.md`), mesurer ce que le chat du jeu envoie au clic sur le nom d'un joueur,
sans rien envoyer au jeu.

### Ce que fait la sonde (mode développeur seulement, en lecture seule)

- `LogViewer.HandleLinkClick(LinkData*)` (signature de FFXIVClientStructs, `MemberFunctionPointers.HandleLinkClick` vérifié d'abord) est
  suivi par un crochet actif seulement en mode développeur (vérifié une fois par seconde), jusqu'à ce que les 40 lignes de la sonde soient
  écrites. Le détour copie les champs du lien, puis appelle toujours la fonction du jeu avec ce qu'elle a reçu ; il n'écrit rien et
  n'appelle rien d'autre du jeu. Rien n'est lu pendant que Tensho est coupé (JcJ, contenus classés).
- Une ligne par clic (« Chat link probe, click N ») : le type du lien (et le type que le panneau du chat envoie, type + 10, lu en 0.1688),
  son numéro, son index et son groupe, ses trois valeurs, et si son texte est dans le panneau (le texte lui-même n'est jamais lu).
- Quand le jeu ouvre ensuite un menu depuis son chat (`IContextMenu` de Dalamud, en lecture seule), une ligne (« menu after click N ») dit
  ce que vise le menu : identifiant de contenu, monde d'origine, objet à portée, longueur du nom ; et lesquelles des valeurs du clic leur
  correspondent (une moitié de l'identifiant de contenu, le monde d'origine, l'identifiant d'objet). Un menu du chat sans clic juste avant
  est dit aussi (un clic droit peut passer par un autre chemin).
- Jamais un nom ni un identifiant entier (données d'autres joueurs) : les valeurs de −99 999 à 99 999 telles quelles (types, index, mondes),
  les plus grandes par leurs trois derniers chiffres hexadécimaux ; la comparaison se fait en mémoire et n'est que nommée.

### L'essai en jeu qui mesure (T-0.1718-1)

En mode développeur, cliquer sur le nom d'un joueur dans le chat du jeu, du bouton gauche puis du droit : un joueur près de vous, un joueur
loin sur votre monde, un joueur d'un autre monde. Les lignes « Chat link probe » du journal (dalamud.log) disent alors ce que le chat a
envoyé à chaque fois, et si les valeurs désignent le joueur (un identifiant de contenu) ou seulement une place dans le journal du jeu.

### La décision qui suit (D-203)

- a (appliqué d'ici là) : garder ainsi : près de vous, le menu du jeu de ce personnage ; loin, la ligne du chat du jeu.
  Pour : rien de fragile, jamais le menu d'un autre joueur. Contre : loin, il faut encore passer par le chat du jeu.
- b : imiter l'événement mesuré, seulement si la mesure montre des valeurs qui désignent le joueur à coup sûr, avec une vérification à
  chaque ouverture (la cible du menu comparée au joueur voulu, menu fermé sinon). Pour : le menu entier du jeu pour un joueur loin, autre
  monde compris. Contre : un événement interne sans nom, qu'une mise à jour du jeu peut changer sans signe ; risque d'ouvrir le menu d'un
  autre joueur (« Signaler » compris) ; à revérifier à chaque mise à jour du jeu.
