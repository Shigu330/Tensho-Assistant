# X-307 — the retainers' bags the game keeps (ItemFinderModule), against the bank (0.1394)

Question (user's decision of 14/11, comparison with four plugins): does the game keep a usable copy of every retainer's bags, so that the
retainers' table (X-196) and the bank can know a retainer's stock without opening each retainer? Probe of the game (R06), read only.

## What the structure is

FFXIVClientStructs (Dalamud 15.0.4.0, game 2026.11.03), read with `tools/ApiProbe`:

- `FFXIVClientStructs.FFXIV.Client.UI.Misc.ItemFinderModule`: a user file of the game (the item finder's « search for item » data, saved per
  character), with `RetainerInventories`, a map from a retainer id to an `ItemFinderRetainerInventory`, and `IsRetainerCurrent(ulong)`.
- `ItemFinderRetainerInventory` (1 144 bytes): `EquippedItemIds` (14 × uint), `ItemIds` (175 × uint), `ItemCount` (175 × ushort),
  `CrystalQuantities` (18 × ushort). 175 = the seven retainer pages of 25 slots; 18 = the retainer's crystal slots (as container 12001).

## How it was read

`src/TenshoAssistant/Inventory/RetainerFinderReader.Dalamud.cs` copies the map on the framework thread into managed data (unavailable, never
guessed, when the module is missing or the sizes differ); `RetainerFinderCompare` (pure, test `RetainerFinder1394Tests`) compares each retainer
with the bank's saved pages of the same retainer (pages 10000 to 10006, crystals 12001). The self-check writes one line of numbers only (no item
or retainer name) to `dalamud.log` at each load.

## First reading (0.1394, 2026-11-15 07:31, the game started, the player not at a summoning bell)

```
Selftest retainer finder    OK       2 retainers in the game's copy (0 current), 346 stacks, 18 equipped pieces; 2 in the bank: same items 2/2,
same slots 0/2, high ids 14 (bank HQ 14), same crystals 2/2
```

What it says:

- The copy is there without opening any retainer in this session: both retainers of the character, their 346 stacks and 18 equipped pieces.
- **Contents: the same as the bank** for both retainers (each item, its quality and its quantity).
- **High quality**: an item id from 1 000 000 on is the HQ item (id − 1 000 000): 14 such ids, and the bank holds exactly 14 HQ stacks. The
  encoding is confirmed for these retainers.
- **Crystals**: the same 18 counts as the bank for both retainers.
- **Slots: not the bank's slots** (0 of 2): the copy does not keep the item at the slot where the retainer's pages hold it (second reading below).
- `IsRetainerCurrent` was false for both: away from a summoning bell the game does not call the copy current; the contents still matched the
  bank, saved at the last opening. A change made since (another client, the market) would not show until the game updates its copy, which the
  game does when the retainer is called: the copy is a stock, not a live view.

## Second reading (0.1395, 2026-11-15 07:38): which order the copy keeps

```
Selftest retainer finder    OK       2 retainers in the game's copy (0 current), 346 stacks, 18 equipped pieces; 2 in the bank: same items 2/2,
same slots 0/2, high ids 14 (bank HQ 14), same crystals 2/2; packed 1/2, same sequence as the bank's slots 0/2, same display order 2/2
```

- **The copy follows the retainer window's display order** (2 of 2): its stacks, read from slot 0 on, are the bank's stacks sorted by their
  display index (the order the game shows them, from ItemOrderModule), not the order of the pages' slots (0 of 2).
- Packed from slot 0 for one retainer of two: the other has empty slots between its stacks (where they fall was not read); the display
  order, not packing, is what holds for both.

## What it allows

- X-196 (retainers' table) can show every retainer's stock, HQ apart, crystals and equipped pieces, without opening each retainer: yes, from
  this copy (two retainers read, same contents as the bank).
- The bank's fallback when the visual order is missing (X-275): yes: the copy gives the items in the window's display order.
- Limits: the copy is the game's last known state of each retainer (`IsRetainerCurrent` false away from a bell), and only retainers called at
  least once on this PC are in it. Read on one character with two retainers: a character with more retainers, or after a game patch, is read
  again by the same self-check line at each load.
- Local keys only: retainer ids stay on this PC, as the bank's.
