# Universalis : annonces, historique et portées (sonde 2026-11-02, lecture seule)

Requêtes faites par l'agent avec curl, réponses tronquées ; elles fondent `Market/MarketBoard.cs` (0.270).

- `GET https://universalis.app/api/v2/Chaos/5057?listings=2&entries=2` (portée centre de données) :
  - `listings[]` : `pricePerUnit`, `quantity`, `total`, `hq`, `worldName`, `worldID`, `retainerName`, `lastReviewTime`
    (secondes Unix), `tax` ;
  - `recentHistory[]` : `hq`, `pricePerUnit`, `quantity`, `timestamp` (secondes Unix), `worldName`, `buyerName`, `total` ;
  - en plus : `dcName`, `regularSaleVelocity`, `nqSaleVelocity`, `hqSaleVelocity` (unités par jour), `minPrice`, `averagePrice`…
- `GET https://universalis.app/api/v2/Ragnarok/5057?listings=1&entries=1` (portée monde) : mêmes champs, **sans** `worldName`
  dans les annonces et l'historique (seulement `worldID` à la racine) : le monde est alors celui de la portée.
- `GET https://universalis.app/api/v2/Europe/5057?listings=1&entries=1` (portée région) : `worldName` présent.
- `GET https://universalis.app/api/v2/data-centers` : `[{ "name": "Chaos", "region": "Europe", "worlds": [...] }, …]` ; donne la
  région Universalis d'un centre de données (Japan, North-America, Europe, Oceania…).

Règle de jeu utilisée par le calcul « coût pour N unités » : une annonce du marché s'achète en entier (pas d'achat partiel).
