# 0.488 : regain de PR et traits (2026-11-04)

Demande de l'utilisateur : la mesure des PR doit tenir compte de ce qui est débloqué.

Feuilles `Trait` et `TraitTransient` (XIVAPI v2, version `0874aee069e1e7c4`) :

| Trait | Niveau | Mineur | Botaniste | Pêcheur | Description |
|---|---|---|---|---|---|
| Enhanced GP Regeneration | 70 | 192 | 193 | 194 | Raises base GP regeneration rate by one. |
| Enhanced GP Regeneration II | 80 | 236 | 237 | 238 | Raises base GP regeneration rate by a total of two. When gathering, raises base regeneration rate by one. |
| Enhanced GP Regeneration III | 83 | 239 | 240 | 241 | Raises base GP regeneration rate by a total of three. When gathering, raises base regeneration rate by one. |

Le trait niveau 70 du mineur a une quête (`Quest` 68094) : un métier peut donc l'avoir ou non au même niveau. D'où la lecture de `IUnlockState.IsTraitUnlocked` pour chaque métier.

## Utilisation

Le regain de base n'est dans aucune de ces lignes. Il est mesuré en jeu : une hausse de PR arrivant un tic après la précédente, moins le total des traits débloqués du métier. Le taux d'un autre métier est cette base plus ses propres traits.

## Limites

- « When gathering, raises base regeneration rate by one » : un taux propre à la récolte existe. Tensho ne le mesure pas, et l'utilisateur a vu ses PR s'arrêter à l'ouverture d'une fenêtre de récolte. Le temps avant le plein vaut hors récolte.
- Une mesure faite pendant une récolte pourrait compter ce +1. La dernière mesure remplace l'ancienne.
