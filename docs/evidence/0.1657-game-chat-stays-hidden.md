# 0.1657: the game chat stays hidden while Tensho's chat replaces it (X-689, X-694)

> *Traduction française plus bas.*

## Question

With « Hide the game chat's messages » on, the user saw the game's chat come back « each time » Tensho's chat window hid itself
(report of 20/11/2026 around 22:45), and, around 22:50 (capture « Coal »), hovering an item link in Tensho's chat showed the game's own
item tooltip over Tensho's item panel; the game's tooltips then made everything vanish and Tensho's chat settings could not be reached.
What gave the game's chat back, and where did the game's tooltip come from?

## Reading

`dalamud.log` of 20/11/2026 (the user's game, Tensho 0.1655), lines of the game chat hider and of the chat window's cover, with
« Under a game window » set to « Hide »:

| Time | Line |
|---|---|
| 22:58:54.786 | Chat window covered by a game window ("Hide") … windows: ItemDetail. |
| 22:58:54.795 | Game chat: its message panels shown again (0, 1, 2). |
| 22:58:55.119 | Chat window uncovered ("Hide") … |
| 22:58:55.569 | Chat window covered by a game window ("Hide") … windows: Tooltip. |
| 22:58:55.578 | Game chat: its message panels shown again (0, 1, 2). |
| 22:58:59.787 to 23:00:31 | the same pair seven more times, each with ItemDetail |

1. The game's chat came back because the rule of 0.1506 and 0.1507 (X-527, X-528 M1) gave its messages back whenever Tensho's window
   hid itself: in combat with « Hide in combat », in a duty or a cutscene with their own setting, and while a game window covered it with
   « Under a game window » set to « Hide ».
2. At 22:58:54.786 the game's item tooltip (ItemDetail) opened over Tensho's window while the game's panels were still hidden: they
   were given back only 9 ms later, because of that very tooltip. Tensho only reads ItemDetail (`Items/ItemHoverReader.Dalamud.cs`), it
   never opens it. So the game's message panel hidden by its window flag alone (`AtkUnitBase.IsVisible = false`) still answered the mouse:
   the item link of the game's message, at the same place as Tensho's, opened the game's tooltip, which covered Tensho's window, which hid
   itself and gave the game's chat back: the loop the user saw.

## Use

- X-689: `ChatHideWants.Of(wanted, competitive, gameUiHidden)`: Tensho's window hiding itself (combat, duty, cutscene, covered, faded)
  no longer gives the game's messages back. They come back only when the option is unticked, Tensho's chat window is closed or failed,
  « both chats » is chosen, in a competitive cut, which gives the hand back to the game (R03.2, DEC-038: all of Tensho stops there), or
  when Tensho is unloaded. While the game hides its own interface (cutscene, GPose), they stay as they are (Hold, unchanged).
- X-694: `GameChatHider` hides the panel's root node too (`PanelRoot`), the way the game hides its own parts (Tensho hides the game chat's
  tab bar the same way since 0.1508, and its tabs never answered the mouse); both are given back together. That a hidden root node takes
  no hover is the game's behaviour, not read in its code: the in-game test of 0.1657 checks it (hover an item link in Tensho's chat: one
  tooltip only, no « ItemDetail » cover line in the log).

# 0.1657 : le chat du jeu reste caché tant que celui de Tensho le remplace (X-689, X-694)

## Question

Avec « Cacher les messages du chat du jeu », l'utilisateur a vu le chat du jeu revenir « à chaque fois » que la fenêtre de chat de Tensho
se cachait (signalement du 20/11/2026 vers 22 h 45), et, vers 22 h 50 (capture « Charbon »), survoler un lien d'objet dans le chat de
Tensho montrait l'info-bulle d'objet du jeu par-dessus le panneau d'objet de Tensho ; les info-bulles du jeu faisaient ensuite tout
disparaître et les réglages du chat de Tensho devenaient inaccessibles. Qu'est-ce qui rendait le chat du jeu, et d'où venait l'info-bulle
du jeu ?

## Lecture

`dalamud.log` du 20/11/2026 (le jeu de l'utilisateur, Tensho 0.1655), lignes du masqueur du chat du jeu et de la couverture de la fenêtre
de chat, avec « Sous une fenêtre du jeu » réglé sur « Se cacher » :

| Heure | Ligne |
|---|---|
| 22:58:54.786 | Chat window covered by a game window ("Hide") … windows: ItemDetail. |
| 22:58:54.795 | Game chat: its message panels shown again (0, 1, 2). |
| 22:58:55.119 | Chat window uncovered ("Hide") … |
| 22:58:55.569 | Chat window covered by a game window ("Hide") … windows: Tooltip. |
| 22:58:55.578 | Game chat: its message panels shown again (0, 1, 2). |
| 22:58:59.787 à 23:00:31 | la même paire sept fois de plus, chaque fois avec ItemDetail |

1. Le chat du jeu revenait parce que la règle de 0.1506 et 0.1507 (X-527, X-528 M1) rendait ses messages chaque fois que la fenêtre de
   Tensho se cachait d'elle-même : en combat avec « Masquer en combat », en mission ou en scène cinématique avec leur propre réglage, et
   tant qu'une fenêtre du jeu la couvrait avec « Sous une fenêtre du jeu » réglé sur « Se cacher ».
2. À 22:58:54.786, l'info-bulle d'objet du jeu (ItemDetail) s'est ouverte par-dessus la fenêtre de Tensho alors que les panneaux du jeu
   étaient encore cachés : ils n'ont été rendus que 9 ms plus tard, à cause de cette info-bulle même. Tensho ne fait que lire ItemDetail
   (`Items/ItemHoverReader.Dalamud.cs`), il ne l'ouvre jamais. Donc le panneau de messages du jeu caché par son seul drapeau de fenêtre
   (`AtkUnitBase.IsVisible = false`) répondait encore à la souris : le lien d'objet du message du jeu, à la même place que celui de Tensho,
   ouvrait l'info-bulle du jeu, qui couvrait la fenêtre de Tensho, qui se cachait et rendait le chat du jeu : la boucle vue par
   l'utilisateur.

## Usage

- X-689 : `ChatHideWants.Of(wanted, competitive, gameUiHidden)` : la fenêtre de Tensho qui se cache d'elle-même (combat, mission, scène
  cinématique, couverte, estompée) ne rend plus les messages du jeu. Ils ne reviennent que quand l'option est décochée, que la fenêtre de
  chat de Tensho est fermée ou en échec, que « les deux chats » est choisi, pendant une coupure de contenu compétitif, qui rend la main au
  jeu (R03.2, DEC-038 : tout Tensho s'y arrête), ou quand Tensho est déchargé. Tant que le jeu cache sa propre interface (scène
  cinématique, GPose), ils restent tels quels (Hold, inchangé).
- X-694 : `GameChatHider` cache aussi le nœud racine du panneau (`PanelRoot`), comme le jeu cache ses propres éléments (Tensho cache ainsi
  la barre d'onglets du chat du jeu depuis 0.1508, et ses onglets n'ont jamais répondu à la souris) ; les deux sont rendus ensemble. Qu'un
  nœud racine caché ne reçoive plus le survol est le comportement du jeu, pas lu dans son code : l'essai en jeu de 0.1657 le vérifie
  (survoler un lien d'objet dans le chat de Tensho : une seule info-bulle, aucune ligne de couverture « ItemDetail » au journal).
