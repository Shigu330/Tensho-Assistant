# 0.1688: the game's menu of a player far away, from the Tensho chat window (X-699)

English first, then French.

## English

### The request

The user's request of 21/11 around 02:35 (chat): « is there really no way to keep the player's id for the right-click menu? the game's
chat does it ». Since 0.1660 Tensho keeps each sender's identifiers in memory (X-679, `Chat/ChatSources`); what was missing is the
function: « Send Friend Request », « Add to Blacklist » and « Report this player » greyed (0.1662, X-680), « Game menu… » only for a
character in range (`AgentHUD.OpenContextMenuFromTarget`, 0.1602).

### What was searched (21/11; Dalamud 15.0.4.1, FFXIVClientStructs 80cb4a7, game 2026.11.03.0000.0000)

- `AgentContext` (ApiProbe): it holds the target of a menu (`ContextMenuTarget`, an `InfoProxyCommonList.CharacterData`; `TargetName`,
  `TargetContentId`, `TargetAccountId`, `TargetHomeWorldId`, `TargetObjectId`) and builds menus for whoever opens them (`ClearMenu`,
  `AddMenuItem`, `AddContextMenuItem`, `AddContextMenuItem2`, `OpenContextMenu`, `OpenContextMenuForAddon`, `OpenSubMenu`). No function of
  it fills the target and adds a player's entries: the opener does.
- `AgentChatLog`: context fields for items, statuses, quests and party finder links (`ContextItemId`, `ContextStatusId`, `LinkedQuestId`,
  `LinkedPartyFinderId`, `TellPlayerName`, `TellWorldId`…); none for a player, and no function that opens a menu (`HideLogWindow`,
  `InsertTextCommandParam`, `LinkItem`, `ChangeChannelName`).
- `RaptureLogModule`: the log (`GetLogMessage`, `GetLogMessageDetail` by index, `AddMsgSourceEntry`, which gives Tensho the identifiers,
  `FormatPlayerLink`); nothing opens a menu.
- Every method of FFXIVClientStructs whose name holds « Menu », « Context », « Friend », « Blacklist », « Block », « Report »,
  « Complain », « Player » or « Link », or which takes a `CharacterData` or a content id: the only openers of a player's menu are
  `AgentHUD.OpenContextMenuFromTarget` (a character in the object table, so in range), `AgentHUD.OpenContextMenuFromPartyAddon` (the party
  list) and `AgentFreeCompany.OpenContextMenuForMember` (a member on the company window). `AgentDetail.OpenForCharacterData` opens the
  search info window, not the menu. Friend request, blacklist and report still have no function of their own (as in 0.1662). Dalamud's
  `IContextMenu` adds entries to the menus the game opens; it opens none.
- How the game's chat does it: `LogViewer.HandleLinkClick(LinkData*)`, named and kept by FFXIVClientStructs, read in the game's
  executable on disk (read-only, no game code run; disassembled with Iced, which ships with Dalamud; the functions it calls named from
  FFXIVClientStructs' own signatures). The chat panel does not open the menu itself. It packs the clicked link into eight AtkValues: its
  type (`LinkData.LinkType` + 10), its three values (`IntValue1` to `IntValue3`), its group (`LinkGroupId`), its text (read from the
  panel's own text node at the link's place: `LinkData.Payload` points into that node), a number of the panel; then it sends them, with
  the panel's window id, to the interface's external handler: `AtkStage.AtkExternalInterface->CallHandler(handler 2, three values)`.
  Handler 2 is one of `UIModule`'s 57 handlers (`UIModule+0x30`, zeroed by the constructor and filled later at run time), none of which
  FFXIVClientStructs names; it finds the player from those values and opens `AgentContext` with the player's entries.

### Why Tensho cannot open it for a player far away

- No function of the game's library opens the game's menu of a player from a name, a world or identifiers.
- The game's own way is an internal event of its interface, unnamed. Imitating it would mean forging the chat panel's values (a group and
  a text that come from the game's own panel) for a handler whose rules no library describes. A game update can change them without a
  sign: the menu could open for another player, « Report this player » included, and Tensho could not tell. That goes against R08
  (never a wrong value) and the care owed to other players.
- `LogViewer.HandleLinkClick` itself needs a link that is in the game's own chat panel: its `Payload` points into the panel's text node;
  a link made by Tensho would make the game read elsewhere in memory.
- So for a player far away, the line in the game's own chat remains the way.

### What changes in 0.1688

- For a player near you (in the object table), « Send Friend Request », « Add to Blacklist » and « Report this player » are no longer
  greyed: each opens the game's own menu of that character (the same call as « Game menu… »), where the entry is, with a tooltip that
  says so. Only on the player's click, at the next framework tick with the character loaded (R03.3); never during a cut (R03.2).
- Far away, they stay greyed; their tooltip says that the game opens that menu only from a line of its own chat for a player far away.
- Whether to keep it so (recommended, applied) or to measure first, in developer mode, what the game's chat sends on a click before any
  imitation, is the user's decision (D-202).

# 0.1688 : le menu du jeu d'un joueur loin, depuis la fenêtre de chat de Tensho (X-699)

L'anglais d'abord, puis le français.

## Français

### La demande

Demande de l'utilisateur du 21/11 vers 2 h 35 (chat) : « y a vraiment aucun moyen de retenir l'id du joueur pour le menu clic droit ? le
chat du jeu le fait ». Depuis 0.1660, Tensho garde en mémoire les identifiants de chaque auteur (X-679, `Chat/ChatSources`) ; ce qui
manquait, c'est la fonction : « Envoyer une requête d'ami », « Ajouter à la liste noire » et « Signaler ce joueur » grisés (0.1662,
X-680), « Menu du jeu… » seulement pour un personnage à portée (`AgentHUD.OpenContextMenuFromTarget`, 0.1602).

### Ce qui a été cherché (21/11 ; Dalamud 15.0.4.1, FFXIVClientStructs 80cb4a7, jeu 2026.11.03.0000.0000)

- `AgentContext` (ApiProbe) : il garde la cible d'un menu (`ContextMenuTarget`, un `InfoProxyCommonList.CharacterData` ; `TargetName`,
  `TargetContentId`, `TargetAccountId`, `TargetHomeWorldId`, `TargetObjectId`) et construit les menus pour qui les ouvre (`ClearMenu`,
  `AddMenuItem`, `AddContextMenuItem`, `AddContextMenuItem2`, `OpenContextMenu`, `OpenContextMenuForAddon`, `OpenSubMenu`). Aucune de
  ses fonctions ne remplit la cible et n'ajoute les entrées d'un joueur : c'est l'ouvreur qui le fait.
- `AgentChatLog` : des champs de contexte pour les objets, statuts, quêtes et liens de recherche d'équipe (`ContextItemId`,
  `ContextStatusId`, `LinkedQuestId`, `LinkedPartyFinderId`, `TellPlayerName`, `TellWorldId`…) ; aucun pour un joueur, et aucune fonction
  qui ouvre un menu (`HideLogWindow`, `InsertTextCommandParam`, `LinkItem`, `ChangeChannelName`).
- `RaptureLogModule` : le journal (`GetLogMessage`, `GetLogMessageDetail` par index, `AddMsgSourceEntry`, qui donne à Tensho les
  identifiants, `FormatPlayerLink`) ; rien n'ouvre un menu.
- Toutes les méthodes de FFXIVClientStructs dont le nom contient « Menu », « Context », « Friend », « Blacklist », « Block », « Report »,
  « Complain », « Player » ou « Link », ou qui prennent un `CharacterData` ou un identifiant de contenu : les seules qui ouvrent le menu
  d'un joueur sont `AgentHUD.OpenContextMenuFromTarget` (un personnage de la table des objets, donc à portée),
  `AgentHUD.OpenContextMenuFromPartyAddon` (la liste d'équipe) et `AgentFreeCompany.OpenContextMenuForMember` (un membre dans la fenêtre
  de la compagnie). `AgentDetail.OpenForCharacterData` ouvre la fenêtre des informations de recherche, pas le menu. Requête d'ami, liste
  noire et signalement n'ont toujours aucune fonction à eux (comme en 0.1662). L'`IContextMenu` de Dalamud ajoute des entrées aux menus
  que le jeu ouvre ; il n'en ouvre aucun.
- Comment fait le chat du jeu : `LogViewer.HandleLinkClick(LinkData*)`, nommée et tenue par FFXIVClientStructs, lue dans l'exécutable du
  jeu sur le disque (lecture seule, aucun code du jeu exécuté ; désassemblée avec Iced, fourni avec Dalamud ; les fonctions qu'elle
  appelle nommées d'après les signatures de FFXIVClientStructs). Le panneau du chat n'ouvre pas le menu lui-même. Il emballe le lien
  cliqué en huit AtkValues : son type (`LinkData.LinkType` + 10), ses trois valeurs (`IntValue1` à `IntValue3`), son groupe
  (`LinkGroupId`), son texte (lu dans le nœud de texte du panneau, à la place du lien : `LinkData.Payload` pointe dans ce nœud), un numéro
  du panneau ; puis il les envoie, avec l'identifiant de la fenêtre du panneau, au gestionnaire externe de l'interface :
  `AtkStage.AtkExternalInterface->CallHandler(gestionnaire 2, trois valeurs)`. Le gestionnaire 2 est l'un des 57 gestionnaires
  d'`UIModule` (`UIModule+0x30`, mis à zéro par le constructeur puis remplis à l'exécution), dont aucun n'est nommé par
  FFXIVClientStructs ; il retrouve le joueur d'après ces valeurs et ouvre `AgentContext` avec les entrées du joueur.

### Pourquoi Tensho ne peut pas l'ouvrir pour un joueur loin

- Aucune fonction de la bibliothèque du jeu n'ouvre le menu du jeu d'un joueur à partir d'un nom, d'un monde ou d'identifiants.
- La voie du jeu est un événement interne de son interface, sans nom. L'imiter voudrait dire fabriquer les valeurs du panneau du chat (un
  groupe et un texte qui viennent du propre panneau du jeu) pour un gestionnaire dont aucune bibliothèque ne décrit les règles. Une mise à
  jour du jeu peut les changer sans signe : le menu pourrait s'ouvrir pour un autre joueur, « Signaler ce joueur » compris, sans que
  Tensho puisse le voir. C'est contraire à R08 (jamais de valeur fausse) et au soin dû aux autres joueurs.
- `LogViewer.HandleLinkClick` elle-même demande un lien qui est dans le propre panneau du chat du jeu : son `Payload` pointe dans le nœud
  de texte du panneau ; un lien fait par Tensho ferait lire le jeu ailleurs en mémoire.
- Pour un joueur loin, la ligne du propre chat du jeu reste donc la voie.

### Ce qui change en 0.1688

- Pour un joueur près de vous (dans la table des objets), « Envoyer une requête d'ami », « Ajouter à la liste noire » et « Signaler ce
  joueur » ne sont plus grisés : chacun ouvre le propre menu du jeu de ce personnage (le même appel que « Menu du jeu… »), où se trouve
  l'entrée, avec une info-bulle qui le dit. Seulement au clic du joueur, au tour suivant du framework, personnage chargé (R03.3) ; jamais
  pendant une coupure (R03.2).
- Loin, ils restent grisés ; leur info-bulle dit que le jeu n'ouvre ce menu, pour un joueur loin, que depuis une ligne de son propre chat.
- Garder ainsi (recommandé, appliqué) ou mesurer d'abord, en mode développeur, ce que le chat du jeu envoie au clic avant toute
  imitation : décision de l'utilisateur (D-202).
