# 0.1665: the typing modes of « Reply in the same mode » (X-697 M3)

English first, then French.

## English

Question: which value does `RaptureShellModule.ChangeChatChannel(Int32 mode, UInt32 linkshellIndex, Utf8String* tellTarget, Boolean)` take
for each spoken channel? The review of 0.1664 (M3) found that « Reply in Selected Chat Mode » stayed greyed on yell, shout, free company,
linkshells and novice network, because FFXIVClientStructs' `ChatChannel` enumeration names only Say 1, Party 2, Alliance 3; that does not
prove the game refuses the other values.

- ApiProbe, 21/11 (Dalamud 15.0.4.1, its FFXIVClientStructs): `ChangeChatChannel(System.Int32, System.UInt32, Utf8String*, System.Boolean)`;
  `FFXIVClientStructs.FFXIV.Client.UI.Agent.ChatChannel` = Say 1, Party 2, Alliance 3, nothing else; `RaptureShellModule` holds `ChatType`
  (Int32), `ShellCommandLinkshellIndex` and `ShellCommandChatCrossWorldLinkshell`.
- External reference (read for understanding only, nothing copied; below the game's own data): the chat plugin « Chat 2 »
  (github.com/Infiziert90/ChatTwo, file ChatTwo/Code/InputChannel.cs, read 21/11) uses the same function with these modes: Tell 0, Say 1,
  Party 2, Alliance 3, Yell 4, Shout 5, Free Company 6, PvP team 7, Novice Network 8, cross-world linkshells 1 to 8 = 9 to 16, linkshells
  1 to 8 = 19 to 26 (17 and 18 not used); its call (ChatTwo/GameFunctions/Chat.cs) passes the mode and the linkshell's index as second
  argument. The values Say 1, Party 2, Alliance 3 agree with ClientStructs.
- Tensho (0.1665): the mode of each spoken channel from this table; the linkshell's index counted from 0 (linkshell 1 gives 0). Only the
  typing box changes; nothing is sent.
- Not proven yet: the index counted from 0, and the game accepting each value from Tensho's menu. In-game test of 0.1665: right click on a
  player in a Yell, a Free Company message and a linkshell message, « Reply in the same mode », the game's typing box shows that channel.

## Français

Question : quelle valeur `RaptureShellModule.ChangeChatChannel(Int32 mode, UInt32 indexLinkshell, Utf8String* cibleMurmure, Boolean)` prend-elle
pour chaque canal parlé ? La relecture de 0.1664 (M3) a trouvé que « Répondre avec le même mode de discussion » restait grisé sur Hurler,
Crier, compagnie libre, linkshells et réseau des novices, parce que l'énumération `ChatChannel` de FFXIVClientStructs ne nomme que Dire 1,
Équipe 2, Alliance 3 ; cela ne prouve pas que le jeu refuse les autres valeurs.

- ApiProbe, 21/11 (Dalamud 15.0.4.1, son FFXIVClientStructs) : `ChangeChatChannel(System.Int32, System.UInt32, Utf8String*, System.Boolean)` ;
  `FFXIVClientStructs.FFXIV.Client.UI.Agent.ChatChannel` = Say 1, Party 2, Alliance 3, rien d'autre ; `RaptureShellModule` porte `ChatType`
  (Int32), `ShellCommandLinkshellIndex` et `ShellCommandChatCrossWorldLinkshell`.
- Référence externe (lue pour comprendre seulement, rien de copié ; sous les données du jeu) : le plugin de chat « Chat 2 »
  (github.com/Infiziert90/ChatTwo, fichier ChatTwo/Code/InputChannel.cs, lu le 21/11) se sert de la même fonction avec ces modes : murmure 0,
  Dire 1, Équipe 2, Alliance 3, Hurler 4, Crier 5, compagnie libre 6, équipe JcJ 7, réseau des novices 8, linkshells inter-mondes 1 à 8 = 9 à
  16, linkshells 1 à 8 = 19 à 26 (17 et 18 inutilisés) ; son appel (ChatTwo/GameFunctions/Chat.cs) passe le mode et l'index de la linkshell
  en deuxième argument. Les valeurs Dire 1, Équipe 2, Alliance 3 concordent avec ClientStructs.
- Tensho (0.1665) : le mode de chaque canal parlé selon ce tableau ; l'index de la linkshell compté depuis 0 (la linkshell 1 donne 0). Seule
  la zone de saisie change ; rien n'est envoyé.
- Pas encore prouvé : l'index compté depuis 0, et que le jeu accepte chaque valeur depuis le menu de Tensho. Essai en jeu de 0.1665 : clic
  droit sur un joueur dans un message Hurler, un message de compagnie libre et un message de linkshell, « Répondre avec le même mode », la
  zone de saisie du jeu montre ce canal.
