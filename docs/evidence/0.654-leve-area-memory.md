# Remembering a leve's areas (0.654)

Report of the user, 2026-11-06, with captures: no green area when the character is not on it, while the journal's target badge shows on the map's edge; opening and closing the map within range makes the area appear; a leve was abandoned too.

`dalamud.log`, capture added here:

```
11:43:34 Reading leves: 1 accepted: 1670 (sequence 1, flags 0, hidden False, priority False)
```

XIVAPI v2: Leve 1670 is « Grosse récolte : pierre septentrionale d'ornement », the leve running. So `QuestManager.LeveQuests[].LeveId` is a row of the Leve sheet.

## Reading

- The game's list does not always hold the area: docs/evidence/0.653-markers-during-journal-request.md shows it emptied, and the user's report shows it missing until the map is opened within range. Its absence says nothing about the leve.
- The edge badge of that report comes from the journal's target, not from the area: it is another source.
- `LeveQuests` says at any time which leves are accepted.

So Tensho remembers the areas seen, map by map, while the leve is accepted. A new read of the same leve on the same map replaces them; a leve no longer accepted loses them, and a marker of it is no longer drawn.

## Not established

- An area never seen in this session cannot be shown: nothing is saved, so after a restart of the game or a reload of the plugin the area comes back once the game gives it. The sheets were not searched for a position.
- A finished leve not yet handed in: `Sequence` and `Flags` may tell it, and the capture writes them to compare; until then its area stays while it is accepted.
- An abandoned leve was reported by the user before this version: the line above has only the leve left. The removal itself is not read in game.

## 0.655

Report of the user: the dark badge on the map's edge stays after abandoning the leve. `dalamud.log`: `11:51:33 Reading leves: 0 accepted:`. That badge is the journal's target, which a leve keeps with quest 0, so the quest check of 0.243 never removed it. Tensho now ties the target to the leve through the title of the game's map request, and removes it when the game no longer lists the leve.

Not established: that this title is the leve's name. Quests have theirs (docs/evidence/0.633-quest-route.md); for a leve it was not read. The log line « Game map hosted » now writes it. If it does not match, the target stays until removed by hand, as before.
