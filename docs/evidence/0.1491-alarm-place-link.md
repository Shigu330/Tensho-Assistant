# 0.1491 — The place link of Tensho's alarms: a bare link start (X-509)

Review of 0.1490 (11/16, finding I1): the user sees only an arrow before the item in the game's own chat when an alarm of Tensho rings; R-12
(0.414) meant the ring to carry a link to the gathering place, with its name and coordinates. 0.1487 read the recorded message as « the game
shows only its arrow » and made the Tensho chat window copy that. This file gives the cause.

## Source

The intermediate language of Dalamud 15.0.4.0 (`%AppData%\XIVLauncher\addon\Hooks\15.0.4.0\Dalamud.dll`, the version the game loads on 11/16),
read with `System.Reflection.Metadata` (calls and `newobj` of each method body, in order; nothing run), and Dalamud's public source
(goatcorp/Dalamud, `Dalamud/Game/Text/SeStringHandling/SeString.cs` and `SeStringBuilder.cs`), which agrees with it.

## Reading

| What | Shape | Consequence |
|---|---|---|
| Tensho's ring from 0.414 to 0.1490: `AddText(" ").AddMapLink(territory, map, x, y, 0.05f)` | the link's start alone: no arrow, no name, no coordinates, no end | the game's chat shows nothing for the place; the link stays open over what follows |
| `SeString.CreateMapLink(territory, map, x, y, 0.05f)` (calls CreateMapLinkWithInstance) | start, the game's arrow (with a space in French and German), « Place ( x , y ) », end | the place link as the game writes one |
| `AddItemLink(item, false)` (CreateItemLink, evaluated through the game's Addon row 371) | colour and edge colour pushed, the link glyph, colours popped, a space, then the item link: colours, Item, its name, its end | the arrow the user sees belongs to the item link; it stands before the item link, outside it |

The alarm message recorded on 11/16 at 05:29:36 (docs/evidence/0.1487-chat-link-said.md, kind 1) reads accordingly:
`MapLink` (the bare start), `TextPayload (1)` (the space Tensho adds before the item), `Raw (9 bytes), Raw (6 bytes)` (colour and edge colour
pushed: macros Dalamud does not parse), the glyph, `Raw (5 bytes), Raw (5 bytes)` (popped), `TextPayload (1)` (the space of the template),
then the item link. The place's name and coordinates were never sent: the glyph read in 0.1487 as « the place link's arrow » is the item
link's.

## What 0.1491 does

- The ring sends the whole place link (`Alarms/AlarmPlaceLink.Dalamud.cs`: `SeString.CreateMapLink`); if Dalamud cannot make it, the ring
  goes without a place link, never with a bare one.
- The self-check (developer mode) makes that link as the ring does and reads it as the chat window does (`alarm place link`: a place and
  coordinates, then the end); FAILED otherwise.
- The Tensho chat window gives a glyph alone just before a link (spaces only between) to that link, as its arrow: the item link of the ring
  keeps its arrow, as in the game.
- Tests: ChatReview1491Tests (the recorded message fails the check, the whole link passes; both laid out with the default look).
