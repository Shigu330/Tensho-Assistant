# 0.1445: the local link's serialization prepared off the game's thread (X-433)

Lines of `dalamud.log` (developer mode) of 2026-11-15, kept here in 0.1446 because the log rotates (review of 0.1445, X-444 M1). Code:
`src/TenshoAssistant/Link/LocalLink.cs` (`LocalLinkProtocol.Prepare`, `LinkPreparation`) and `src/TenshoAssistant/Link/LocalLinkFeed.Dalamud.cs`;
tests: `LinkPrepare1445Tests`, `Review1446Tests`.

## Before

At each load, LocalLinkFeed's first pass (the link with the desktop application, on) compiled 23 methods in a frame of the game (raw
lines above). 0.1440's listening names them at the load of 18:28: 5 of the plugin and **18** getters System.Text.Json makes at run time
(`dynamicClass.…Getter`) for the link's snapshot and its parts. The 0.1445 section of the CHANGELOG, its test and the code comment said 17:
count corrected in 0.1446.

## After (0.1445)

At the loads of 18:49 and 18:50, LocalLinkFeed has no slow first pass any more. At the one of 18:58 its first pass still takes 70 ms, with 5
methods compiled and no getter: the plugin's lambdas and two methods of the window it calls (the next case of X-433). Since 0.1446 (X-444
M5) the preparation also runs when the player turns the link on during a session: the feed publishes nothing before it ends (a second at
most in practice), instead of making the getters in a frame of the game.
