# 0.1746: the game's menu of a player far away: what the click sends, measured (X-758)

English first, then French.

## The measure (T-0.1718-1, 21/11/2026 between 18:43:43 and 18:44:43, developer mode, dalamud.log)

Five clicks on a player's name in the game's own chat (the probe of 0.1718, read-only: `docs/evidence/0.1718-chat-link-click-probe.md`):

| Click | Link type (sent as) | id, index | group | values | menu the game opened: content id, home world, object, name |
|---|---|---|---|---|---|
| 1 | 0 (10) | 3, 3 | 13588 | 14, 85, 0 | set, 85, none, 14 characters |
| 2 | 0 (10) | 4, 3 | 13524 | 16, 42, 0 | 0, 42, none, 12 characters |
| 3 | 0 (10) | 1, 5 | 13490 | 30, 85, 0 | set, 85, none, 16 characters |
| 4 | 0 (10) | 2, 7 | 8915 | 16, 42, 0 | 0, 42, none, 12 characters |
| 5 | 0 (10) | 1, 2 | 6919 | 30, 42, 0 | set, 42, none, 12 characters |

Each time the game opened its « Default » menu from « ChatLog », target « MenuTargetDefault », no object (the player was not in the
object table: far away).

## What the game does at the click (read from the measure and from 0.1688)

- The chat panel sends the link to the interface's external handler number 2 of `UIModule` (unnamed by FFXIVClientStructs, filled at run
  time; `docs/evidence/0.1688-chat-player-menu-far.md`): the type (player link, 0, sent as 10), the three values, the group, the name (the
  link's text in the panel) and the panel's number.
- Value 2 is the player's home world each time. Value 1 is 14, 16 or 30: the numbers of Dalamud's `XivChatType` for party, linkshell 1 and
  yell; the probe did not note the line's channel, so this is a likely reading, not a proof. Value 3 is 0.
- The click never carries the content id (no half of it matched a value). The game finds it itself from its own log line (the group grows
  with the log: 6919 to 13588, the older lines lower): 3 clicks of 5 gave a content id, the two others (value 1 = 16, world 42) none, as
  if the game's log had not kept the sender of those lines.

## Is there a safe way for Tensho to open that menu for a player far away?

- Not by a named function: none of FFXIVClientStructs opens a player's menu from a name, a world or a content id (0.1688: the only
  openers need the character in the object table, the party list or the company window).
- Imitating the click would mean calling the unnamed handler 2 with eight values of Tensho's making, among them the number of a line of
  the game's own log, which Tensho does not keep for the lines it copies. A wrong number fills the menu from another line, so another
  player (« Report » included); a game update can move the handler or change its values without a sign, and a native call with wrong
  values can crash the game, which a `try` does not catch (R08). A check after the menu opens (Dalamud's `IContextMenu`: its target
  compared with the player wanted, the menu closed otherwise) would catch another player, not the crash nor the silent change.
- What Tensho already does for a player far away goes through named functions only: the tell (the typing box set to « /tell
  Name@World », nothing sent), the party invitation (`InfoProxyPartyInvite.InviteToParty` and `InviteToPartyContentId`) and the adventurer
  plate (`AgentCharaCard.OpenCharaCard`, by content id). Left to the game's own chat: friend request, blacklist and report, which have no
  function of their own.
- Recommended: keep it so (D-203 a). Nothing is sent to the game while the user has not chosen (R03.3, R04).

# 0.1746 : le menu du jeu d'un joueur loin : ce que le clic envoie, mesuré (X-758)

L'anglais d'abord, puis le français.

## La mesure (T-0.1718-1, 21/11/2026 entre 18 h 43 min 43 et 18 h 44 min 43, mode développeur, dalamud.log)

Cinq clics sur le nom d'un joueur dans le chat du jeu (la sonde de 0.1718, en lecture seule : `docs/evidence/0.1718-chat-link-click-probe.md`) :

| Clic | Type du lien (envoyé comme) | id, index | groupe | valeurs | menu ouvert par le jeu : content id, monde d'origine, objet, nom |
|---|---|---|---|---|---|
| 1 | 0 (10) | 3, 3 | 13588 | 14, 85, 0 | présent, 85, aucun, 14 caractères |
| 2 | 0 (10) | 4, 3 | 13524 | 16, 42, 0 | 0, 42, aucun, 12 caractères |
| 3 | 0 (10) | 1, 5 | 13490 | 30, 85, 0 | présent, 85, aucun, 16 caractères |
| 4 | 0 (10) | 2, 7 | 8915 | 16, 42, 0 | 0, 42, aucun, 12 caractères |
| 5 | 0 (10) | 1, 2 | 6919 | 30, 42, 0 | présent, 42, aucun, 12 caractères |

À chaque fois, le jeu a ouvert son menu « Default » depuis « ChatLog », cible « MenuTargetDefault », sans objet (le joueur n'était pas
dans la table des objets : loin).

## Ce que fait le jeu au clic (d'après la mesure et 0.1688)

- Le panneau du chat envoie le lien au gestionnaire externe numéro 2 de `UIModule` (sans nom dans FFXIVClientStructs, rempli à
  l'exécution ; `docs/evidence/0.1688-chat-player-menu-far.md`) : le type (lien de joueur, 0, envoyé comme 10), les trois valeurs, le
  groupe, le nom (le texte du lien dans le panneau) et le numéro du panneau.
- La valeur 2 est à chaque fois le monde d'origine du joueur. La valeur 1 vaut 14, 16 ou 30 : les numéros du `XivChatType` de Dalamud pour
  l'équipe, la linkshell 1 et le cri ; la sonde n'a pas noté le canal de la ligne : lecture probable, pas une preuve. La valeur 3 vaut 0.
- Le clic ne porte jamais le content id (aucune moitié ne correspondait à une valeur). Le jeu le retrouve lui-même dans sa propre ligne
  du journal (le groupe grandit avec le journal : de 6919 à 13588, les lignes plus anciennes plus bas) : 3 clics sur 5 ont donné un
  content id, les deux autres (valeur 1 = 16, monde 42) aucun, comme si le journal du jeu n'avait pas gardé l'auteur de ces lignes.

## Y a-t-il une façon sûre pour Tensho d'ouvrir ce menu pour un joueur loin ?

- Pas par une fonction nommée : aucune de FFXIVClientStructs n'ouvre le menu d'un joueur à partir d'un nom, d'un monde ou d'un content
  id (0.1688 : les seules demandent le personnage dans la table des objets, la liste d'équipe ou la fenêtre de la compagnie).
- Imiter le clic, ce serait appeler le gestionnaire 2 sans nom avec huit valeurs faites par Tensho, dont le numéro d'une ligne du journal
  du jeu, que Tensho ne garde pas pour les lignes qu'il copie. Un mauvais numéro remplit le menu depuis une autre ligne, donc un autre
  joueur (« Signaler » compris) ; une mise à jour du jeu peut déplacer le gestionnaire ou changer ses valeurs sans signe, et un appel
  natif avec de mauvaises valeurs peut faire planter le jeu, ce qu'un `try` ne rattrape pas (R08). Une vérification après l'ouverture
  (`IContextMenu` de Dalamud : sa cible comparée au joueur voulu, menu fermé sinon) attraperait un autre joueur, pas le plantage ni le
  changement silencieux.
- Ce que Tensho fait déjà pour un joueur loin passe seulement par des fonctions nommées : le message privé (la zone de saisie mise à
  « /tell Nom@Monde », rien n'est envoyé), l'invitation dans l'équipe (`InfoProxyPartyInvite.InviteToParty` et
  `InviteToPartyContentId`) et la fiche d'aventurier (`AgentCharaCard.OpenCharaCard`, par content id). Laissés au chat du jeu : demande
  d'ami, liste noire et signaler, qui n'ont pas de fonction à eux.
- Recommandé : garder ainsi (D-203 a). Rien n'est envoyé au jeu tant que l'utilisateur n'a pas choisi (R03.3, R04).
