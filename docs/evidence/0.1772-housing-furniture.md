# 0.1772: the furniture placed in a house, before showing summoning bells on the map (X-747, probe)

English first, then French.

## The question

The user, 21/11 (idea I-019, test T-0.1402-1): the summoning bells placed in the house are not on Tensho's map, nor on the game's. Does the
game give the furniture placed in a house and its position?

## What the game's structures give (tools/ApiProbe, FFXIVClientStructs of Dalamud 15.0.4, 22/11/2026)

- `HousingManager.Instance()->IndoorTerritory` (inside a house): `FurnitureManager` (`HousingFurnitureManager`), whose `FurnitureVector` holds
  a pointer to each piece placed (`HousingFurniture`: `Id`, `Position` (world), `Rotation`, `Index`, `Stain`); `HousingManager.IsInside()`.
- `IndoorTerritory` also has `HouseId`, `CurrentFloor`, `TargetedHousingObject` and `HoveredHousingObject`.
- What `Id` is (a `HousingFurniture` row, an `Item` row, or one of them plus an offset) is not established offline; neither whether a placed
  summoning bell is an event object of the object table. Only a reading inside a house with a bell tells it.
- The game's map has no marker for placed furniture (the user's report): nothing to read there.

## The probe (0.1772, developer mode only)

`Maps/HousingFurnitureProbe.Dalamud.cs`: every five seconds while inside a house, read only, said in the log when it changes: « Housing
furniture probe (X-747, developer mode): territory T, N pieces of K kinds (Id x count, …); E event objects: row « name » (x, z); … ». No
player's name is read (pieces and event objects only). Nothing is shown on the map until the reading says which Id or object is the bell.

### To read in game

- In the user's house, developer mode on: the log line, with the bells' places noted (a capture of the room helps). Then the next step:
  the bells on Tensho's map of the house (or the reason it cannot be done, written for the user).

# 0.1772 : les meubles posés dans une maison, avant de montrer les sonnettes sur la carte (X-747, sonde)

L'anglais d'abord, puis le français.

## La question

L'utilisateur, 21/11 (idée I-019, essai T-0.1402-1) : les sonnettes posées dans la maison ne sont pas sur la carte de Tensho, ni sur celle
du jeu. Le jeu donne-t-il les meubles posés dans une maison et leur position ?

## Ce que donnent les structures du jeu (tools/ApiProbe, FFXIVClientStructs de Dalamud 15.0.4, 22/11/2026)

- `HousingManager.Instance()->IndoorTerritory` (dans une maison) : `FurnitureManager` (`HousingFurnitureManager`), dont le `FurnitureVector`
  tient un pointeur vers chaque meuble posé (`HousingFurniture` : `Id`, `Position` (monde), `Rotation`, `Index`, `Stain`) ;
  `HousingManager.IsInside()`.
- `IndoorTerritory` a aussi `HouseId`, `CurrentFloor`, `TargetedHousingObject` et `HoveredHousingObject`.
- Ce qu'est `Id` (une ligne de `HousingFurniture`, une ligne d'`Item`, ou l'une d'elles plus un décalage) n'est pas établi hors du jeu ; ni
  si une sonnette posée est un objet d'événement de la table des objets. Seul un relevé dans une maison avec une sonnette le dit.
- La carte du jeu n'a aucun marqueur des meubles posés (rapport de l'utilisateur) : rien à y lire.

## La sonde (0.1772, mode développeur seulement)

`Maps/HousingFurnitureProbe.Dalamud.cs` : toutes les cinq secondes dans une maison, en lecture seule, dite dans le journal quand elle change :
« Housing furniture probe (X-747, developer mode): territory T, N pieces of K kinds (Id x nombre, …); E event objects: ligne « nom » (x, z);
… ». Aucun nom de joueur n'est lu (meubles et objets d'événement seulement). Rien n'est montré sur la carte tant que le relevé ne dit pas quel
Id ou quel objet est la sonnette.

### À relever en jeu

- Dans la maison de l'utilisateur, mode développeur actif : la ligne du journal, avec la place des sonnettes notée (une capture de la pièce
  aide). Puis l'étape suivante : les sonnettes sur la carte de Tensho de la maison (ou la raison pour laquelle ce n'est pas possible, écrite
  pour l'utilisateur).
