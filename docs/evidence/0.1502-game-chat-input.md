# 0.1502 — The game's own typing box under Tensho's chat window: feasibility (X-467, probe)

Question (the master's choice of 2026-11-16, before the chat's look): can Tensho keep **the game's real typing box** (window `ChatLog`) right
under Tensho's chat window, hide the **messages** part of the game's chat, and offer a mode that shows both chats, each one reducible, to
compare? Tensho sends nothing to the game in any case (R03.3): the text leaves through the game's own box, on the player's own Enter.

Sources: `tools/ApiProbe` on `FFXIVClientStructs.FFXIV.Client.UI.AddonChatLog` and `AddonChatLogPanel` (Dalamud 15.0.4.0, game
2026.11.03.0000.0000, 2026-11-16), metadata only; the chat study of 2026-11-15 (how Chat 2 hides the game's chat: every frame, `ChatLog` and
`ChatLogPanel_0` to `_3` made non-interactive and invisible, given back on unload); the layout measured in the game by
`Chat/ChatLogLayoutProbe` (developer mode, read-only: section 3).

## 1. What the game's chat is made of (static, ApiProbe)

- **`ChatLog`** (AddonChatLog, 1592 bytes) holds the **typing box** (`TextInput`, an `AtkComponentTextInput`), the **channel menu**
  (`ChannelSelectDropDown`) and its text (`CurrentChannelTextNode`), the **tabs** (`ChatTabs`, five, `TabIndex`, `TabCount`, `ChangeTab`),
  the **background** (`BackgroundNode`, a nine-grid), the **resize button** (`ResizeButton`), the settings and novice network buttons, and a
  collision node for its controls (`ControlsCollisionNode`).
- **`ChatLogPanel_0` to `_3`** (AddonChatLogPanel) are **four separate windows**, one per tab: each holds the messages (`LogViewer`,
  `ChatComponent`, `ChatText`), its own resize button, and its own collision nodes (`PanelCollisionNode`, `TabCollisionNode`).
- So **the messages are not in the window that holds the typing box**: hiding the messages is hiding the panels (separate windows), and the
  typing box can stay the game's, untouched.

## 2. The four questions

| Question | What the game allows | Verdict |
|---|---|---|
| Move the typing box alone, or the whole window? | The box is a node of `ChatLog`; a node can be moved (`AtkResNode` position), but the game lays its nodes out again on its own refresh and resize, and the controls' collision node stays where it was (clicks). The whole window moves by `SetPosition`, but the game saves the chat's place in the player's HUD layout (`SaveAddonConfig`). | Neither is clean. Cleaner: **Tensho follows the game** — leave `ChatLog` where the player put it, and draw Tensho's chat window over the panel's box, right above the game's typing box. Nothing of the player's layout changes. |
| Hide the messages part? | The panels are separate windows; Chat 2 hides them each frame (visibility and interactivity) and gives them back on unload. To hide: the four panels, plus `ChatLog`'s background and tabs if they show behind Tensho's window. | Possible; done each frame, with a guaranteed give-back (unload, plugin off, competitive content, option off). Whether the game shows a panel again on its own (new tab, new message, zone change) is measured in the game (section 4). |
| Focus and keyboard | The box stays the game's: Enter, `/`, the reply key, the history, auto-translate, the tab completion of names are the game's own; Tensho intercepts nothing and steals no key. | **The strong point**: no hook, no signature, no key read; nothing sent by Tensho. |
| Resizing | `ChatLog`'s size covers the tabs, the panel's area and the typing box; resizing it is the game's own resize button (saved in the player's layout). | Tensho reads `ChatLog`'s box each frame and sizes its window to it; the player resizes with the game's button, never Tensho. |

The « show both » mode is then simple: the panels are shown again (nothing hidden), Tensho's window is drawn beside the game's chat as
today, and each can be reduced (Tensho's by its own button; the game's by its own collapse of the panel, or by the option).

## 3. Layout measured in the game

`dalamud.log`, 2026-11-16 14:58:19, after the reload of 0.1502 (screen 1080 pixels high, the player's own layout, interface scale 1.00),
one line (the layout did not change after it):

`window shown 1,824 706x256 scale 1.00; input 24,1024 679x28 inside focused; channel 1,1024 116x28; tabs 24,1052 75x28;
background 1,824 706x197; input below the shown panels False; panel0 shown 1,824 706x221 inside; panel1 shown 1,824 706x221 inside;
panel2 shown 1,824 706x221 inside`

What it shows:

- `ChatLog` sits at the bottom left (1,824 to 707,1080); the **typing box is its bottom row** (y 1024 to 1052, 679 pixels wide), the
  channel menu at its left; the row read for the first tab is under it (y 1052 to 1080).
- The **message panels have exactly `ChatLog`'s place and width** (1,824, 706 pixels) and stop at y 1045: they lie over the window, and
  their box overlaps the typing row by 21 pixels (the panel's own margin and resize corner). Three panels are « shown » at the same box:
  the game keeps the panels of the other tabs visible in the same place (only the shown tab's lines are drawn).
- `focused` was read while the player was not typing: `ChatLog`'s focus node is the typing box even when it is closed, so this flag does
  not tell « the player is typing ». A later reading would need the text input's own state.
- So Tensho's window would take the panel's box minus the typing row (here 1,824 706x200), and the game's typing row would stay visible
  under it. The overlap and the row under the typing box are to check on a capture before coding (positions of nested nodes as the game
  reports them).

## Conclusion (0.1502)

Feasible without a hook or a signature and without sending anything: the typing box is the game's and stays where the player put it; the
messages are separate windows that can be hidden each frame and given back. Not coded in 0.1502: hiding the panels changes the player's
game interface, and what section 4 lists needs the player there. Recommended next step: a trial version, off by default, that only hides
the panels and draws Tensho's window in their box (« Tensho follows the game »), with a « both chats » switch, then the in-game trial of
section 4; DEC-053 (« never hides the game's chat ») is completed first by the user's decision.

## 4. What only a trial in the game can tell (with the player there)

Hiding the panels changes the player's game UI, so it is tried with the player, never alone (R34): a panel hidden by Tensho stays hidden
through a new message, a tab change, a zone change and a cutscene; the game's tabs still work with their panel hidden; the hidden panels
come back when Tensho is unloaded, when the option is turned off and in competitive content; clicks over the hidden area go to Tensho's
window (ImGui takes the mouse there) and not to the game.
