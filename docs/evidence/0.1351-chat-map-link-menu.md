# 0.1351 — A Tensho menu on a chat map link (X-365)

Probed on 2026-11-14 with `tools/ApiProbe` (Dalamud 15.0.4.0 and FFXIVClientStructs of the dev folder, metadata only), and in `dalamud.log`.

- No context menu exists for a map link. Dalamud's `IContextMenu` knows two menu types (`Default`, `Inventory`); the default target
  (`MenuTargetDefault`) only carries a character (name, object, content id, home world). The game's chat agent (`AgentChatLog`) keeps a
  right-click context for an item (`ContextItemId`), a party finder listing, a quest and a status, nothing for a map link. In
  `dalamud.log` of 14/11, Tensho's developer line « Context menu opened » (written for every menu) names no menu of the chat window
  (the one line of the evening is the Character window's, 18:34).
- The chat panels receive the link events: `AtkEventType.LinkMouseClick` 75, `LinkMouseOver` 76, `LinkMouseOut` 77 (same numbering as
  Dalamud's `AddonEventType`: `MouseDown` 3 in both). Their data is `AtkEventData.LinkData` (`LinkData`: `Payload` pointer, `LinkType`,
  `MinX…MaxY`). `Payload` points at the link in the message text (NUL-terminated): the bytes Dalamud's own chat link handler reads.
- Dalamud's `IAddonLifecycle` has `AddonEvent.PreReceiveEvent` with `AddonReceiveEventArgs` (`AtkEventType`, `EventParam`, `AtkEvent`,
  `AtkEventData`): the chat panels' (`ChatLogPanel_0` to `_3`) events are seen without a hook of the plugin's own.

Tensho (0.1351) copies the hovered link (`MapLinkPayload` parsed from the first payload, at most 512 bytes) on the game thread and, on a
right click while it is under the mouse, draws its own place menu (ImGui) at the mouse. It never changes the event, never opens a game
menu and sends nothing to the game. That the panels' link events reach `PreReceiveEvent` is checked in game: developer mode writes
« Chat link hovered (ChatLogPanel_n): map link, map N. » when the mouse goes over a map link.
