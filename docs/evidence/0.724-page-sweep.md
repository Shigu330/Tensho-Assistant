# Page sweep of the self-check (0.724, corrected in 0.726)

The self-check of 0.722 proves that reads run, not that pages draw. Since the plugin reloads in the running game at each build, the sweep draws every page there too.

- Developer mode only, once per load, after the self-check.
- A Dalamud window on the main viewport, marked hidden through `HiddenFramesCannotSkipItems`, as ImGui does for a new window's first frame: its items run, nothing is rendered, and a hidden window is never hovered. `NoInputs` as well, and no page tests the mouse rectangle by itself. If the window is ever not hidden, the sweep stops.
- One draw every 10 frames: 20 draws per page to start what it loads, then a second pass of 3 draws with what has been loaded.
- It waits during combat, duties, crafting, gathering, fishing, zone changes and cutscenes, and under the competitive cut.
- The market page is left out: with an item chosen, opening it asks Universalis. Other pages may ask a community source they would ask when opened, within the user's settings and cache; `BoundedHttp` counts them and the summary line gives the hosts.

Decided with the user on 2026-11-07 (DEC-040): automatic, developer mode only, with these requests.

What it proves: each page's first tab runs with real data without an exception, and what it costs. What it does not prove: what the page looks like, tabs not selected by default, details opened by a click, and that the values match the game: `docs/project/TESTING.md`.
