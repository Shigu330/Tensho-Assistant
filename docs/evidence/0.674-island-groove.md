# The groove's rise in an agenda (0.674)

N-10. Before this version the groove stayed as read, so totals ran low.

## Sources

- Game files, `tools/XbmProbe`, 2026-11-06: `MJICraftworksTension` has 6 rows: 10, 15, 20, 25, 35, 45.
- [Island Workshop, FFXIV Console Games Wiki](https://ffxiv.consolegameswiki.com/wiki/Island_Workshop), read 2026-11-06: an efficient craft gives two items at the time and materials of one; one groove point per efficient craft, 1% of export value each; caps of 15, 20, 25, 35, 45 for 1 to 5 landmarks. It gives no cap for zero landmarks and does not say whether the groove carries over.
- WorkshopOptimizerPlugin (MIT), `Optimizer/ItemSet.cs`, `Data/Groove.cs`, read 2026-11-06: goes hour by hour; crafts finishing in the same hour see the same groove and the same units made; the groove rises after an efficient craft's value is counted; flat cap of 45. Written again here.
- FFXIVClientStructs (`tools/ApiProbe`): `MJIManager.LandmarkPlacements`, 5 entries with `LandmarkId` and `UnderConstruction`.

## Choices

| Point | Choice | Why |
|---|---|---|
| When the groove rises | When the efficient craft finishes | **The sources differ:** the wiki says when it starts, the plugin counts it at the end. Finishing gives the lower total and matches the code already written. The capture can tell |
| Cap | `MJICraftworksTension[finished landmarks]` | **Row inferred:** rows 1 to 5 match the wiki; row 0 (10) is only the sheet's. Unknown count: the highest. Never under the groove the game gives |
| Finished landmark | `LandmarkId != 0` and `UnderConstruction == 0` | **Inferred**, the capture writes the raw values (`Reading island`) |
| Search | Unchanged: it picks crafts at the groove read | The multiplier is shared by all crafts at a given moment; only the totals change |
