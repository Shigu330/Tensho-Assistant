# A list line that blinks while gathering (0.740)

User report, 2026-11-07: while gathering, the list panel « changes between two values », like a blink. Not reproduced by reading the code: the stock comes from one source, the live bags, and the need is worked out once a second.

So a reading first: in developer mode, `Diagnostics/BlinkWatch.cs` writes « List blink: » to `dalamud.log` when a line goes back to the value it had just before, within three seconds, with the list, the item, and the stock and need before, then, and now. Once in thirty seconds per line.

## Result, 2026-11-07 11:06

After a few items gathered: « List blink: Workshop, item 5111: held 345->0->345, needed 537->537->537, 215 ms apart », the same for every line of the panel, at the same moment. The need never moved: every stock fell to 0 for about 200 ms.

Cause: at each change of the bags, `InventoryCaptureCoordinator.Invalidate` cleared the live reading, and the next one waited for the 250 ms pause. Stock counts read from that gap fell to 0, the other storages (retainers, armoury) still counting as observed.

Fix in 0.741: `InventoryService.Shown` keeps the last reading of the same character for display; `Current` stays unknown during the gap for what acts (the bag sort). A logout, another character or a failed reading still clears both.
