## The three defects behind the 11 wrong facts (fixed in 0.911)

- **FATEs at (0,0)**: Fates 516, 520, 524, 527 (Mor Dhona), 1148 (La Mer de Rubis), 260, 265 (Lower La Noscea) recorded at exactly (0,0), each also
  recorded right within the same second (matching Fate.Location in the zone's layout). The game gives a zero position for about a second (entering
  the zone, reloading the plugin). The map reader now skips it, the store refuses it, and a FateSeen at (0,0) is dropped when read (also by the merge
  tool; the 4 such facts of the shared file were removed).
- **Festivals counted per plugin load**: the once-per-day guard was an instance field reset at each load (the DLL reloads at each build), so one day
  counted 46 times. A festival day now counts once from the store itself.
- **Key item hand-in**: quest 68631 asks for 2002169, a key item (EventItem); `BaseItem` (raw % 500 000) turned it into item 2169. Ids from 2 000 000
  are kept as key items and named from the EventItem sheet. The one wrong fact cannot be told apart from a real request for item 2169: left.

## Game-data edge cases found (not errors)

- The Sunken Temple of Qarn's maps 43 and 44 still name the retired territory 163 (Map.TerritoryType), while the duty is territory 1267 (map 42):
  a check « Map.TerritoryType == territory » would refuse right facts.
- SpearfishingItem.TerritoryType holds 1, 5 or 43, not territories (a misnamed column): spearfishing is checked through GatheringPoint → base items.
