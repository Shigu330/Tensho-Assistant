# The map after a teleport (0.658)

Report of the user, 2026-11-06: after a teleport the map closes and does not come back, « but not every time ». `dalamud.log`:

```
12:14:51 The game closed its map window: the Tensho map closes with it; occupied: true.
12:14:53 The event is over: the map opens again.
12:15:26 The game closed its map window: the Tensho map closes with it; occupied: true.
12:15:41 The game closed its map window: the Tensho map closes with it; occupied: true.
12:16:27 The game closed its map window: the Tensho map closes with it; occupied: false.
```

## Reading

`MapResume` of 0.625 waits for the player to be free, and gave up as soon as the territory changed: the map came back in the same zone only. Closing with `occupied: false` counted as the player's own choice.

The log does not say which of these closings were teleports. The cause of the second kind is inferred: a close during a cast or between zones has none of the flags that `Occupied` reads.

## Change

- Another zone reached brings the map back once free, unless the new zone is a duty (`BoundByDuty`).
- `Casting`, `BetweenAreas` and `BetweenAreas51` count as an event at the closing and while waiting. The close line writes both results.
- The competitive cut cancels the wait.

## Not established

- The map key pressed during a cast now counts as an event: the map would come back.
- A duty entered with its flag set after the arrival: not read.

## 0.659

Request of the user: a map that was open comes back in a duty too. The `BoundByDuty` exception is gone. PvP and ranked content stay out: the competitive cut cancels the wait (DEC-038).

## 0.661

Test of the user: casting a teleport and closing the map with its key, the map comes back just before the end of the teleport. `dalamud.log`:

```
12:50:46 The game closed its map window: the Tensho map closes with it; occupied: false, event: true.
12:50:47 The event is over: the map opens again.
12:50:48 The game closed its map window: the Tensho map closes with it; occupied: false, event: true.
12:51:14 The game closed its map window: the Tensho map closes with it; occupied: false, event: true.
12:51:18 The event is over: the map opens again.
12:51:19 The game closed its map window: the Tensho map closes with it; occupied: false, event: true.
```

So `Casting` caught the map key, and the flags drop for a moment before the loading screen. `Casting` no longer counts, and the player must stay free for 1.5 seconds before the map comes back.

Not established: that the game never closes its map itself during a cast. If it does, that close now counts as the player's and the map stays closed; the close line of the log says which.
