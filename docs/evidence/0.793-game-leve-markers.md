# Leve areas from the game's own markers (X-32, 0.793)

The problem (docs/evidence/0.654-leve-area-memory.md): a leve's area was missing from Tensho's map until the game map had been opened in range; opening and closing it was the workaround. Tensho read only `AgentMap.EventMarkers`, the map window's list.

0.792 wrote the game's own `Map` (UIState) markers to the log. 2026-11-07, the user doing leve 1670 (« Grosse récolte : pierre septentrionale d'ornement », map 697):

```
17:35:26 game map open, event markers 0; [quest …] (no leve)
17:35:27 game map open, event markers 0; [leve 1670 render True, 1 data; map 697 icon 60492 … at 579,8,276,4 radius 50,0 type 0] [quest …]
17:36:45 … event markers 24; [leve 1670 …] [active leve 2147615206 render False, 8 data; map 697 icon 60492 … at 541,8,272,4 radius 35,0 …; (7 more)]
17:37:09 … [active leve … 7 data …]   one point fewer after each gathering
17:39:29 … [active leve … 1 data …]
```

## Reading

- `Map.LevequestMarkers` holds the accepted leve's area (radius 50) one second after it is accepted, while the map window's list holds nothing (event markers 0). Its `ObjectiveId` is the Leve row.
- `Map.ActiveLevequestMarker` holds the points of the leve started (radius 35), one fewer after each gathering.

So Tensho adds these to the map window's list, each once (same map, icon and place within a yalm); the leve memory of 0.654 then works as before.

## Not established

- « game map open » in the capture reads `AgentMap.IsAgentActive()`, true here throughout; it does not prove the window was closed. The proof is the empty map window's list next to the game's leve.
- Quest markers (`Map.QuestMarkers`) are not used: most read `render False`, which the game does not draw.
