# 0.335 — Paliers de surveillance dans les relevés de butin des sous-marins (sonde du 2026-11-02)

DEC-023, point 2 : « les paliers de surveillance / récupération si la source sépare les relevés par palier (sonde d'abord) ».

## Source sondée
- FFXIVGachaSpreadsheet `website/static/data/Submarines.json` (MIT, (c) 2023 Infi), branche `master`, téléchargé le 2026-11-02.
- SHA-256 ca900aef1a12425699f870c4ab273795fff4ed2b36f6f5a4abf581205353d44c : le même fichier que l'instantané de 0.309.
- La base embarquée (relevés et totaux par objet) est donc inchangée.

## Ce que contient chaque secteur
- `Records` : nombre de relevés du secteur. `T3Capable` : relevés faits par un sous-marin capable du palier 3.
- `Pools.Tier1`, `Pools.Tier2`, `Pools.Tier3` : les trois pools de butin. Chacun a :
  - `Records` ;
  - `Rewards` (par objet : `Amount`, `Total`, `WasT3`, et `MinMax` = quantités vues pour Poor / Normal / Optimal) ;
  - `Stats`.
- Dans `Stats` :
  - `Min`, `Mid`, `High` : relevés du pool faits avec une surveillance sous le palier 2, entre les paliers 2 et 3, au palier 3 ;
  - `Low`, `Normal`, `Optimal` : la même chose pour la récupération ;
  - `Favor`, `DoubleDips`, `MinT2`, `MinT3`, `MinNormal`, `MinOptimal`, `MinFavor` (2147483647 = jamais observé).

## Contrôles faits sur tout le fichier (143 secteurs)
- Pour chaque secteur, la somme des `Records` des trois pools vaut le `Records` du secteur.
  - Exemple, secteur 1 : 317 416 + 205 136 + 687 = 523 239.
- Pour chaque pool, `Min + Mid + High` vaut son `Records`.
  - Exemple, secteur 1, Tier1 : 40 + 316 290 + 1 086 = 317 416.
- Exemple de répartition, secteur 1, au palier 3 de surveillance : Tier1 1 086, Tier2 1 096, Tier3 687 relevés.
  Sous le palier 3, aucun relevé Tier3.

## Ce que Tensho en fait (0.335)
- `tools/submarine-loot.py` garde aussi, par secteur, les trois pools sous la forme [relevés, Min, Mid, High, [[objet, total], …]].
- Taille du fichier : 24 Ko avant, 55 Ko après.
- Valeur d'un secteur pour une bande de surveillance b :
  - Σ pools (part des relevés de b dans ce pool) × Σ objets (Total ÷ Records du pool) × prix ;
  - sans relevé dans b, la valeur est inconnue et la moyenne de tous les relevés est prise (signalé).

## Non modélisé
- **Récupération** : les quantités d'un pool mélangent Poor, Normal et Optimal. La source ne donne par bande que des fourchettes
  (`MinMax`), pas des totaux. Aucune valeur par palier de récupération n'est donc calculée.
- **Faveur et doubles prises** (`Favor`, `DoubleDips`) : non utilisées.
- **Surveillance du sous-marin** : la bande correspondant à vos statistiques n'est pas choisie automatiquement. Elle se lit dans l'onglet Montages.
