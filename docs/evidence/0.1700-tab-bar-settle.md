# A reorderable tab bar put back in order without a new bar (X-709, 0.1700)

Dear ImGui's own code, read on GitHub (ocornut/imgui, `imgui_widgets.cpp` at the tags v1.91.9 and v1.92.1: the same lines in both; no game
data involved). Dalamud's bindings wrap cimgui, built from these sources.

- `BeginTabBarEx`, before `tab_bar->Flags = flags;`: when the `ImGuiTabBarFlags_Reorderable` flag differs from the last frame's (or when a
  tab was added to a bar that is not reorderable), the bar's tabs are sorted with `TabItemComparerByBeginOrder`, the order in which they
  were drawn in the last frame (comment in the source: « Ensure correct ordering when toggling ImGuiTabBarFlags_Reorderable flag »).
- `TabItemEx`: a tab id the bar does not know is added at the end of the bar (`tab_bar->Tabs.push_back`) and given its drawing order
  (`tab->BeginOrder = tab_bar->TabsActiveCount++`); in its first frame it is not drawn (`ItemAdd(ImRect(), …)`, an empty place, then
  `return`), in a bar that was already shown.
- `BeginTabBarEx` pushes the bar's id (`PushOverrideID(tab_bar->ID)`): a bar with another id gives every window opened inside it (the child
  window of a tab's body) another id, hence new windows.

What Tensho does with it (UI/TabBarDrag.cs): a bar whose tabs change (a tab comes) or which shows another order than the one drawn, outside
a drag, is drawn for one frame without `Reorderable`; at that frame and the next, ImGui sorts its tabs in the order drawn, in the same bar
(same id: its child windows, their scroll and the tab open are kept). Before 0.1700 the bar was made again with a new id (review of 0.1698,
M1: new child windows at nearly each item opened in the item sheet, the scroll lost, a frame in the wrong order, then an empty one). A new
bar remains for « put the pages' tabs back in order », and when settling twice in a row did not bring the order back.

# Une barre d'onglets réordonnable remise en ordre sans nouvelle barre (X-709, 0.1700)

Le code même de Dear ImGui, lu sur GitHub (ocornut/imgui, `imgui_widgets.cpp` aux étiquettes v1.91.9 et v1.92.1 : les mêmes lignes dans les
deux ; aucune donnée du jeu en jeu). Les liaisons de Dalamud enveloppent cimgui, construit depuis ces sources.

- `BeginTabBarEx`, avant `tab_bar->Flags = flags;` : quand le drapeau `ImGuiTabBarFlags_Reorderable` diffère de celui de l'image d'avant (ou
  quand un onglet a été ajouté à une barre non réordonnable), les onglets de la barre sont triés par `TabItemComparerByBeginOrder`, l'ordre
  où ils ont été dessinés à l'image d'avant (commentaire de la source : « Ensure correct ordering when toggling ImGuiTabBarFlags_Reorderable flag »).
- `TabItemEx` : un identifiant d'onglet que la barre ne connaît pas est ajouté à la fin de la barre (`tab_bar->Tabs.push_back`) et reçoit
  son rang de dessin (`tab->BeginOrder = tab_bar->TabsActiveCount++`) ; à sa première image il n'est pas dessiné (`ItemAdd(ImRect(), …)`,
  une place vide, puis `return`), dans une barre déjà montrée.
- `BeginTabBarEx` pousse l'identifiant de la barre (`PushOverrideID(tab_bar->ID)`) : une barre d'un autre identifiant donne un autre
  identifiant à chaque fenêtre ouverte dedans (la fenêtre enfant du corps d'un onglet), donc de nouvelles fenêtres.

Ce qu'en fait Tensho (UI/TabBarDrag.cs) : une barre dont les onglets changent (un onglet arrive) ou qui montre un autre ordre que celui
dessiné, hors glissement, est dessinée une image sans `Reorderable` ; à cette image et à la suivante, ImGui trie ses onglets dans l'ordre
dessiné, dans la même barre (même identifiant : ses fenêtres enfants, leur défilement et l'onglet ouvert sont gardés). Avant 0.1700, la barre
était refaite avec un nouvel identifiant (relecture de 0.1698, M1 : de nouvelles fenêtres enfants presque à chaque objet ouvert dans la fiche
d'objet, le défilement perdu, une image dans le mauvais ordre puis une vide). Une nouvelle barre reste pour « Remettre les onglets des pages
dans l'ordre », et quand deux remises en ordre de suite n'ont pas ramené l'ordre.
