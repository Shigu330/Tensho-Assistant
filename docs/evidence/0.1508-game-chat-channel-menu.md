# 0.1508 — The game chat's tab bar and channel menu under Tensho's chat window (X-533)

Question (the user's request of 2026-11-16 around 23:15 to 23:25, trial T-0.1504-1): with « Hide the game chat's messages » on, three
things of the game's chat still showed around Tensho's chat window: the game's tab bar, the current channel's name (« Say ») cut by the
bottom of Tensho's window, and the channel menu of the typing box, which opens upward and went behind Tensho's window. The user chose:
hide the game's tabs, keep the game's typing row visible right under Tensho's window without covering it, Tensho's window taking exactly
the frame of the messages and tabs, and find a way for the channel menu to be readable and clickable.

Sources: `tools/ApiProbe` on `FFXIVClientStructs.FFXIV.Client.UI.AddonChatLog` and
`FFXIVClientStructs.FFXIV.Component.GUI.AtkComponentDropDownList` (Dalamud 15.0.4.0, game 2026.11.03.0000.0000, 2026-11-16), metadata
only; the user's capture of 2026-11-16 23:10 (kept out of git, it shows chat lines); `dalamud.log` of 2026-11-16 (lines « Chat window
covered by a game window »).

## 1. What ClientStructs says

- `AddonChatLog` (window `ChatLog`) holds, besides the typing box (`TextInput`), the **channel menu** `ChannelSelectDropDown`, an
  `AtkComponentDropDownList*`, and the current channel's name `CurrentChannelTextNode` (`AtkTextNode*`).
- `AtkComponentDropDownList` holds its button (`Checkbox`, an `AtkComponentCheckBox*`) and **its list** (`List`, an `AtkComponentList*`):
  the list is a component of the drop-down, so of `ChatLog`'s own node tree.
- The tab bar is made of `ChatTabs` (five `AtkComponentTab*`, `TabCount` in use), `AddTabComponentNode`, `TabBarStartImageNode`,
  `TabBarEndImageNode`; the window also has `SettingsComponentNode` and `NoviceNetworkComponentNode`.
- `AtkUnitBase` (so `ChatLog`) has `CurrentDropDownOwnerNode` (`AtkComponentNode*`): by its name, the owner node of the drop-down open in
  that window.
- `AtkResNode` has `IsVisible()`, `ToggleVisibility(bool)` and `ParentNode`.

## 2. Why the menu went behind Tensho's window

Tensho's « under a game window » rule reads the game's **windows** (`GameWindowsReader`) and leaves `ChatLog` out (`GameWindows.NotWindows`,
since 0.537: the chat is always on screen). The menu's list being a node of `ChatLog`, no window came in front of Tensho's chat window when
it opened: `dalamud.log` of 2026-11-16 23:12 to 23:30 shows the chat window covered only by `Tooltip` and `ActionDetail`, never by a
menu, while the user opened it in that time. And a window drawn by Dalamud is always over the game's: the menu was behind.

## 3. The game's tabs on the user's screen

On the capture of 2026-11-16 23:10, the user's game chat draws its **tab bar at the bottom**, under the typing row (« Général », « Combat »,
« Evenements », then « + », a gear and a cross), and the channel's name « Dire » sits above the typing line, its top cut by Tensho's window.
This agrees with the 0.1502 reading (`tabs 24,1052 75x28`, under the typing box at y 1024), which 0.1503 had set aside as suspect
(docs/evidence/0.1502-game-chat-input.md, « Correction »): that reading looks right for this layout. The game also lets the tabs sit at the
top; both cases are handled (below).

## 4. What 0.1508 does (to be checked in the game, trial of X-533)

- **Tabs**: the tab bar's nodes (the tabs in use, « add a tab », both end images, the settings button) are hidden with the panels and given
  back with them (`ChatGameHide` on slots, `ChatTabBar`): held during a cutscene, given back in competitive content, on unload and on a
  failure. The typing box, the channel menu, the channel's name and the novice network button are never hidden. The window `ChatLog`
  itself is never made invisible.
- **Place**: Tensho's window takes the panel's box, from `ChatLog`'s own top when that top lies above the panel within its upper half
  (tabs at the top), down to the highest plausible top of the typing row: the typing box or the channel's name, each believed only inside
  `ChatLog` and in the panel's lower half (`ChatFollow.Box`).
- **Channel menu**: read open when `ChatLog`'s `CurrentDropDownOwnerNode` is set or the menu list's node is shown with all its parents
  (bounded walk); while Tensho's window follows the game's messages and the menu is open, the window is not drawn (the messages stay hidden:
  nothing blinks); it comes back when the menu closes.
- In developer mode, `dalamud.log` gets « Game chat: channel menu open|closed (drop-down owner set|none, list shown|hidden BOX) » on each
  change and « Game chat: Tensho's place BOX (window, panel, input, channel name) » when the place changes.

## 5. Not proven yet (the in-game trial tells)

- Which of the two signals the game sets when the channel menu opens, and that neither stays set once it is closed (if one did, Tensho's
  window would stay away: the log line says which).
- The box of the channel's name, and whether the gear, the cross and the novice network button belong to the tab bar row on every layout.
- Whether the game shows a hidden tab node again on its own (new tab, tab change): the hider hides it again on the next frame.
