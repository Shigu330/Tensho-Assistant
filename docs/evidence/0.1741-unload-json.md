# 0.1741: what keeps an unloaded copy of Tensho in the game process (X-685, part 1: System.Text.Json)

English first, then French.

## The measure (the log, game started at 02:53 on 21/11/2026)

- Managed memory of the process at each load (« Load created » and « 10 s later »): load 1 (fresh game) 295 MB then 385 MB; load 2
  470 / 544 MB; load 4 408 / 454 MB; load 6 544 / 661 MB; load 97 (18:16) 1439 MB. The process's private memory: 4475 MB at load 1,
  7684 MB at load 97.
- Developer mode, ten seconds after each load, one line per earlier copy: since the morning every one says « context alive, 0 of N parts
  alive » once a few loads have passed: the plugin object, the window and the closures are collected, the load context is not (its code,
  its static tables and what they hold stay in the process). Before that, a copy can stay held for a while (0.1730, loaded at 15:48: « 530
  of 540 parts alive » until 16:33, registrations disposed, no release left).

## Out of the game (21/11, .NET 10, the same runtime as the game's)

A small library loaded in a context that can unload (as Dalamud loads a plugin), one call, then unloaded and collected; meanwhile the host
goes on using System.Text.Json (as the other plugins and the next copy do):

| What the copy did | Its context after the unload |
|---|---|
| nothing with JSON | collected |
| System.Text.Json, default options (JsonSerializer without options) | alive, for good |
| System.Text.Json, options equal to the host's (same settings) | alive, for good |
| System.Text.Json, options with a resolver of their own | collected (once the runtime's reflection accessors expire, about a second) |
| Newtonsoft.Json shared with the host (default, with type names, or with a resolver of its own) | alive, for good |

The runtime's System.Text.Json keeps the type information it makes in the options that made it; its default options are one object for
the whole process, and options with the same settings share one cache. Newtonsoft.Json keeps types in caches of its own (static ones,
never emptied).

## What Tensho does (0.1741)

- Every options of Tensho is made by `TenshoJson.Own` (a resolver of its own, never equal to anyone else's options); `TenshoJson.Plain` in
  place of the default options. 41 calls changed, 18 options; a test fails on a call without Tensho's options or on options made elsewhere.
- JsonUnload1741Tests loads a copy of the tests in a context that can unload: with Tensho's options it is collected after the unload, with
  the default options it stays (the control).

## Not done yet

- Newtonsoft.Json: Dalamud saves and reads the plugin's settings with it (and Tensho makes the text of each save with it), so a copy of
  Tensho still stays in the process after its unload; the log's line « context alive » remains until that is cut (X-685, next part).
- Tried out of the game after 0.1741: with Newtonsoft's own caches emptied of the copy's types (8 entries), the copy still stays: Newtonsoft
  asks System.ComponentModel's TypeDescriptor about every type it writes, and TypeDescriptor (shared too) keeps the type in three private
  tables (ReflectTypeDescriptionProvider.s_attributeCache, TypeDescriptor.s_providerTable, TypeDescriptor.s_defaultProviderInitialized);
  TypeDescriptor.Refresh (type or assembly) does not empty them. Choice asked (D-206): Tensho saves its settings itself without
  Newtonsoft, or empties those private tables at unload, or leaves it.

# 0.1741 : ce qui garde une copie déchargée de Tensho dans le processus du jeu (X-685, partie 1 : System.Text.Json)

L'anglais d'abord, puis le français.

## La mesure (le journal, jeu lancé à 2 h 53 le 21/11/2026)

- Mémoire gérée du processus à chaque chargement (« Load created » et « 10 s later ») : chargement 1 (jeu neuf) 295 Mo puis 385 Mo ;
  chargement 2 470 / 544 Mo ; chargement 4 408 / 454 Mo ; chargement 6 544 / 661 Mo ; chargement 97 (18 h 16) 1 439 Mo. Mémoire privée du
  processus : 4 475 Mo au chargement 1, 7 684 Mo au chargement 97.
- Mode développeur, dix secondes après chaque chargement, une ligne par copie précédente : depuis le matin, chacune dit « context alive,
  0 of N parts alive » après quelques chargements : l'objet du plugin, la fenêtre et les fermetures sont libérés, le contexte de chargement
  ne l'est pas (son code, ses tables statiques et ce qu'elles tiennent restent dans le processus). Avant cela, une copie peut rester tenue un
  moment (0.1730, chargée à 15 h 48 : « 530 of 540 parts alive » jusqu'à 16 h 33, abonnements défaits, aucune libération restante).

## Hors du jeu (21/11, .NET 10, le même moteur que celui du jeu)

Une petite bibliothèque chargée dans un contexte déchargeable (comme Dalamud charge un plugin), un appel, puis déchargée et collectée ;
pendant ce temps, l'hôte continue d'utiliser System.Text.Json (comme les autres plugins et la copie suivante) :

| Ce que la copie a fait | Son contexte après le déchargement |
|---|---|
| rien en JSON | libéré |
| System.Text.Json, options par défaut (JsonSerializer sans options) | vivant, pour de bon |
| System.Text.Json, options égales à celles de l'hôte (mêmes réglages) | vivant, pour de bon |
| System.Text.Json, options avec un résolveur à elles | libéré (une fois expirés les accesseurs de réflexion du moteur, une seconde environ) |
| Newtonsoft.Json partagé avec l'hôte (par défaut, avec noms de types, ou avec un résolveur à lui) | vivant, pour de bon |

Le System.Text.Json du moteur garde les informations de type qu'il fabrique dans les options qui les ont faites ; ses options par défaut
sont un seul objet pour tout le processus, et des options de mêmes réglages partagent un seul cache. Newtonsoft.Json garde les types dans
des caches à lui (statiques, jamais vidés).

## Ce que fait Tensho (0.1741)

- Toutes les options de Tensho sont faites par `TenshoJson.Own` (un résolveur à elles, jamais égales aux options de quelqu'un d'autre) ;
  `TenshoJson.Plain` à la place des options par défaut. 41 appels changés, 18 options ; un test échoue sur un appel sans les options de
  Tensho ou sur des options faites ailleurs.
- JsonUnload1741Tests charge une copie des tests dans un contexte déchargeable : avec les options de Tensho elle est libérée après le
  déchargement, avec les options par défaut elle reste (le témoin).

## Pas encore fait

- Newtonsoft.Json : Dalamud enregistre et relit les réglages du plugin avec lui (et Tensho fait le texte de chaque enregistrement avec
  lui) : une copie de Tensho reste donc encore dans le processus après son déchargement ; la ligne « context alive » du journal reste tant
  que ce n'est pas coupé (X-685, partie suivante).
- Essayé hors du jeu après 0.1741 : les caches de Newtonsoft vidés des types de la copie (8 entrées), la copie reste encore : Newtonsoft
  interroge le TypeDescriptor de System.ComponentModel sur chaque type qu'il écrit, et TypeDescriptor (partagé lui aussi) garde le type dans
  trois tables privées (ReflectTypeDescriptionProvider.s_attributeCache, TypeDescriptor.s_providerTable,
  TypeDescriptor.s_defaultProviderInitialized) ; TypeDescriptor.Refresh (type ou assemblage) ne les vide pas. Choix demandé (D-206) : Tensho
  enregistre ses réglages lui-même sans Newtonsoft, ou vide ces tables privées au déchargement, ou laisse ainsi.
