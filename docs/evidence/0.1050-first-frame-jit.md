# 0.1050 — First frame of a page: mostly code compilation (X-01)

In the game, the self-check's page sweep of 2026-11-11 02:14 (dalamud.log, « Selftest draw » lines) measured the first frame of the
slowest pages at Gear 161.5 ms, SortPreview 130.9 ms, Storage 113.5 ms, Reminders 92.5 ms, Home 82.9 ms, Gathering 77.4 ms; once
drawn, the same pages settle under 1.1 ms. The first frame of a page comes once per load of the plugin, and is spent before anything
the page shows changes: a cost that is paid by the code itself, not by the data.

settled frame (median of the last ten). Same build, two runs: `--cold` stops the warm-up before it starts (the pages as before),

Without the game, 86 % of the first frames' time was compilation. The warm-up compiles 27 239 methods (the window first, then every
type of the plugin) in 2.3 s on one background thread below normal priority, 5 s after the window is built, 0 skipped. Working set
after a full collection: 544 MB in both runs (no measurable cost).

What stays on the first frame (`--jit-names`, methods compiled during it, by declaring type): generic code made for given type
arguments (`Enumerable` iterators, `Dictionary<uint,…>`), and the libraries' code (ImGui bindings, Lumina's texture decoding,
`GameIconLookup`) — the Gathering page's icons. A first warm-up limited to the window (5 122 methods, 0.8 s) brought the total to
152.9 ms; the rest of the plugin's types (Configuration 23 methods on Settings, GameTimerSnapshot 15 on Reminders, TenshoAlarm 11 on
Alarms, Credit 12 on Credits) brought it to 111.6 ms.

Gear and SortPreview are not measured here: without a character they show their « offline » line (0.2 and 1.9 ms). Their first frame
in the game is checked by the next page sweep, with the log line « JIT warm-up: N methods of the window and the plugin compiled ahead
in T ms, K skipped. » written once per load.
