## 0.1916.0
- Plan global, X-891 : Outil de tests : le gel complet du processus de tests sous charge (X-891, et sans doute les deux gels de X-671) avait pour cause un interblocage de la bibliothèque du runtime .NET entre deux écouteurs des événements du runtime (EventListener) fermés en même temps par deux tests : chacun prenait les deux verrous internes de la bibliothèque dans l'ordre inverse de l'autre, puis tout fil qui créait une source d'événements attendait à son tour, chien de garde compris. Cause lue dans l'image mémoire du processus figé du 27/11 par la bibliothèque d'accès aux données du runtime installée avec .NET (preuve : docs/evidence/0.1916-event-listener-deadlock.md). Correctif : tout écouteur des événements du runtime (mesures du mode développeur du plugin et tests) se crée et se ferme désormais sous un même verrou (RuntimeListeners.Gate), jamais deux à la fois. Le même risque existait dans le jeu en mode développeur (écouteur du chat et écouteur des deux minutes après le chargement).
- Tests : EventListenerGate1916Tests. Verify.ps1 (agent) : 4246/4246, 0 avertissement, 0 erreur ; DLL 0.1916.0.0. Rien à essayer en jeu.
### English
- Test tool: the whole test process freezing under load (X-891, and most likely X-671's two freezes) was caused by a deadlock in the .NET runtime library between two listeners of the runtime's events (EventListener) disposed at the same time by two tests: each took the library's two internal locks in the order opposite to the other's, then every thread that made an event source waited too, the watchdog included. The cause was read from the memory image of the process frozen on 27/11 through the runtime's data access library shipped with .NET (evidence: docs/evidence/0.1916-event-listener-deadlock.md). Fix: every listener of the runtime's events (the plugin's developer-mode measures and the tests) is now made and disposed under one gate (RuntimeListeners.Gate), never two at once. The same risk existed in the game in developer mode (the chat's listener and the two-minute listener after the load).
