Liste dressée par les images elles-mêmes : chaque image note les clés de texte d'erreur ou d'attente de l'image prise (LocalizationManager.KeyRead, Desktop/ReferenceErrors.cs) ; 7 pages en erreur (Peuples alliés, Grandes Compagnies, Félicité insulaire, Livraisons particulières, Carnaval masqué, Armes reliques, Pêche en mer) et 11 en attente sans fin. Cause : les fonctions qui lisent seulement les feuilles du jeu n'étaient données qu'en jeu (Plugin.cs). Elles sont maintenant données par une seule méthode, MainWindow.UseSheetLoaders, appelée par le plugin et par l'application de bureau (lexique, peuples, Grandes Compagnies, île, livraisons, carnaval, reliques, pêche en mer, aléas, contenus de terrain, donjons profonds) ; l'horaire de la pêche en mer passe dans Gathering/OceanScheduleLoader. Sans la lecture du personnage, la page Grandes Compagnies charge ses feuilles avec les noms de grades habituels. Là où une page montre ce que le jeu détient du joueur (peuples, Grandes Compagnies, île, livraisons, carnaval, livre des reliques), l'application dit « Lu dans le jeu » au lieu de rien. Les pages dont les données viennent d'un lecteur du jeu (collections, magie bleue, quêtes, Triple Triade, dresseur, livraisons spéciales, découvertes) disent « Lu dans le jeu » dans l'application au lieu d'un chargement sans fin. Une image dessine la page tant qu'elle attend encore (20 s au plus) ; la publication refuse une image qui montre une erreur ou une attente sans fin (images.py). Les images de référence sont refaites et attendent l'accord de l'utilisateur.
- Pour les joueurs : Application de bureau : pêche en mer, aléas, contenus de terrain, donjons profonds et armes reliques montrent leur contenu ; les pages qui demandent le jeu disent « Lu dans le jeu » au lieu d'une erreur ou d'un chargement sans fin.
- Tests : ReferenceErrors1300Tests. Verify.ps1 (agent) : 2405/2405, 0 avertissement, 0 erreur ; DLL 0.1300.0.0. Non validé en jeu.
