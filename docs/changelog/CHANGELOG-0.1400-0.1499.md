## 0.1493.0
- Plan global, X-514 : Historique du chat sur ce PC, constats de la relecture de 0.1492 (X-514, X-515). I1 : un lien de Dalamud ou d'un plugin n'est plus gardé comme lien sur le disque, seulement son texte ; une ligne écrite par 0.1492 avec un tel lien est relue comme du texte. Son numéro de commande ne vaut que pour la session où le plugin l'a inscrit : après un rechargement ou une relance, un clic sur un vieux lien pouvait lancer une autre action du plugin. Les liens de lieu, d'objet, de quête et web restent des liens. M1 : « Effacer l'historique » juste après la relecture d'un fichier (relu, pas encore placé dans la fenêtre) ne laisse plus revenir les messages effacés à la seconde suivante : les messages relus attendent dans l'écrivain de l'historique, que l'arrêt, l'effacement et le changement de personnage vident. M2 : dans l'application de bureau, les réglages de l'historique sont grisés avec la raison (l'historique se garde et s'efface dans le jeu seulement) ; la question d'accord n'y s'ouvre plus avec « - » à la place du dossier. M3 : une écriture en cours quand le joueur décoche la case ou efface l'historique est reprise (le fichier revient à sa longueur d'avant, ou est supprimé s'il venait d'être créé) et rien n'est écrit après elle. M4 : les messages du disque datés de la même seconde que la première ligne de la session sont relus, sauf ceux que la session a déjà (même heure, sorte, auteur et texte, comptés). M5 : le journal ne reçoit plus l'erreur elle-même, dont le message contient le chemin du fichier et donc le numéro du personnage : il reçoit le message, la sorte d'erreur et son texte avec le numéro remplacé par <character> (aussi pour les erreurs de l'écrivain en arrière-plan).
- Pour les joueurs : historique du chat : un lien de plugin relu après un rechargement est du texte simple et ne peut plus lancer une ancienne action ; effacer l'historique juste après un rechargement ne fait plus revenir d'anciens messages ; les messages de la même seconde que le rechargement ne sont plus perdus.
- Tests : ChatHistory1493Tests (6 cas : lien de plugin relu en texte et sans rien à cliquer, effacement juste après une relecture, écriture reprise quand la case est décochée ou l historique effacé pendant elle, lignes de la même seconde relues sans doublon, journal sans numéro de personnage, réglages grisés hors du jeu) ; ChatHistory1492Tests adapté. Verify.ps1 (agent) : 2947/2947, 0 avertissement, 0 erreur ; DLL 0.1493.0.0. Non validé en jeu.
### English
- Chat history on this PC, findings of the review of 0.1492 (X-514, X-515). I1: a link of Dalamud or of a plugin is no longer kept as a link on disk, only its text; a line written by 0.1492 with such a link is read back as text. Its command number is valid only in the session where the plugin registered it: after a reload or a restart, a click on an old link could run another action of that plugin. Place, item, quest and web links stay links. M1: « Erase the history » right after a file was read back (read, not yet put in the window) no longer lets the erased messages come back the next second: the messages read back wait in the history's writer, which turning it off, erasing and a change of character empty. M2: in the desktop app, the history's settings are greyed with the reason (the history is kept and erased in the game only); the consent question no longer opens there with « - » instead of the folder. M3: a write under way when the player unticks the box or erases the history is taken back (the file cut back to its length before, or deleted when that write made it), and nothing is written after it. M4: the messages on disk from the same second as the session's first line are read back, except those the session already holds (same time, kind, sender and text, counted). M5: the log no longer receives the error itself, whose message holds the file's path and so the character's number: it receives the message, the error's kind and its text with the number replaced by <character> (the background writer's errors too).
- For players: Chat history: a plugin's link read back after a reload is plain text and can no longer run an old action; erasing the history right after a reload no longer brings old messages back; messages of the same second as the reload are no longer lost.
