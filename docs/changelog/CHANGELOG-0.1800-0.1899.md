M2 : un jeu tué ou planté pendant la copie qui précède « vider la base » laissait pour toujours dans le dossier Backups la copie entière de la base (snapshot-<guid>.db.tmp) ou un zip à moitié écrit (le ménage ne prenait que les copies finies) ; ces fichiers de passage, et eux seuls (BackupZip.Leftover), sont retirés une fois vieux d'une heure, à chaque copie et au chargement (BackupZip.Sweep ; un fichier tenu ouvert par une copie encore en cours est laissé). M1 : la copie (VACUUM INTO de toute la base, puis le zip) se fait hors du fil du jeu (DiscoveryBackup.Start) ; le bouton la faisait dans Draw, le jeu se figeait plusieurs secondes avec une grosse base ; la base est vidée une fois la copie finie, une fois par seconde sur le fil du jeu, même page fermée, jamais si elle a échoué (dit sur la page). M3 : le cliquet des fils bruts des tests (X-783) n'accepte plus qu'un fil dont tout le corps est un try avec un catch (Exception …) sans filtre qui garde l'exception, et dont l'exception gardée est vérifiée par un Check après le Join (suivie jusqu'aux appels d'une aide comme Greedy) ; un catch autour d'une partie du travail ne passe plus. La cause du plantage du 22/11 reste supposée : écartée avec sa raison (10 passages de stress verts sur 0.1796 ; la trace d'un prochain plantage est désormais gardée par les outils). DiscoveryClear1800Tests (5), RawThreads1800Tests (4).

### English
- Discoveries and tests: minor findings of the review of 0.1796 to 0.1799 (X-793, X-794). M2: a game killed or crashed during the copy taken before « empty the base » left in the Backups folder for good the whole copy of the base (snapshot-<guid>.db.tmp) or a half-written zip (the cleaning took only finished copies); those passing files, and only those (BackupZip.Leftover), are removed once an hour old, at each copy and at load (BackupZip.Sweep; a file held open by a copy still running is left). M1: the copy (VACUUM INTO of the whole base, then the zip) is made off the game's thread (DiscoveryBackup.Start); the button made it in Draw and the game froze for seconds with a big base; the base is emptied once the copy ended, once a second on the game's thread, even with the page closed, never when it failed (said on the page). M3: the ratchet over the tests' raw threads (X-783) only accepts a thread whose whole body is a try with an unfiltered catch (Exception …) keeping the exception, and whose kept exception is read by a Check after the Join (followed to the calls of a helper such as Greedy); a catch around part of the work no longer passes. The cause of the crash of 22/11 stays assumed: set aside with its reason (10 green stress runs on 0.1796; the trace of a next crash is now kept by the tools). DiscoveryClear1800Tests (5), RawThreads1800Tests (4).
