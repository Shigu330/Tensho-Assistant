# Journal des versions / Changelog, 0.1800 à 0.1899

## 0.1801.0
- Plan global, X-772 : Découvertes partagées : confidentialité des fichiers de joueur (X-772, choix de l'utilisateur du 22/11, R12.2). Les fichiers de joueur du dépôt (community-discoveries/players) gardaient, à côté du login GitHub, le lieu exact (X, Z) et les jours (First, Last) de chaque fait : pour un poisson, où était ce compte ce jour-là. Ils ne gardent plus que ce que la fusion demande (l'identité du fait, ses niveaux, ses observations HQ et ses valeurs), compressés comme les fichiers communs : <ticket>.jsonl.gz (en-tête tensho-discoveries-player version 1, puis un fait par ligne). L'outil de fusion (tools/discoveries-merge.py) prend le premier lieu exact et les jours de chaque fait dans l'ensemble commun tel qu'il est, dans les fichiers d'avant (encore lus, réécrits au nouveau format par rebuild) et dans les gists que lit sync ; un fait dont le lieu n'est nulle part attend dans son fichier qu'un partage l'apporte ; retirer un joueur retire les faits qu'aucun autre n'a. Le fichier du ticket 43 est réécrit par l'outil (rebuild) dans ce commit : 3370 faits, plus aucun lieu ni jour, 819 Ko devenus 23 Ko ; l'ensemble commun v3 est resté identique octet pour octet. L'historique git garde les anciens fichiers (aucune réécriture d'historique). Le plugin ne lit que l'ensemble commun, jamais un fichier de joueur. Selftest de l'outil 78/78 (cas de comportement : un fichier de joueur produit ne contient ni lieu ni jour ; un fichier d'avant converti, l'ensemble commun aux mêmes octets ; lieux et jours venus des gists ; fait sans lieu connu en attente ; fichiers abîmés refusés ; retrait). DEC-052 complétée ; community-discoveries/README.md et tools/README.md (deux moitiés). Les tests lisent les deux formats (RepositoryCommon.Players) ; DiscoveryPlayers1801Tests (3).
- Pour les joueurs : découvertes partagées : le dépôt ne garde plus, à côté de votre nom GitHub, le lieu exact ni le jour de ce que vous avez partagé (l'ensemble commun les garde sans aucun nom).
- Tests : DiscoveryPlayers1801Tests. Verify.ps1 (agent) : 3941/3941, 0 avertissement, 0 erreur ; DLL 0.1801.0.0. Rien à essayer en jeu.
### English
- Shared discoveries: privacy of the player files (X-772, user choice of 22/11, R12.2). The player files of the repository (community-discoveries/players) kept, next to the GitHub login, each fact's exact place (X, Z) and days (First, Last): for a fish, where that account was on that day. They now keep only what the merge needs (the fact's identity, its levels, its HQ sightings and values), compressed like the common files: <issue>.jsonl.gz (a tensho-discoveries-player version 1 header, then one fact per line). The merge tool (tools/discoveries-merge.py) takes each fact's earliest exact place and its days from the common set as it is, from the files of before (still read, written again in the new format by rebuild) and from the gists sync reads; a fact whose place is nowhere waits in its file until a share brings it; withdrawing a player removes the facts no other player has. The file of issue 43 is written again by the tool (rebuild) in this commit: 3370 facts, no place nor day left, 819 KB down to 23 KB; the v3 common set stayed the same byte for byte. The git history keeps the old files (no history rewrite). The plugin reads the common set only, never a player file. The tool's selftest 78/78 (behaviour cases: a player file produced holds neither place nor day; a file of before converted, the common set the same bytes; places and days from the gists; a fact without a known place waiting; damaged files refused; withdrawal). DEC-052 completed; community-discoveries/README.md and tools/README.md (both halves). The tests read both formats (RepositoryCommon.Players); DiscoveryPlayers1801Tests (3).
- For players: Shared discoveries: the repository no longer keeps, next to your GitHub name, the exact place and the day of what you shared (the common set keeps them without any name).

## 0.1800.0
- Plan global, X-793 : Découvertes et tests : mineurs de la relecture du bloc 0.1796 à 0.1799 (X-793, X-794). M2 : un jeu tué ou planté pendant la copie qui précède « vider la base » laissait pour toujours dans le dossier Backups la copie entière de la base (snapshot-<guid>.db.tmp) ou un zip à moitié écrit (le ménage ne prenait que les copies finies) ; ces fichiers de passage, et eux seuls (BackupZip.Leftover), sont retirés une fois vieux d'une heure, à chaque copie et au chargement (BackupZip.Sweep ; un fichier tenu ouvert par une copie encore en cours est laissé). M1 : la copie (VACUUM INTO de toute la base, puis le zip) se fait hors du fil du jeu (DiscoveryBackup.Start) ; le bouton la faisait dans Draw, le jeu se figeait plusieurs secondes avec une grosse base ; la base est vidée une fois la copie finie, une fois par seconde sur le fil du jeu, même page fermée, jamais si elle a échoué (dit sur la page). M3 : le cliquet des fils bruts des tests (X-783) n'accepte plus qu'un fil dont tout le corps est un try avec un catch (Exception …) sans filtre qui garde l'exception, et dont l'exception gardée est vérifiée par un Check après le Join (suivie jusqu'aux appels d'une aide comme Greedy) ; un catch autour d'une partie du travail ne passe plus. La cause du plantage du 22/11 reste supposée : écartée avec sa raison (10 passages de stress verts sur 0.1796 ; la trace d'un prochain plantage est désormais gardée par les outils). DiscoveryClear1800Tests (5), RawThreads1800Tests (4).
- Tests : DiscoveryClear1800Tests. Verify.ps1 (agent) : 3938/3938, 0 avertissement, 0 erreur ; DLL 0.1800.0.0. Rien à essayer en jeu.
### English
- Discoveries and tests: minor findings of the review of 0.1796 to 0.1799 (X-793, X-794). M2: a game killed or crashed during the copy taken before « empty the base » left in the Backups folder for good the whole copy of the base (snapshot-<guid>.db.tmp) or a half-written zip (the cleaning took only finished copies); those passing files, and only those (BackupZip.Leftover), are removed once an hour old, at each copy and at load (BackupZip.Sweep; a file held open by a copy still running is left). M1: the copy (VACUUM INTO of the whole base, then the zip) is made off the game's thread (DiscoveryBackup.Start); the button made it in Draw and the game froze for seconds with a big base; the base is emptied once the copy ended, once a second on the game's thread, even with the page closed, never when it failed (said on the page). M3: the ratchet over the tests' raw threads (X-783) only accepts a thread whose whole body is a try with an unfiltered catch (Exception …) keeping the exception, and whose kept exception is read by a Check after the Join (followed to the calls of a helper such as Greedy); a catch around part of the work no longer passes. The cause of the crash of 22/11 stays assumed: set aside with its reason (10 green stress runs on 0.1796; the trace of a next crash is now kept by the tools). DiscoveryClear1800Tests (5), RawThreads1800Tests (4).
