## 0.1033.0
- Plan global, X-121 : Application de bureau : mise à jour automatique depuis les releases GitHub du dépôt, sans geste de l'utilisateur (X-121). Au démarrage (et sur « Chercher une mise à jour »), elle demande la release qui a la version du plugin installé, sinon la dernière release Stable (HTTPS, aucune donnée du joueur, aucune requête quand les versions sont déjà les mêmes) ; elle vérifie que c'est une Stable publiée de ce dépôt, télécharge TenshoAssistant.Desktop.zip depuis l'adresse de téléchargement du dépôt, compare son SHA-256 à celui publié dans la même release (TenshoAssistant.Desktop.zip.sha256), l'installe à côté (%LOCALAPPDATA%\TenshoAssistant\Desktop\versions) en vérifiant les versions de l'application et du plugin qu'il contient, et garde la version d'avant. L'exe en cours n'est jamais écrasé : la copie lancée passe la main à la plus récente au démarrage ; la nouvelle version ne redémarre seule que si la fenêtre n'a pas servi et que les catalogues sont chargés, sinon au prochain démarrage ou sur « Redémarrer maintenant ». « Version d'avant » revient en arrière et met la version de côté ; une copie qui échoue au démarrage revient seule à la précédente ; « Mise à jour automatique » la coupe. Publication : Verify.ps1 écrit l'empreinte et essaie la mise à jour sur une fausse release locale (installation, passage de main, retour en arrière, zip abîmé et adresse étrangère refusés) ; Release.ps1 refuse une release sans l'empreinte et la joint à la release. Source réseau déclarée (SECURITY.md) ; nouvelle question de la FAQ. Limite dite dans SECURITY, la FAQ et le README : sans signature de code, l'empreinte protège d'un fichier abîmé, pas d'un compte GitHub volé. Dépôt (D-100, X-123) : code de conduite en deux langues (CODE_OF_CONDUCT.md), CODEOWNERS (revue du propriétaire demandée sur les demandes de fusion des autres), hook pre-push actif chez le mainteneur, qui réutilise le repère de Verify : pas de deuxième compilation après publish.sh. Preuve dans docs/evidence (X-121).
- Tests : DesktopUpdate1033Tests. Verify.ps1 (agent) : 1681/1681, 0 avertissement, 0 erreur ; DLL 0.1033.0.0. Non validé en jeu.
### English
- Desktop application: automatic update from the repository's GitHub releases, with no step for the user (X-121). At start (and on « Check for update »), it asks for the release that has the installed plugin's version, else the latest Stable release (HTTPS, no player data, no request when the versions are already the same); it checks that it is a published Stable release of this repository, downloads TenshoAssistant.Desktop.zip from the repository's download address, compares its SHA-256 with the one published in the same release (TenshoAssistant.Desktop.zip.sha256), installs it beside (%LOCALAPPDATA%\TenshoAssistant\Desktop\versions) after checking the versions of the app and plugin inside, and keeps the version before. The running exe is never overwritten: the copy started hands over to the newest one at start; the new version restarts by itself only when the window was not used and the catalogues are loaded, otherwise at the next start or on « Restart now ». « Previous version » goes back and sets the version aside; a copy that fails at start goes back to the previous one by itself; « Automatic update » turns it off. Publishing: Verify.ps1 writes the hash and tries the update on a fake local release (install, hand-over, going back, damaged zip and foreign address refused); Release.ps1 refuses a release without the hash and attaches it to the release. Network source declared (SECURITY.md); new FAQ question. Limit stated in SECURITY, the FAQ and the README: without code signing, the hash protects against a damaged file, not against a stolen GitHub account. Repository (D-100, X-123): code of conduct in two languages (CODE_OF_CONDUCT.md), CODEOWNERS (owner review requested on other people's pull requests), pre-push hook active on the maintainer's PC, reusing Verify's stamp: no second build after publish.sh. Evidence in docs/evidence (X-121).
