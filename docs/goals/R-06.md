# R-06 — Refonte de l'interface (plan, à valider avant tout code)

Demande (2026-11-01) : revoir entièrement l'interface, style FF14, sans alourdir les pages ; relier tous les outils ; icônes d'objet
partout avec l'infobulle et le clic droit adéquats ; noms plus cohérents rangés par catégorie ; marché Tensho plus riche (plusieurs
prix par objet, quantité min/max, fourchette de prix).

Principe : KEEP → EXTEND. On garde les outils existants, on change l'enveloppe et on factorise. Une étape = une version vérifiable.

## Étape 1 — Bibliothèque de modèles communs (fondation)

Choix : des composants C# partagés (dossier `UI/Components/`), appelés par chaque page. Pas un script externe : avec ImGui, chaque
image redessine tout, et un appel de méthode suffit. Chaque modèle est écrit une fois, testé, puis utilisé partout. Une
page n'assemble plus que des modèles.

| Modèle | Rôle |
|---|---|
| `ItemCell` | affichage d'un objet (détail ci-dessous) |
| `Tip` | infobulle unique : largeur bornée, jamais hors de l'écran, texte grisé interdit, lignes « clic / clic droit » normalisées |
| `ContextMenu` | menu de clic droit construit par type de chose (objet, PNJ, quête, monstre, lieu…) à partir des liens disponibles |
| `DetailPage` | fiche : en-tête (icône, nom, données clés, liens) + onglets calculés seulement s'ils sont ouverts |
| `FilteredTable` | tableau compact : recherche, filtres, tri, liste virtualisée, état « chargement / erreur / vide » dit en clair |
| `SettingRow` | un réglage : contrôle + infobulle obligatoire + bouton « valeur par défaut » + sauvegarde |
| `SourceStamp` | provenance et âge des données (jeu, cache, Garland, Universalis…) affichés de la même façon partout |

Le premier client de ces modèles est l'affichage d'objet :


- Un seul composant `ItemCell` : icône du jeu, nom (couleur de rareté), quantité, HQ.
  - Survol : l'infobulle d'objet commune (`DrawItemInfoTooltip`) ;
  - clic : devient l'objet en contexte ;
  - clic droit : le menu commun des outils utiles (`ItemLinksMenu` / `RelevantRoutes`, déjà partagé).
- Relevé de toutes les listes qui affichent un objet sans ce composant, puis remplacement module par module.
- Résultat : le même comportement partout, et moins de code par page.

- Un même nom pour le même outil dans la navigation, les titres et les menus de clic droit.

## Étape 3 — Fiches complètes et Objets / Rangements séparés

Exemple donné par l'utilisateur (capture, 2026-11-01, Objets & rangements › Recherche, « Carte Bugaal Ja ») : sous les
résultats, « Objet sélectionné » n'affiche que l'icône, le nom et la phrase « Passez à l'onglet Stocks ou Craft lié pour
consulter les détails ». Ce qui est attendu à la place, sur la même page : la fiche complète de l'objet sélectionné.
- En-tête : icône, nom, catégorie, niveaux, collection (obtenu ou non), stock total, prix.
- Onglets : Comment l'obtenir · Usages · Fabrication · Récolte · Stocks (où sont les exemplaires) · Marché.
- Le même contenu que l'infobulle commune (`DrawItemInfoBody`), en plus détaillé, avec des liens cliquables.
- On garde les onglets du haut (Stocks, Craft lié…) seulement si la fiche ne les remplace pas ; sinon ils disparaissent.

Règle (demande 2026-11-01) : quand on sélectionne un objet **ou autre chose** (quête, PNJ, monstre, contenu, carte, poisson,
carte de Triple Triad…), **toutes** ses informations sont sur la même page, réparties en onglets si besoin. On n'a pas à
changer de module pour les voir. Chaque fiche a son en-tête (icône, nom, données clés) et ses liens vers les autres fiches.


- **Objets** : la fiche de l'objet en contexte (en-tête : icône, niveau, catégorie, prix) et des onglets Sources / Usages /
  Fabrication / Récolte / Prix. Un onglet n'est calculé que lorsqu'il est ouvert.
- **Rangements** : où sont mes objets.
  - Recherche dans tous les rangements.
  - Grille par conteneur, comme dans le jeu, avec des `ItemCell`.
  - Filtres : catégorie, rangement, personnage ou servant, HQ, emplacements vides.
  - Le tri d'inventaire y est rattaché.

## Étape 4 — Marché Tensho enrichi

- Données : Universalis `GET /api/v2/{monde|centre de données|région}/{itemId}?listings=…&entries=…`.
  - On garde les mêmes garde-fous qu'aujourd'hui : 3 s minimum entre deux requêtes, cache « Prix ».
  - Toutes les annonces : prix unitaire, quantité, total, HQ, monde, vendeur, date de mise à jour.
- Filtres :
  - HQ / NQ ;
  - quantité minimum et maximum par annonce ;
  - fourchette de prix (minimum et maximum) ;
  - monde.
- **Coût pour N unités** : les annonces les moins chères qui couvrent N unités, avec le total et le monde de chaque achat.
- Historique : dernières ventes, avec le prix minimum, la moyenne, le maximum et le volume par jour.
- Accessible depuis tout `ItemCell` (clic droit › Marché).

## Étape 5 — Réglages complets et infobulles

- Relevé de tous les réglages, module par module.
- On ajoute ceux qui manquent : ce qui est aujourd'hui figé dans le code et qu'un joueur voudrait choisir (durées, tailles,
  affichage par défaut, sources communautaires…).
- **Chaque** réglage a une infobulle : ce qu'il fait, sa valeur par défaut, son effet sur les performances ou le réseau.
- Un contrôle automatique dans Verify signale un réglage sans infobulle (clé `…Help` absente des fichiers de langue).
- **Remettre les réglages par défaut** :
  - un bouton par réglage (`SettingRow`) ;
  - un bouton par module ;
  - un bouton « Tout remettre par défaut », avec confirmation.
  - Les données gardées (alarmes, banque, préréglages, favoris) ne sont jamais effacées par ces boutons. Elles ont leur propre
    bouton, séparé, lui aussi avec confirmation.

## Étape 6 — Style FF14 et légèreté

- Un seul jeu de composants (`UiComponents`) : panneaux encadrés, titres dorés, tableaux compacts, boutons à icône.
  - Le thème suit le jeu, comme aujourd'hui.
- Rien de lourd dans Draw :
  - projections mises en cache par référence d'état (pas de LINQ refait à chaque image) ;
  - listes longues virtualisées (`ImGuiListClipper`).
- Relevé des pages les plus coûteuses avant et après, avec le temps de Draw mesuré dans Diagnostics.

si elle est prioritaire. Chaque étape : Verify vert, CHANGELOG, puis essai en jeu avant la suivante.
