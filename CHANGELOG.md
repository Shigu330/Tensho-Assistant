# Journal des versions / Changelog

Résumé par version, en français puis `### English` (partie anglaise obligatoire depuis 0.219.0) ; la partie anglaise sert aussi de corps
aux commits et aux notes de release sur GitHub. Preuves citées : docs/evidence/.

## 0.1351.0
- Plan global, X-365 : Menu Tensho au clic droit sur un lien de carte du chat (demande de l'utilisateur du 14/11, choix « clic gauche : le drapeau du jeu ; clic droit : menu complet Tensho cohérent avec celui d'un objet ») : le clic gauche reste au jeu ; un clic droit sur le lien ouvre à la souris le menu « Tensho — lieu » avec les entrées du menu de lieu de Tensho (drapeau, éthérite la plus proche et son coût, retirer le drapeau, carte Tensho sur le point, météo de la zone). Sonde (preuve docs/evidence/0.1351-chat-map-link-menu.md) : ni le jeu ni le menu contextuel de Dalamud n'ont de menu pour un lien de carte ; les panneaux du chat reçoivent les événements de survol de lien (76 et 77, données LinkData), que Dalamud montre par IAddonLifecycle (PreReceiveEvent) : aucun crochet de Tensho, lecture seule, rien n'est envoyé au jeu, rien pendant une coupure, même réglage que la liste des liens (Carte › Liens de carte du chat). Classe pure ChatLinkHover (survol, sortie avec 150 ms de grâce, coupure, réglage) ; lecture du lien dans ChatLinkHoverWatcher ; menu dans MainWindow.DrawChatLinkMenu.
- Pour les joueurs : Un clic droit sur un lien de carte du chat ouvre le menu Tensho de ce lieu : drapeau, éthérite la plus proche avec son coût, carte Tensho, météo. Le clic gauche pose toujours le drapeau du jeu.
- Tests : ChatLinkMenu1351Tests. Verify.ps1 (agent) : 2530/2530, 0 avertissement, 0 erreur ; DLL 0.1351.0.0. Non validé en jeu.
### English
- Tensho menu on a right click of a chat map link (user request of 14/11, choice « left click: the game's flag; right click: a full Tensho menu consistent with an item's »): the left click stays the game's; a right click on the link opens at the mouse the « Tensho — place » menu with the entries of Tensho's place menu (flag, nearest aetheryte and its cost, remove the flag, Tensho map on the point, zone weather). Probe (evidence docs/evidence/0.1351-chat-map-link-menu.md): neither the game nor Dalamud's context menu has a menu for a map link; the chat panels receive the link hover events (76 and 77, LinkData), which Dalamud shows through IAddonLifecycle (PreReceiveEvent): no hook of Tensho's own, read only, nothing sent to the game, nothing during a cut, same setting as the link list (Map › Chat map links). Pure class ChatLinkHover (hover, out with a 150 ms grace, cut, setting); link read in ChatLinkHoverWatcher; menu in MainWindow.DrawChatLinkMenu.
- For players: A right click on a map link in the chat opens Tensho's menu for that place: flag, nearest aetheryte with its cost, Tensho map, weather. The left click still sets the game's flag.

## 0.1350.0
- Plan global, X-363 : Correction de la ligne « Ajouté au patch 7.x (Garland Tools) » (essai T-0.1317-1 du 14/11) : elle ne lisait que ce que Garland avait déjà rendu pour les sources, et Garland n'est demandé pour les sources que si les données du jeu n'en connaissent aucune ; un objet vendu par un PNJ (49731, Bague d'attaquant de grand champion, patch 7.4 chez Garland) n'avait donc jamais la ligne, ni dans l'en-tête de sa fiche ni dans son infobulle. La fiche demande maintenant le document Garland de son objet (une requête, cache partagé) ; l'infobulle le demande quand la souris reste 0,6 s sur le même objet (HoverDwell), jamais pour chaque ligne balayée ; rien quand Garland ou son usage « sources des objets » est coupé. Preuve complétée : docs/evidence/0.1227-garland-patch.md.
- Pour les joueurs : La ligne « Ajouté au patch » s'affiche de nouveau pour les objets vendus par des PNJ, dans la fiche de l'objet et dans son infobulle (souris gardée sur l'objet).
- Tests : ItemPatchAsk1350Tests. Verify.ps1 (agent) : 2526/2526, 0 avertissement, 0 erreur ; DLL 0.1350.0.0. Non validé en jeu.
### English
- Fix of the « Added in patch 7.x (Garland Tools) » line (test T-0.1317-1 of 14/11): it only read what Garland had already given for the sources, and Garland is asked for the sources only when the game data knows none; an item sold by an NPC (49731, Grand Champion's Ring of Slaying, patch 7.4 on Garland) therefore never had the line, neither in its sheet header nor in its tooltip. The sheet now asks for its item's Garland document (one request, shared cache); the tooltip asks for it once the mouse rests 0.6 s on the same item (HoverDwell), never for every row swept; nothing while Garland or its « item sources » use is off. Evidence extended: docs/evidence/0.1227-garland-patch.md.
- For players: The « Added in patch » line shows again for items sold by NPCs, in the item sheet and in the item tooltip (hold the mouse on the item).
