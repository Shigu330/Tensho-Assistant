## 0.1827.0
- Plan global, X-826 : L'en-tête d'un fichier joueur des découvertes partagées (community-discoveries/players) n'admettait au test DiscoveryPlayers1801Tests que Format, Version, Issue, Login et Count, alors que l'outil de fusion y écrit aussi Gist et Revision (X-804) et Counted (X-808) : toute fusion faite avec l'outil actuel (sync, travailleur du portable, PR « note seule ») échouait à la CI (PR #54). Une seule liste désormais, PLAYER_HEADER de tools/discoveries-merge.py : player_bytes n'écrit rien d'autre (sinon arrêt), read_player refuse un en-tête qui porte un autre champ, et les tests lisent cette liste. La règle de l'en-tête (DiscoveryHeader1827Tests.Header) : ces champs seulement, dans cet ordre, chacun de sa forme (numéro du ticket qui nomme le fichier, ou nom aléatoire d'un fichier anonyme « withdrawn » sans login ; login GitHub ; gist et révision en hexadécimal, ensemble ; Counted oui ou non ; nombre de faits), jamais un nom de personnage, un monde, un lieu ni un jour. Elle s'applique aux fichiers du dépôt et à ceux que l'outil actuel écrit (un partage fusionné avec son gist noté, le fichier anonyme d'un joueur retiré, X-803). Auto-test de l'outil 112/112 (en-tête exact ; World, Name, X, First refusés à la lecture).
- Tests : DiscoveryHeader1827Tests. Verify.ps1 (agent) : 4018/4018, 0 avertissement, 0 erreur ; DLL 0.1827.0.0. Rien à essayer en jeu.
### English
- The header of a shared-discoveries player file (community-discoveries/players) allowed only Format, Version, Issue, Login and Count in the DiscoveryPlayers1801Tests test, while the merge tool also writes Gist and Revision (X-804) and Counted (X-808): every merge made with the current tool (sync, the laptop worker, a « note only » pull request) failed CI (PR #54). One list now, PLAYER_HEADER of tools/discoveries-merge.py: player_bytes writes nothing else (else it stops), read_player refuses a header holding another field, and the tests read that list. The header rule (DiscoveryHeader1827Tests.Header): those fields only, in that order, each of its own shape (the issue number naming the file, or the random name of an anonymous « withdrawn » file without a login; a GitHub login; a gist and revision in hex, together; Counted yes or no; the fact count), never a character name, a world, a place nor a day. It applies to the repository's files and to those the current tool writes (a share merged with its gist noted, the anonymous file of a withdrawn player, X-803). Tool selftest 112/112 (exact header; World, Name, X, First refused on reading).

## 0.1826.0
- Plan global, X-824 : Relecture de 0.1823, constats mineurs. M1 : « ShareOldGistKept » prenait la place de « Sent », si bien que l'avis « ShareAsideGivenUp » (des copies mises de côté abandonnées, retirées du gist) n'était jamais dit tant que l'ancien gist d'un autre compte attendait, et meta.AsideGivenUp restait vrai. L'envoi lui-même le dit désormais (Rotate rend aussi « remplacé ») : l'abandon est dit une fois, à l'envoi qui remplace le gist, puis « ShareOldGistKept » aux échanges suivants (il se redit tant que ce gist attend). M2 (tools/discoveries-trust.py) : des états passagers donnaient un doute public au lieu d'attendre : mergeable « UNKNOWN » (GitHub pas encore calculé, juste après un push) attend maintenant (sortie 4) ; un statut de commit (StatusContext, sans « status ») n'est fini qu'à SUCCESS, FAILURE ou ERROR, PENDING et EXPECTED attendent ; une vérification sans statut n'est plus prise pour finie. La raison « pr-conflict » ne parle plus que d'un conflit. Tests : ReviewMinors1826Tests (M1 contre un faux GitHub, câblage de M2) ; auto-test de l'outil 67/67 (4 cas M2), lancé par DiscoveryOrigin1824Tests.
- Pour les joueurs : quand des copies de découvertes abîmées ont dû être abandonnées, Tensho le dit maintenant au prochain envoi, même si un ancien gist d'un autre compte GitHub attend encore d'être supprimé.
- Tests : ReviewMinors1826Tests. Verify.ps1 (agent) : 4015/4015, 0 avertissement, 0 erreur ; DLL 0.1826.0.0. Rien à essayer en jeu.
### English
- Review of 0.1823, minor findings. M1: « ShareOldGistKept » took the place of « Sent », so the notice « ShareAsideGivenUp » (copies set aside given up, gone from the gist) was never said while another account's old gist waited, and meta.AsideGivenUp stayed true. The upload itself now tells it (Rotate also returns « replaced »): the give-up is said once, at the send that replaces the gist, then « ShareOldGistKept » at the next exchanges (said again while that gist waits). M2 (tools/discoveries-trust.py): passing states gave a public doubt instead of waiting: mergeable « UNKNOWN » (GitHub not computed yet, just after a push) now waits (exit 4); a commit status (StatusContext, no « status ») is finished only at SUCCESS, FAILURE or ERROR, PENDING and EXPECTED wait; a check without its status is no longer taken as finished. The « pr-conflict » reason now speaks of a conflict only. Tests: ReviewMinors1826Tests (M1 against a fake GitHub, M2 wiring); tool selftest 67/67 (4 M2 cases), run by DiscoveryOrigin1824Tests.
- For players: When copies of damaged discoveries had to be given up, Tensho now says so at the next send even if an older gist of another GitHub account is still waiting to be deleted.

## 0.1825.0
- Plan global, X-822 : Découvertes partagées, sûreté des données : l'écriture de github.json (le gist en cours, le ticket, depuis X-804) qui échouait (disque plein, fichier verrouillé, droits) était avalée sans trace, et l'échange suivant pouvait créer un nouveau gist et un nouveau ticket en laissant l'ancien gist, avec ses lieux et ses jours, jamais supprimé. Désormais SaveMeta rend vrai ou faux et l'échec est dit une fois dans le journal (puis « written again » quand l'écriture repasse) ; aux étapes du gist et du ticket (après la création du gist, après le ticket, après une fusion constatée, après l'envoi), un échec arrête l'échange avec le message « ExchangeMetaUnsaved » sur la page Découvertes : aucun ticket n'est ouvert, le gist déjà créé est noté dans l'état de rotation (X-819) et réécrit à l'échange suivant, jamais un second. Après un échec, l'échange suivant réécrit github.json avant tout envoi, sinon rien n'est créé ni écrit sur GitHub. Pas d'écriture préalable quand la dernière a réussi : la copie de ce client effacerait une connexion renouvelée par un autre client du même profil (cas de GitHubToken1171). Base des découvertes : une ligne illisible rencontrée par un enregistrement (faits vus depuis le dernier) ou par la relecture d'une copie du gist était prise pour absente et écrasée sans le dire ; son texte est maintenant copié dans facts_aside (gardé, jamais effacé), la clé réglée quand la ligne est réécrite avec le fait entier de ce client, et c'est dit dans le journal (le plugin donne son journal à la base). Tests de comportement MetaUnsaved1825Tests (github.json bloqué par un dossier contre un faux GitHub : arrêt au gist, aucun ticket, rien ensuite, dit une fois, puis le même gist réécrit ; github.json perdu juste après le gist ; ligne abîmée à l'enregistrement et à la relecture, texte gardé).
- Pour les joueurs : si Tensho ne peut pas écrire sa note GitHub (disque plein, fichier verrouillé), l'échange des découvertes s'arrête et le dit sur la page Découvertes, au lieu de risquer un second gist ; une ligne de découverte abîmée est mise de côté au lieu d'être écrasée.
- Tests : MetaUnsaved1825Tests. Verify.ps1 (agent) : 4013/4013, 0 avertissement, 0 erreur ; DLL 0.1825.0.0. Rien à essayer en jeu.
### English
- Shared discoveries, data safety: a failed write of github.json (the gist in use and the issue, since X-804) because of a full disk, a locked file or missing rights was swallowed without a trace, and the next exchange could make a new gist and issue and leave the old gist, with its places and days, never deleted. SaveMeta now returns true or false and the failure is said once in the log (then « written again » when a write succeeds); at the gist and issue steps (after the gist is made, after the issue, after a merge is confirmed, after the send) a failure stops the exchange with the message « ExchangeMetaUnsaved » on the Discoveries page: no issue is opened, the gist already made is noted in the rotation's state (X-819) and written again at the next exchange, never a second one. After a failure, the next exchange writes github.json again before any send, or nothing is made nor written on GitHub. No write beforehand when the last one held: this client's copy would hide a sign-in renewed by another client of the same profile (GitHubToken1171's case). Discoveries database: a row that cannot be read, met by a save (facts seen since the last one) or by the read-back of a gist copy, was taken as missing and written over without a word; its text is now copied into facts_aside (kept, never erased), the key settled when the row is written again with this client's whole fact, and it is said in the log (the plugin gives the database its log). Behaviour tests MetaUnsaved1825Tests (github.json blocked by a folder against a fake GitHub: stopped at the gist, no issue, nothing after, said once, then the same gist written again; github.json lost right after the gist; a damaged row met by a save and by a read-back, its text kept).
- For players: If Tensho cannot write its GitHub notes file (full disk, locked file), the discoveries exchange now stops and says so on the Discoveries page, instead of risking a second gist; a damaged discovery row is kept aside instead of being overwritten.

## 0.1824.0
- Plan global, X-823 : Relecture de 0.1823 (I1), sécurité de la base partagée : la fusion automatique des comptes de confiance (tools/discoveries-trust.py) ne lisait que le nom de la branche, si bien qu'une demande de fusion venue d'un fork, nommée travailleur/discoveries-N, passait, et l'ensemble commun qu'elle apportait n'était contrôlé que par ses chemins. Désormais : la demande doit venir d'une branche du dépôt lui-même (isCrossRepository faux, dépôt de tête Shigu330/Tensho-Assistant), ouverte par le compte du travailleur (celui du propriétaire) ; les auteurs des commits ne sont pas lus (GitHub les déduit d'une adresse que n'importe qui peut écrire). Le contenu est vérifié par valeur : un sync de ce seul partage est rejoué hors ligne (union et rebuild de tools/discoveries-merge.py) sur les fichiers de Devloppement lus à un commit fixé, avec le gist lu à l'instant, et chaque fichier players/ et v3/ de la demande doit contenir ce que ce rejeu écrit (fichiers gzip comparés décompressés, index.json sans ses tailles et empreintes, qui doivent nommer les fichiers de la demande elle-même), sans fichier de plus ni de moins. Tout écart, ou un rejeu qui s'arrête : doute, pas de fusion. Auto-test de l'outil : 63 cas, dont un essai de bout en bout contre un faux GitHub (fork, autre auteur, fichier hors champ, ensemble commun ou fichier du joueur changé par valeur, fichier en plus ou en moins, index qui nomme d'autres octets : jamais fusionné ; même texte compressé autrement : fusionné). Essai à blanc réel sur la PR 54 : doute « pr-files », juste. README de tools et de community-discoveries mis à jour.
- Tests : DiscoveryOrigin1824Tests. Verify.ps1 (agent) : 4008/4008, 0 avertissement, 0 erreur ; DLL 0.1824.0.0. Rien à essayer en jeu.
### English
- Review of 0.1823 (I1), security of the shared set: the trusted accounts' automatic merge (tools/discoveries-trust.py) read only the branch's name, so a pull request from a fork named travailleur/discoveries-N passed, and the common set it brought was checked by its paths only. Now the pull request must come from a branch of the repository itself (isCrossRepository false, head repository Shigu330/Tensho-Assistant), opened by the worker's account (the owner's); the commits' authors are not read (GitHub derives them from an address anyone can write). The content is checked by value: a sync of that share alone is replayed offline (union and rebuild of tools/discoveries-merge.py) on Devloppement's files read at a pinned commit, with the gist just read, and every players/ and v3/ file of the pull request must hold what that replay writes (gzip files compared unpacked, index.json without its sizes and hashes, which must name the pull request's own files), no file more nor less. Any difference, or a replay that stops: a doubt, no merge. Tool selftest: 63 cases, including an end-to-end run against a made-up GitHub (a fork, another author, a file out of scope, a common set or player file changed by value, a file more or missing, an index naming other bytes: never merged; the same text packed otherwise: merged). Real dry run on PR 54: « pr-files » doubt, as expected. READMEs of tools and community-discoveries updated.

## 0.1823.0
- Plan global, X-805 : Décision de l'utilisateur du 22/11 (R12.2 et R20.6 complétées) : fusion automatique des découvertes partagées pour les comptes de confiance. Nouvel outil du mainteneur tools/discoveries-trust.py, pour le travailleur du portable : la liste des comptes de confiance est un fichier texte hors du dépôt (~/.tensho/trusted-accounts.txt, un identifiant GitHub par ligne, refusée dans le dépôt ; « init » la crée avec le compte du propriétaire du dépôt, sans jamais la réécrire). « merge N » fusionne la demande travailleur/discoveries-<ticket> seulement si tout passe : la demande (ouverte, base Devloppement, sans conflit, fichiers de ce ticket et de v3/ seulement, liste entière, CI verte), le ticket (partage ouvert, un gist, CC0-1.0, titre, auteur du ticket sur la liste, jamais celui de la demande, gist de cet auteur, pas de partage plus récent), le gist lu maintenant (au plus 5 % refusés, sortes connues, volume plausible), le fichier du joueur de la demande (ce ticket, cet identifiant, cette révision du gist notée ; aucun fait perdu, aucun venu d'ailleurs, du neuf). Fusion en squash épinglée sur le commit vérifié, « merged automatically » dans son titre, ticket commenté en anglais puis en français. Au moindre doute : pas de fusion, la demande commentée une fois avec la raison, ligne « TELL THE MAINTAINER ». Compte hors liste : rien ne change. Auto-test de l'outil (décision sur des cas inventés).
- Tests : DiscoveryTrust1823Tests. Verify.ps1 (agent) : 4006/4006, 0 avertissement, 0 erreur ; DLL 0.1823.0.0. Rien à essayer en jeu.
### English
- User decision of 22/11 (R12.2 and R20.6 completed): automatic merge of shared discoveries for trusted accounts. New maintainer tool tools/discoveries-trust.py, for the laptop worker: the list of trusted accounts is a text file outside the repository (~/.tensho/trusted-accounts.txt, one GitHub login per line, refused inside the repository; « init » creates it with the repository owner's account, never writing over it). « merge N » merges the pull request travailleur/discoveries-<issue> only when everything passes: the pull request (open, base Devloppement, no conflict, files of that ticket and of v3/ only, whole list, CI green), the ticket (open share, one gist, CC0-1.0, title, the ticket's author on the list, never the pull request's, gist owned by that author, no newer share), the gist read now (at most 5 % refused, known kinds, plausible volume), the pull request's player file (that ticket, login and gist revision noted; no fact lost, none from elsewhere, something new). Squash merge pinned on the checked commit, « merged automatically » in its title, the ticket commented in English then French. Any doubt: no merge, the pull request commented once with the reason, a « TELL THE MAINTAINER » line. An account not on the list: nothing changes. Tool selftest (decision on made-up cases).
