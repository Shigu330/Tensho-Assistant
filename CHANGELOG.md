## 0.1742.0
- Plan global, X-751 : Outil (X-751, idée I-049 choisie par l'utilisateur le 21/11) : le verrou juste prouvé par mutation. Mutation essayée hors version : FairFileLock rendu injuste (le chemin rapide ne regarde plus les marques d'attente, un client se sert toujours) : la classe FairLock1309Tests échouait (2 cas sur 7), mais le cas des deux magasins de la banque passait quand même (le magasin pressé laisse des trous entre ses enregistrements et le magasin qui attend attend 10 s). Ce cas compte maintenant les enregistrements du magasin pressé pendant chaque attente de l'autre : verrou juste, 1 à chaque fois (4 passages) ; verrou injuste, jusqu'à 8, 20 ou 100 ; règle : jamais plus de 3. Avec la mutation, la classe échoue à chaque passage (4 sur 4), ce cas 3 fois sur 4 ; sans elle, 7/7 sur 4 passages, et 6/6 sous charge. Durée inchangée (environ 1,5 s). Un test existant modifié (raison écrite).
- Tests : FairLock1309Tests. Verify.ps1 (agent) : 3722/3722, 0 avertissement, 0 erreur ; DLL 0.1742.0.0. Rien à essayer en jeu.
### English
- Tool (X-751, idea I-049 chosen by the user on 21/11): the fair lock proven by mutation. Mutation tried outside the version: FairFileLock made unfair (the quick path no longer looks at the waiting marks, a client always serves itself): the FairLock1309Tests class failed (2 cases of 7), but the two bank stores' case still passed (the busy store leaves gaps between its saves and the waiting store waits 10 s). That case now counts the busy store's saves during each wait of the other: fair lock, 1 each time (4 runs); unfair lock, up to 8, 20 or 100; rule: never more than 3. With the mutation the class fails at every run (4 of 4), that case 3 times of 4; without it, 7/7 over 4 runs, and 6/6 under load. Same duration (about 1.5 s). One existing test changed (reason written).

## 0.1741.0
- Plan global, X-685 : Mémoire après les rechargements (X-685, partie 1). Cause trouvée en partie : chaque copie déchargée de Tensho restait dans le processus du jeu (journal : « context alive, 0 of N parts alive » pour chaque copie d'avant ; mémoire gérée 295 Mo au premier chargement du jeu, 1 439 Mo au 97e). Essai hors du jeu (contexte déchargeable, comme Dalamud) : System.Text.Json, partagé par tout le processus, garde pour de bon les types d'une copie qui a utilisé ses options par défaut ou des options égales à celles d'un autre ; avec un résolveur à elle, la copie est libérée. TenshoJson (nouveau) : toutes les options de Tensho ont leur propre résolveur (Own), Plain remplace les options par défaut ; 41 appels et 18 options changés (script x685-json.py), sondes de tools/ liées. JsonUnload1741Tests (3 : comportement en contexte déchargeable avec témoin, résolveur jamais partagé, cliquet sur tous les appels). Reste : Newtonsoft.Json (réglages enregistrés par Dalamud) garde aussi la copie ; partie suivante. Preuve docs/evidence/0.1741-unload-json.md.
- Tests : JsonUnload1741Tests. Verify.ps1 (agent) : 3722/3722, 0 avertissement, 0 erreur ; DLL 0.1741.0.0. Rien à essayer en jeu.
### English
- Memory after reloads (X-685, part 1). Cause found in part: every unloaded copy of Tensho stayed in the game process (log: « context alive, 0 of N parts alive » for every earlier copy; managed memory 295 MB at the game's first load, 1439 MB at the 97th). Tried out of the game (a context that can unload, as Dalamud's): System.Text.Json, shared by the whole process, keeps for good the types of a copy that used its default options or options equal to someone else's; with a resolver of its own, the copy is collected. TenshoJson (new): every options of Tensho has its own resolver (Own), Plain replaces the default options; 41 calls and 18 options changed (script x685-json.py), tools/ probes linked. JsonUnload1741Tests (3: behaviour in a context that can unload with a control, resolver never shared, ratchet on every call). Left: Newtonsoft.Json (settings saved by Dalamud) keeps the copy too; next part. Evidence docs/evidence/0.1741-unload-json.md.

## 0.1740.0
- Plan global, X-757 : Constats mineurs de la relecture 0.1738 (X-757 ; M1 écrit en 0.1739). M2 : page Marchands, la ligne « Marchands sans position : N » compte les marchands (PNJ distincts, comme l'en-tête de la page), plus leurs offres : un PNJ de deux boutiques compte une fois. M3 : fenêtre de chat effacée (« S'effacer après ») : la remise du chat sur son historique (toutes les lignes renumérotées) ne la fait plus revenir ; le plus récent de l'onglet et le dernier message regardé sont repris des données, aucun n'est neuf (comme les conversations), et les vieux messages privés remis ne la réveillent plus ; un vrai nouveau message la fait toujours revenir. M4 : la ligne du mode développeur d'un retour dit aussi l'onglet, le numéro de son plus récent message et l'alpha avant et après (la sonde de la définition de X-732). ReviewMinors1740Tests (3, dont le comportement de la remise sur l'historique).
- Pour les joueurs : fenêtre de chat : une fenêtre effacée ne revient plus quand les anciens messages sont remis après un rechargement. Marchands : les marchands sans position sont comptés une fois chacun.
- Tests : ReviewMinors1740Tests. Verify.ps1 (agent) : 3719/3719, 0 avertissement, 0 erreur ; DLL 0.1740.0.0. Non validé en jeu.
### English
- Minor findings of the review of 0.1738 (X-757; M1 written in 0.1739). M2: Vendors page, the row « Vendors without a position: N » counts the vendors (distinct NPCs, as the page's header), no longer their offers: an NPC of two shops counts once. M3: faded chat window (« Fade after »): the chat put back on its history (every line numbered again) no longer brings it back; the tab's newest and the last message looked at are taken again from the data, none is new (as the conversations), and the old tells put back no longer wake it; a real new message still brings it back. M4: the developer-mode line of a comeback also says the tab, its newest message's number and the alpha before and after (the probe of X-732's definition). ReviewMinors1740Tests (3, the restore's behaviour among them).
- For players: Chat window: a faded window no longer comes back when the old messages are put back after a reload. Vendors: the vendors without a position are counted once each.

## 0.1739.0
- Plan global, X-756 : Info-bulle d'un repas dans la fenêtre de chat (X-756, constat I1 de la relecture 0.1738 ; X-757 M1). Le Param du statut Repu ou Médicamenté n'est plus pris à la première image où le statut en porte un : la valeur portée à l'arrivée de la ligne est gardée et les 30 images suivantes sont suivies ; une valeur différente est celle de la ligne (repas B pris alors qu'on est Repu d'un repas A, ligne écrite avant le statut), une valeur restée la même pendant tout le suivi aussi (statut posé avant la ligne, ou même repas) ; jamais l'ancien repas. Seules les lignes « bénéficie de l'effet » (genre 46, LogFilter) lisent le statut ; une ligne « perd l'effet » (genre 48) garde la description (le journal du 21/11 à 17 h 29 montrait une lecture sur une ligne de fin d'effet). ChatStatusWatch (pur). M1 (D-205) : la lecture du statut d'un autre joueur à portée est gardée, écrite dans PUBLISHING (règle 5) et dans la preuve docs/evidence/0.1739-meal-status-gained.md. Un test de câblage de 0.1734 modifié (un argument de plus).
- Pour les joueurs : fenêtre de chat : l'info-bulle d'un repas montre le repas qu'on vient de prendre, jamais un plus ancien encore actif.
- Tests : MealStatus1739Tests. Verify.ps1 (agent) : 3716/3716, 0 avertissement, 0 erreur ; DLL 0.1739.0.0. Non validé en jeu.
### English
- Meal tooltip in the chat window (X-756, finding I1 of the review of 0.1738; X-757 M1). The Param of the Well Fed or Medicated status is no longer taken at the first frame where the status holds one: the value held when the line arrives is kept and the next 30 frames are watched; a different value is the line's (meal B eaten while Well Fed from meal A, line printed before the status), a value that stays the same for the whole watch is too (status put on before the line, or the same meal); never the older meal. Only the lines « gains the effect » (kind 46, LogFilter) read the status; a line « loses the effect » (kind 48) keeps the description (the log of 21/11 at 17:29 showed a read on an effect-lost line). ChatStatusWatch (pure). M1 (D-205): reading the status of another player in range is kept, written in PUBLISHING (rule 5) and in the evidence docs/evidence/0.1739-meal-status-gained.md. One wiring test of 0.1734 changed (one more argument).
- For players: Chat window: a meal's tooltip shows the meal just eaten, never an older one still active.

## 0.1738.0
- Plan global, X-748 : Page Marchands, marchands sans position (X-748, idée I-022 choisie par l'utilisateur le 21/11 vers 16 h, après l'essai T-0.1374-1 du 17/11 : une vingtaine de lignes « Marchand · Position non renseignée » pour un objet). - Tests : VendorRows1738Tests. Verify.ps1 (agent) : 3712/3712, 0 avertissement, 0 erreur ; DLL 0.1738.0.0. Non validé en jeu.
### English
- Vendors page, vendors without a position (X-748, idea I-022 chosen by the user on 21/11 around 16:00, after test T-0.1374-1 of 17/11: about twenty rows « Vendor · Position not available » for one item). An item's vendors that stand on a map come first, in their order; those the game puts on no map (to place at home, no longer reachable) are grouped in one row « Vendors without a position: N », hidden by default, that a click unfolds or folds (for the session); its tooltip says what they are. The places come from the game's sheets, as before. Texts in en and fr.
