## 0.1923.0
- Plan global, X-900 : Lanceur de tests, faux « disque plein » (X-900). Pendant la release de 0.1919, la sortie d'erreur des tests disait « TRACE stopped: IOException (There is not enough space on the disk.) » alors que le disque C avait plus de 770 Go libres. Cause, prouvée : aucune trace n'était écrite (Verify.ps1 ne pose pas TENSHO_TEST_TRACE) ; la ligne venait du cas de comportement de TestTrace1913Tests, dont le flux simule un disque plein, et la trace disait son arrêt sur la vraie sortie d'erreur du lanceur, à chaque passe complète (artifacts/tests-errors.txt de Verify, seule ligne du fichier). La trace dit maintenant son arrêt à l'écrivain qu'on lui donne (la sortie d'erreur par défaut) ; le cas de TestTrace1913Tests donne le sien et vérifie que l'arrêt y est dit une fois. Passe complète avec TENSHO_TEST_TRACE posée : 4256 tests verts, sortie d'erreur vide, la trace va au bout (autant de fins que de débuts). Nouveau TestTrace1923Tests (2 cas : l'arrêt dit à l'écrivain donné ; cliquet : toute trace d'un test sur son propre flux reçoit un écrivain). Rien ne change pour les joueurs.
- Tests : TestTrace1923Tests. Verify.ps1 (agent) : 4256/4256, 0 avertissement, 0 erreur ; DLL 0.1923.0.0. Rien à essayer en jeu.
### English
- Test runner, false « disk full » (X-900). During the 0.1919 release, the tests' error output said « TRACE stopped: IOException (There is not enough space on the disk.) » while drive C had more than 770 GB free. Cause, proven: no trace was written (Verify.ps1 does not set TENSHO_TEST_TRACE); the line came from the behaviour case of TestTrace1913Tests, whose stream simulates a full disk, and the trace said its stop on the runner's real error output, in every full run (artifacts/tests-errors.txt of Verify, the file's only line). The trace now says its stop to the writer it is given (the error output by default); the TestTrace1913Tests case gives its own and checks the stop is said there once. Full run with TENSHO_TEST_TRACE set: 4256 tests green, error output empty, the trace reaches the end (as many ends as starts). New TestTrace1923Tests (2 cases: the stop said to the given writer; ratchet: every trace a test builds on its own stream gets a writer). Nothing changes for players.

## 0.1922.0

- Tests : EventListenerGate1916Tests. Verify.ps1 (agent) : 4254/4254, 0 avertissement, 0 erreur ; DLL 0.1922.0.0. Rien à essayer en jeu.
### English
- Tests of the runtime listeners' gate (review of 0.1921): the samples' case of X-896 (primary constructor with parentheses, type parameters, full base name, « class C:global::… » without a space, EventSource and IEventListener left out) now goes through the pattern the ratchet really uses (Declared, through Listeners), one sample per file then all together; the former direct pattern, which nothing used any more, is removed (M1). Forms no source writes (a base named through a using alias, a primary constructor with two levels of parentheses, an attribute with typeof) are not added to the pattern: they are listed in « Not covered, on purpose » with their reason, as for the raw newlines' ratchet (M2).

## 0.1919.0
- Plan global, X-897 : Mode développeur et outil de tests (relecture 0.1916, M2, déjà là avant le bloc) : le verrou des écouteurs des événements du runtime (X-891) était un champ statique de l'assembly du plugin, donc un par chargement (chaque rechargement de Dalamud ouvre un nouveau contexte de chargement) : un écouteur de l'ancien chargement fermé en retard et un écouteur créé par le nouveau prenaient deux verrous différents, et l'interblocage de X-891 restait possible à un rechargement, figeant le jeu. Le verrou est désormais un seul objet pour tout le processus, rangé dans les données du processus (AppDomain.SetData), partagé par chaque chargement du plugin et par l'application de bureau ; un simple object, qui ne retient aucun ancien contexte de chargement. L'écouteur des compilations du chat, nommé 2 s après la première image, a maintenant un propriétaire (la fenêtre) : sa fermeture le libère tout de suite au déchargement et le travail différé ne fait alors plus rien. Tests de comportement RuntimeGate1919Tests : un second chargement du même code dans son propre contexte reçoit le même verrou (échoue sur l'ancien code) ; des écouteurs des deux chargements créés et fermés par 6 fils à la fois finissent tous (sur l'ancien code, le processus de tests s'est figé, 0 % de processeur, arrêté à la main) ; la libération unique sous concurrence.
- Tests : RuntimeGate1919Tests. Verify.ps1 (agent) : 4253/4253, 0 avertissement, 0 erreur ; DLL 0.1919.0.0. Rien à essayer en jeu.
### English
- Developer mode and test tool (review of 0.1916, M2, already there before the block): the gate of the runtime's event listeners (X-891) was a static field of the plugin's assembly, so one per load (each Dalamud reload opens a new load context): a listener of the old load disposed late and one made by the new load took two different gates, and X-891's deadlock stayed possible at a reload, freezing the game. The gate is now one object for the whole process, kept in the process's data (AppDomain.SetData), shared by every load of the plugin and by the desktop app; a plain object, which keeps no old load context alive. The chat's compilation listener, named 2 s after the first frame, now has an owner (the window): its Dispose lets it go at once at an unload, and the later work then does nothing. Behaviour tests RuntimeGate1919Tests: a second load of the same code in its own context gets the same gate (fails on the old code); listeners of both loads made and disposed by 6 threads at once all end (on the old code, the test process froze, 0 % processor, stopped by hand); the single release under a race.
