## 0.1772.0
- Plan global, X-747 : Sonnettes posées dans la maison sur la carte (X-747, idée I-019 de l'utilisateur) : sonde d'abord (R06). Les structures du jeu (FFXIVClientStructs, tools/ApiProbe) donnent, dans une maison, les meubles posés et leur position (HousingManager.IndoorTerritory → FurnitureManager.FurnitureVector : Id, Position, Rotation) ; ce qu'est l'Id, et si une sonnette posée est un objet d'événement, ne s'établit qu'en jeu. Nouvelle sonde, mode développeur seulement, lecture seule : toutes les cinq secondes dans une maison, le journal dit (quand cela change) le nombre de meubles, chaque Id avec son nombre, et les objets d'événement avec leur ligne, leur nom du jeu et leur position ; aucun nom de joueur lu ; arrêt propre sur un échec. Rien n'est montré sur la carte avant le relevé de l'utilisateur dans sa maison (essai). Preuve 0.1772 (deux moitiés). Le point reste ouvert.
- Tests : HousingProbe1772Tests. Verify.ps1 (agent) : 3839/3839, 0 avertissement, 0 erreur ; DLL 0.1772.0.0. Non validé en jeu.
### English
- Summoning bells placed in the house on the map (X-747, the user's idea I-019): a probe first (R06). The game's structures (FFXIVClientStructs, tools/ApiProbe) give, inside a house, the furniture placed and its position (HousingManager.IndoorTerritory → FurnitureManager.FurnitureVector: Id, Position, Rotation); what the Id is, and whether a placed bell is an event object, can only be settled in game. New probe, developer mode only, read only: every five seconds inside a house, the log says (when it changes) the number of pieces, each Id with its count, and the event objects with their row, the game's name and position; no player's name read; a clean stop on a failure. Nothing is shown on the map before the user's reading in the house (test). Evidence 0.1772 (both halves). The point stays open.

## 0.1769.0
- Plan global, X-770 : Constats mineurs de la relecture 0.1768 (X-770). M1 corrigé : le compte d'une Grâce que le jeu a retirée (plafond atteint, effet retiré à la main, 18 h écoulées) restait pour toujours dans les réglages ; un manuel du même genre utilisé plus tard, lu avec un temps restant pas plus grand que l'ancien et sans expérience gagnée entre-temps, reprenait l'ancien compte (près de 0) au lieu d'« inconnu » (R06). Désormais un compte dont le statut n'est vu à aucune de 30 lectures de suite pendant que vous êtes chargé (environ une demi-minute) est effacé, et le journal le dit ; un statut manqué quelques lectures (après un chargement ou un écran de chargement) garde son compte ; ce compte de lectures n'est pas enregistré (format des réglages inchangé) ; rien n'est lu dans un contenu compétitif (Tensho coupé, R03.2). Le cas qui reste (ancien manuel retiré et nouveau utilisé pendant que Tensho était éteint, sans expérience gagnée) est écrit dans la preuve 0.1231 : le jeu ne donne rien pour les distinguer. M2 corrigé : avec une famille choisie dans l'onglet « Objets temporaires », les aliments dont les familles n'ont pas été lues dans leur description (client allemand ou japonais surtout) disparaissaient sans le dire, et la famille montrait « Aliments (0) » ; ils restent maintenant dans la liste, marqués « Familles non lues », et une ligne dit combien ; l'aide du filtre le dit, en deux langues. Tests de comportement : le cas de la relecture (29 lectures gardent le compte, la 30e l'efface, le manuel suivant est inconnu), un statut manqué puis revu, compte de lectures absent du texte des réglages ; aliments non lus gardés dans chaque famille, jamais ceux d'une autre famille, client dont aucun crochet n'est lu.
- Pour les joueurs : les points de bonus restants d'un manuel sont oubliés quand le jeu retire son effet : un manuel suivant ne reprend jamais l'ancien compte ; la liste des aliments du Dédale bestial garde, marqués, les aliments dont les familles n'ont pas pu être lues.
- Tests : Grace1769Tests. Verify.ps1 (agent) : 3829/3829, 0 avertissement, 0 erreur ; DLL 0.1769.0.0. Non validé en jeu.
### English
- Minor findings of the 0.1768 review (X-770). M1 fixed: the count of a Grace the game took away (cap reached, effect removed by hand, 18 hours ended) stayed in the settings for good; a manual of the same kind used later, read with no more time left than the old one and no experience gained in between, went on with the old count (close to 0) instead of « unknown » (R06). Now a count whose status is seen at none of 30 readings in a row while you are loaded (about half a minute) is dropped, and the log says so; a status missed for a few readings (after a load or a loading screen) keeps its count; that count of readings is not saved (the settings' format is unchanged); nothing is read in a competitive content (Tensho cut, R03.2). The case left (an old manual removed and a new one used while Tensho was off, with no experience gained) is written in evidence 0.1231: the game gives nothing to tell them apart. M2 fixed: with a family chosen in the « Ephemeral items » tab, the feeds whose families were not read in their description (a German or Japanese client above all) left the list without a word, and the family showed « Feed (0) »; they now stay in the list, marked « Families not read », and a line says how many; the filter's help says so, in both languages. Behaviour tests: the review's case (29 readings keep the count, the 30th drops it, the next manual is unknown), a status missed then seen again, the count of readings absent from the settings' text; unread feeds kept in each family, never another family's, a client whose brackets are never read.
- For players: A manual's bonus points left are forgotten once the game ends its effect, so a later manual never takes up the old count; the Crucible's feed list keeps, marked, the feeds whose families could not be read.

- Plan global, X-744 : Dédale bestial, objets et cases du plateau (X-744, idée I-026 de l'utilisateur, première partie ; le point reste ouvert). Ce que le jeu explique lui-même d'abord (R06) : son guide du Dédale (DescriptionString 1700 à 1755) dit la règle de chaque case et de chaque genre d'objet.
