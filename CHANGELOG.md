## 0.1511.0
- Plan global, X-539 : Rien de Tensho avant la connexion d'un personnage (X-539, capture de l'écran titre par l'utilisateur, 17/11). Sur l'écran titre et la sélection du personnage, Tensho dessinait déjà ses fenêtres (« Suivi Tensho », la fenêtre de chat Tensho). Les fenêtres et les panneaux de Tensho attendent maintenant qu'un personnage soit connecté et chargé (UI.CharacterGate : connexion et joueur chargé) ; leur état ouvert ou fermé n'est jamais touché : après la connexion, les fenêtres de la dernière session reviennent telles quelles ; à la déconnexion (retour à l'écran titre), elles disparaissent sans perdre cet état. La commande /tensho sans personnage dit en une ligne qu'il faut d'abord se connecter avec un personnage. La coupure du contenu classé garde sa place, en premier.
- Pour les joueurs : tensho n'affiche plus ses fenêtres sur l'écran titre et la sélection du personnage : elles reviennent comme vous les aviez laissées une fois votre personnage connecté.
- Tests : CharacterGate1511Tests. Verify.ps1 (agent) : 3007/3007, 0 avertissement, 0 erreur ; DLL 0.1511.0.0. Non validé en jeu.
### English
- Nothing of Tensho before a character is logged in (X-539, user capture of the title screen, 17/11). On the title screen and the character selection, Tensho already drew its windows (« Suivi Tensho », the Tensho chat window). Tensho's windows and panels now wait until a character is logged in and loaded (UI.CharacterGate: login and player loaded); their open or closed state is never touched: after the login, the last session's windows come back as they were; at the logout (back to the title screen), they leave without losing that state. The /tensho command without a character says in one line to log in with a character first. The competitive cut keeps its place, first.
- For players: Tensho no longer shows its windows on the title screen and the character selection: they come back as you left them once your character is logged in.

## 0.1510.0
- Plan global, X-534 : Relecture de 0.1505 à 0.1507, mineurs (X-534). M1 : la place des messages du chat du jeu n'était lue que pendant qu'ils étaient cachés ; quand une fenêtre du jeu qui couvrait la fenêtre de chat Tensho (« Se cacher ») se fermait, ou à la fin d'un combat avec « Masquer en combat », la fenêtre Tensho était dessinée une image à la place du joueur avant de reprendre celle des messages (clignement), et si cette place-là était couverte par une autre fenêtre du jeu, elle se jugeait couverte et les messages du jeu restaient affichés. La place est maintenant lue à chaque image où le chat du jeu est affiché, aussi pendant que les messages sont rendus (ChatHideWants.ReadsPlace) ; la fenêtre ne s'en sert que pendant qu'ils sont cachés. M2 : le contrat de ChatHideWants.Of disait « contenu classé : toujours rendus » alors que le cacheur tient (Hold) tant que la fenêtre du chat du jeu n'est pas affichée ; une seule règle par image, ChatHideWants.InFrame (chat du jeu non affiché : tenu ; sinon contenu classé : rendus ; sinon le souhait), appliquée par le cacheur ; le contrat de Of le dit.
- Pour les joueurs : le chat Tensho ne clignote plus ailleurs quand une fenêtre du jeu posée dessus se ferme, pendant que les messages du chat du jeu sont cachés.
- Tests : ChatGameResume1510Tests. Verify.ps1 (agent) : 3005/3005, 0 avertissement, 0 erreur ; DLL 0.1510.0.0. Non validé en jeu.
### English
- Review of 0.1505 to 0.1507, minor findings (X-534). M1: the place of the game chat's messages was read only while they were hidden; when a game window covering Tensho's chat window (« Hide ») closed, or at the end of a fight with « Hide in combat », Tensho's window was drawn one frame at the player's own place before taking the messages' place again (a blink), and if that place was covered by another game window it judged itself covered and the game's messages stayed shown. The place is now read in every frame the game's chat is shown, also while the messages are given back (ChatHideWants.ReadsPlace); the window uses it only while they are hidden. M2: ChatHideWants.Of's contract said « competitive content: always given back » while the hider holds (Hold) as long as the game's chat window is not shown; one rule per frame now, ChatHideWants.InFrame (game chat not shown: held; else competitive content: given back; else the wish), applied by the hider; Of's contract says so.
- For players: The Tensho chat no longer blinks elsewhere when a game window over it closes, while the game chat's messages are hidden.

## 0.1508.0
- Plan global, X-533 : Chat : avec « Cacher les messages du chat du jeu », la barre d'onglets du chat du jeu restait visible, le nom du canal (« Dire ») était coupé par le bas de la fenêtre Tensho, et le menu des canaux de la saisie, qui s'ouvre vers le haut, passait derrière elle (X-533, demande de l'utilisateur du 16/11). La barre d'onglets du jeu (onglets, « ajouter un onglet », ses deux bouts, le bouton des réglages) est maintenant cachée avec les messages et rendue avec eux (tenue pendant une scène cinématique, rendue en JcJ, au déchargement et sur une erreur) ; la fenêtre ChatLog, sa zone de saisie, son menu des canaux et le nom du canal ne sont jamais cachés. La fenêtre Tensho prend le cadre des messages et des onglets : depuis le haut de ChatLog quand les onglets sont dessinés au-dessus du panneau, jusqu'au plus haut de la zone de saisie ou du nom du canal (ChatFollow.Box). Tant que le menu des canaux est ouvert, la fenêtre Tensho n'est pas dessinée (les messages du jeu restent cachés : rien ne clignote) ; elle revient quand il se ferme (ChatFollow.StepsAside). Le menu est lu ouvert par le menu déroulant ouvert de ChatLog (CurrentDropDownOwnerNode) ou sa liste affichée ; en mode développeur, le journal dit lequel à chaque changement, et la place de la fenêtre. DEC-053 changée (deux moitiés) ; info-bulle de l'option ; preuve docs/evidence/0.1508-game-chat-channel-menu.md.
- Pour les joueurs : avec « Cacher les messages du chat du jeu », les onglets du chat du jeu sont cachés aussi, le chat Tensho ne couvre plus le nom du canal et s'efface pendant que vous choisissez un canal.
- Tests : ChatGameTabs1508Tests. Verify.ps1 (agent) : 3003/3003, 0 avertissement, 0 erreur ; DLL 0.1508.0.0. Non validé en jeu.
### English
- Chat: with « Hide the game chat's messages », the game chat's tab bar stayed visible, the channel's name (« Say ») was cut by the bottom of Tensho's window, and the typing box's channel menu, which opens upward, went behind it (X-533, the user's request of 16/11). The game's tab bar (tabs, « add a tab », both ends, the settings button) is now hidden with the messages and given back with them (held during a cutscene, given back in PvP, on unload and on an error); the ChatLog window, its typing box, its channel menu and the channel's name are never hidden. Tensho's window takes the frame of the messages and tabs: from ChatLog's top when the tabs are drawn above the panel, down to the highest of the typing box or the channel's name (ChatFollow.Box). While the channel menu is open, Tensho's window is not drawn (the game's messages stay hidden: nothing blinks); it comes back when the menu closes (ChatFollow.StepsAside). The menu is read open from ChatLog's open drop-down (CurrentDropDownOwnerNode) or its list shown; in developer mode the log says which on each change, and the window's place. DEC-053 changed (both halves); the option's tooltip; evidence docs/evidence/0.1508-game-chat-channel-menu.md.
- For players: With « Hide the game chat's messages », the game's chat tabs are hidden too, the Tensho chat no longer covers the channel's name, and it steps aside while you pick a channel.

## 0.1507.0
- Plan global, X-528 : Relecture de 0.1504, mineurs (X-528). M1 : une fenêtre du jeu couvre la fenêtre de chat Tensho réglée sur « Se cacher » : les messages du jeu reviennent (dessinés par le jeu sous sa fenêtre, la partie non couverte reste lisible), puis se cachent de nouveau quand elle part. M2 : seuls les panneaux sous la fenêtre Tensho sont cachés (le panneau 0 et les onglets ancrés à sa place) ; un onglet détaché ailleurs sur l'écran reste affiché (ChatFollow.Under). M3 : l'info-bulle de l'option et DEC-053 (deux moitiés) donnent tous les cas (combat avec « Masquer en combat », fenêtre du jeu par-dessus, scène cinématique, GPose, interface cachée, application de bureau, onglet détaché). M4 : l'état « réduite » est effacé quand la fenêtre prend la place des messages du jeu.
- Pour les joueurs : les messages cachés du chat du jeu reviennent sous une fenêtre du jeu qui couvre le chat Tensho, et un onglet du chat détaché ailleurs n'est plus caché.
- Tests : ChatGameHideMinor1507Tests. Verify.ps1 (agent) : 2999/2999, 0 avertissement, 0 erreur ; DLL 0.1507.0.0. Non validé en jeu.
### English
- Review of 0.1504, minor findings (X-528). M1: a game window covers Tensho's chat window set to « Hide »: the game's messages come back (drawn by the game under its window, the uncovered part stays readable), then are hidden again once it goes. M2: only the panels under Tensho's window are hidden (panel 0 and the tabs docked at its place); a tab detached elsewhere on the screen stays shown (ChatFollow.Under). The other half of M2 (a panel the game hid itself, shown again) is set aside: the game hides its panels with its interface or its chat, where Tensho holds since 0.1506. M3: the option's tooltip and DEC-053 (both halves) list every case (combat with « Hide in combat », a game window over it, cutscene, GPose, interface hidden, desktop app, detached tab). M4: the « reduced » state is cleared when the window takes the place of the game's messages.
- For players: Hidden game chat messages come back under a game window that covers the Tensho chat, and a chat tab detached elsewhere is no longer hidden.
