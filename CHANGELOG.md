# Journal des versions / Changelog

Résumé par version, en français puis `### English` (partie anglaise obligatoire depuis 0.219.0) ; la partie anglaise sert aussi de corps
aux commits et aux notes de release sur GitHub. Preuves citées : docs/evidence/.
Chaque version a été compilée et testée par `scripts/Verify.ps1` ; la validation en jeu est indiquée quand l'utilisateur l'a rapportée.
Ce fichier garde la dernière release et les versions qui suivent ; les plus anciennes sont dans [docs/changelog/](docs/changelog/)
(déplacées par `tools/changelog.py archive`, un fichier par centaine de versions).

## 0.1328.0
- Plan global, X-334 : Tests (relecture 0.1318, I6, R28.14) : l'aller-retour « enregistrer puis relire » de la configuration passe désormais par le même sérialiseur que le plugin (Newtonsoft, TypeNameHandling.Objects, réglages de Plugin.cs), au lieu de la réflexion ou de System.Text.Json. Un fichier d'avant le renommage (GearExactOutsideCaps) garde le choix du joueur (coupé, allumé, ou par défaut), seul le nouveau nom est réécrit, et le choix tient après deux sauvegardes ; une alarme déplacée sur place est relue telle quelle (même alarme, nouvelle heure, rien de perdu). Le projet de tests référence Newtonsoft.Json 13.0.4, la version que Dalamud fournit.
- Tests : ConfigRoundTrip1328Tests. Verify.ps1 (agent) : 2491/2491, 0 avertissement, 0 erreur ; DLL 0.1328.0.0. Rien à essayer en jeu.
### English
- Tests (review of 0.1318, I6, R28.14): the settings' « save then read back » now goes through the plugin's own serializer (Newtonsoft, TypeNameHandling.Objects, Plugin.cs's settings) instead of reflection or System.Text.Json. A file from before the rename (GearExactOutsideCaps) keeps the player's choice (off, on, or default), only the new name is written again, and the choice holds across two saves; an alarm moved in place is read back as it is (same alarm, new time, nothing lost). The test project references Newtonsoft.Json 13.0.4, the version Dalamud ships.

## 0.1326.0
- Plan global, X-331 : Marché, prix vus au tableau du jeu (relecture 0.1318, I2) : une réponse d'Universalis sans envoi pour le monde (personne n'y a relevé cet objet, donc aucune date d'envoi) ne cache plus un vrai relevé du tableau du jeu. La règle « le relevé le plus récent gagne » (X-292) compare désormais le relevé du tableau à la date d'envoi d'Universalis seulement ; avant, l'heure de la requête (« maintenant ») comptait à sa place et gagnait toujours. Les autres mondes et la région d'Universalis restent affichés à côté.
- Pour les joueurs : Un prix vu au tableau du marché du jeu n'est plus caché par une réponse vide d'Universalis pour votre monde.
- Tests : EmptyUniversalis1326Tests. Verify.ps1 (agent) : 2485/2485, 0 avertissement, 0 erreur ; DLL 0.1326.0.0. Non validé en jeu.
### English
- Market, prices seen at the game's board (review of 0.1318, I2): a Universalis answer without an upload for the world (nobody uploaded that item there, so no upload date) no longer hides a real reading of the game's board. The rule « the newest reading wins » (X-292) now compares the board's reading with Universalis' upload date only; before, the request time (« now ») counted instead and always won. Universalis' other worlds and region stay shown beside it.
- For players: A price you saw at the game's market board is no longer hidden by an empty Universalis answer for your world.

## 0.1325.0
- Plan global, X-330 : Découvertes, deux clients du jeu sur un même profil (relecture 0.1318, I1) : un import de fichier et la jonction de la base commune notent désormais la fiche telle qu'elle était, comme une observation, et la sauvegarde ajoute ce changement à la ligne telle qu'elle est enregistrée (« additionner les deux », X-171) au lieu de remplacer la ligne entière. Avant, l'import ou la jonction d'un client effaçait les observations que l'autre avait enregistrées depuis, et une fiche vue par l'autre pouvait redevenir partagée. La copie d'un genre partagé lu plus tard et jointe à une fiche déjà là suit la même règle ; la lecture de la base au démarrage reste une conversion écrite telle quelle (les deux clients font la même, l'additionner compterait deux fois).
- Pour les joueurs : Avec deux clients du jeu ouverts, importer des découvertes ou joindre celles des autres n'efface plus ce que l'autre client a enregistré.
- Tests : TwoClientsImport1325Tests. Verify.ps1 (agent) : 2483/2483, 0 avertissement, 0 erreur ; DLL 0.1325.0.0. Rien à essayer en jeu.
### English
- Discoveries, two game clients on one profile (review of 0.1318, I1): a file import and the common base's join now note the fact as it was, like a sighting, and the save adds that change to the row as saved (« add both », X-171) instead of replacing the whole row. Before, one client's import or join erased the sightings the other had saved since, and a fact seen by the other could become shared again. A shared kind's copy read later and joined to a fact already here follows the same rule; reading the base at start stays a conversion written as is (both clients make the same one, adding it would count twice).
- For players: With two game clients open, importing discoveries or joining the shared ones no longer erases what the other client recorded.

## 0.1324.0
- Plan global, X-340 : Signaler un problème : envoi direct par la connexion GitHub de Tensho (celle des découvertes), sur clic seulement (décision de l'utilisateur du 14/11, R04). Le bouton principal devient « Envoyer sur GitHub… » et montre d'abord le texte exact qui part ; connecté, le joueur choisit « par ma connexion GitHub » ou « par mon navigateur » ; « Envoyer maintenant » crée le ticket (titre préfixé, champs du formulaire sous leurs titres, rapport de diagnostic entier dans un bloc de code) puis donne son numéro et un bouton pour l'ouvrir. Le texte envoyé est exactement celui de l'aperçu ; un champ ou une voie changés ferment l'aperçu. Sans connexion : le formulaire du navigateur comme avant, avec un encadré visible qui dit de coller le rapport (Ctrl+V) quand il ne tient pas dans l'adresse. Une action du dépôt (player-report-labels) pose les étiquettes du formulaire d'après le préfixe du titre, car GitHub ignore celles demandées par un joueur sans droit d'écriture. Aide, FAQ, description du manifeste, PUBLISHING et tableau réseau mis à jour.
- Pour les joueurs : Signaler un problème peut maintenant envoyer votre bug sur GitHub en un clic si GitHub est connecté (Monde › Découvertes), après avoir montré le texte exact ; sinon le formulaire s'ouvre dans le navigateur, avec une étape claire pour coller un long rapport.
- Tests : ProblemSend1324Tests. Verify.ps1 (agent) : 2479/2479, 0 avertissement, 0 erreur ; DLL 0.1324.0.0. Non validé en jeu.
### English
- Report a problem: direct sending through Tensho's GitHub connection (the discoveries' one), on click only (user's decision of 14/11, R04). The main button becomes « Send on GitHub… » and first shows the exact text that leaves; when connected, the player chooses « through my GitHub connection » or « through my browser »; « Send now » creates the issue (prefixed title, the form's fields under their headings, the whole diagnostic report in a code block) then gives its number and a button to open it. The text sent is exactly the preview's; a changed field or way closes the preview. Without a connection: the browser's form as before, with a visible framed step saying to paste the report (Ctrl+V) when it does not fit in the address. A repository workflow (player-report-labels) sets the form's labels from the title prefix, since GitHub ignores labels asked by a player without write access. Help, FAQ, manifest description, PUBLISHING and the network table updated.
- For players: Report a problem can now send your bug straight to GitHub in one click when GitHub is connected (World › Discoveries), after showing the exact text; otherwise the browser form opens, with a clear step to paste a long report.
