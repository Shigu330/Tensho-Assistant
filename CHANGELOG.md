## 0.1614.0
- Plan global, X-666 : Relecture du bloc 0.1607 à 0.1612, constat antérieur M4 : « au plus une fois toutes les 20 heures » ne valait que pour un échange réussi ; un échange des découvertes qui échoue (jeton expiré, refus, réseau) était retenté toutes les 15 minutes, donc une requête vers GitHub toutes les 15 minutes tant qu'il échouait. Désormais l'échange automatique attend 15 minutes après un échec, puis deux fois plus après chaque nouvel échec d'affilée (30 minutes, 1 heure… 20 heures au plus) ; le compte et l'heure du dernier essai sont gardés dans github.json (un redémarrage du jeu ne relance pas aussitôt) ; un échange réussi remet le compte à zéro (GitHubExchange.Wait). Info-bulle du réglage (en, fr) et SECURITY (en, fr) le disent. Moins de requêtes seulement (R04), rien d'autre ne change. X-666.
- Pour les joueurs : découvertes : quand l'échange automatique échoue, il attend de plus en plus longtemps avant de réessayer, au lieu de toutes les 15 minutes.
- Tests : ExchangeBackoff1614Tests. Verify.ps1 (agent) : 3335/3335, 0 avertissement, 0 erreur ; DLL 0.1614.0.0. Rien à essayer en jeu.
### English
- Review of the block 0.1607 to 0.1612, pre-existing finding M4: « at most once every 20 hours » held only for an exchange that ended; a discoveries exchange that failed (expired token, refusal, network) was tried again every 15 minutes, so GitHub was asked every 15 minutes for as long as it failed. Now the automatic exchange waits 15 minutes after a failure, then twice as long after each new failure in a row (30 minutes, 1 hour… 20 hours at most); the count and the last attempt's time are kept in github.json (a restart of the game does not try again at once); an exchange that ends clears the count (GitHubExchange.Wait). The setting's tip (en, fr) and SECURITY (en, fr) say so. Fewer requests only (R04), nothing else changes. X-666.
- For players: Discoveries: when the automatic exchange fails, it waits longer and longer before trying again, instead of every 15 minutes.

## 0.1613.0
- Plan global, X-665 : Relecture du bloc 0.1607 à 0.1612, mineurs. M1 : le test à cliquet de 0.1607 gardait des empreintes SHA-256 sans clé des valeurs privées de l'utilisateur, qui se retournent en quelques secondes (montants de quatre à six chiffres) : elles sont retirées. Le test lit désormais ces valeurs dans une liste hors du dépôt (variable TENSHO_PRIVATE_VALUES, sinon un fichier du dossier local de l'utilisateur ; absente en CI : test sauté, jamais réussi en silence), sur tous les fichiers suivis (README, CONTRIBUTING, SECURITY, repo.json et les .json compris), et un second cliquet, sans aucune valeur, fige par fichier le nombre de lignes qui nomment les gils à côté d'un montant de cinq chiffres ou plus. L'historique git n'est pas réécrit. M2 : un compte hors borne des quêtes non acceptées ne fige plus toute la partie « événements » de la carte : elles sont lues à part, vides et dites indisponibles seules (NativeShape.Apart). M3 : le résultat du Dédale bestial relu est fusionné nombre par nombre (bonus, nombre de bonus, total, lignes du score, PV restants, points des bonus) au lieu de comparer leur nombre : une relecture qui connaît d'autres chiffres ne fait plus perdre le bonus et le total. X-665.
- Tests : ReviewFindings1613Tests. Verify.ps1 (agent) : 3331/3331, 0 avertissement, 0 erreur ; DLL 0.1613.0.0. Rien à essayer en jeu.
### English
- Review of the block 0.1607 to 0.1612, minor findings. M1: the 0.1607 ratchet test kept unkeyed SHA-256 hashes of the user's private values, which turn back into the values in a few seconds (amounts of four to six digits): they are removed. The test now reads these values from a list outside the repository (the TENSHO_PRIVATE_VALUES variable, else a file in the user's local folder; absent in the CI: the test is skipped, never passed in silence), over every tracked file (README, CONTRIBUTING, SECURITY, repo.json and the .json files included), and a second ratchet, without any value, freezes per file the number of lines that name gil beside an amount of five digits or more. The git history is not rewritten. M2: an out-of-bounds count of the quests not accepted no longer freezes the map's whole « events » part: they are read apart, empty and reported unavailable on their own (NativeShape.Apart). M3: the Beastmaster result read again is merged number by number (bonus, number of bonuses, total, the score's lines, HP left, the bonuses' points) instead of comparing how many are known: a reading that knows other numbers no longer loses the bonus and the total. X-665.
