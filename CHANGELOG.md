# Journal des versions / Changelog

Résumé par version, en français puis `### English` (partie anglaise obligatoire depuis 0.219.0) ; la partie anglaise sert aussi de corps
aux commits et aux notes de release sur GitHub. Preuves citées : docs/evidence/.
Chaque version a été compilée et testée par `scripts/Verify.ps1` ; la validation en jeu est indiquée quand l'utilisateur l'a rapportée.
Ce fichier garde la dernière release et les versions qui suivent ; les plus anciennes sont dans [docs/changelog/](docs/changelog/)
(déplacées par `tools/changelog.py archive`, un fichier par centaine de versions).

## 0.1180.0
- Plan global, X-250 : Textes vrais sur ce qui quitte le PC (X-250, revue « premier joueur » du 12/11, constats B1, B2, B4, D1, D2, D3). L'avertissement avant « Connecter GitHub » et la page Sources disent maintenant qu'aucun nom ni identifiant du personnage n'est envoyé, mais qu'un poisson pris ou une touche porte l'endroit exact du personnage (avec le jour, il dit où vous avez pêché ce jour-là) ; la page Sources dit que la base commune se lit sans compte, sur « Échanger maintenant » ou avec l'échange automatique. La FAQ (« Qu'est-ce qui est enregistré ? ») dit que les découvertes sortent par l'échange GitHub après connexion (ou un fichier exporté) et les alarmes par le webhook Discord s'il est indiqué. L'info-bulle de l'échange automatique dit « rien d'automatique » (« Échanger maintenant » envoie quand même). Le gist est dit non répertorié (son lien est dans un ticket public), plus « secret ». La description du plugin dans l'installateur (repo.json, depuis le manifeste) dit aussi la base lue sans compte, l'endroit exact d'une prise, le téléchargement de l'application de bureau sur « Installer » (empreinte SHA-256 vérifiée). SECURITY liste aussi community-v3.json et github.lock.
- Tests : TruthTexts1180Tests. Verify.ps1 (agent) : 2048/2048, 0 avertissement, 0 erreur ; DLL 0.1180.0.0. Non validé en jeu.
### English
- True texts on what leaves the PC (X-250, « first player » review of 11/12, findings B1, B2, B4, D1, D2, D3). The warning before « Connect GitHub » and the Credits page now say that no character name or id is sent, but that a fish caught or a bite carries the character's exact spot (with the day, it tells where you fished that day); the Credits page says the common base is read without an account, on « Exchange now » or with the automatic exchange. The FAQ (« What is saved? ») says discoveries leave through the GitHub exchange after connecting (or an exported file) and alarms through the Discord webhook if one is set. The automatic exchange's tooltip says « nothing automatic » (« Exchange now » still sends). The gist is called unlisted (its link is in a public issue), no longer « secret ». The plugin's description in the installer (repo.json, from the manifest) also says the base is read without an account, the exact spot of a catch, and the desktop app download on « Install » (SHA-256 checked). SECURITY also lists community-v3.json and github.lock.

## 0.1179.0
- Plan global, X-189 : Île de Lunule (X-189, demande de l'utilisateur du 12/11) : alertes des confrontations critiques et des ALÉA de l'île, activées par défaut (interrupteur dans l'onglet de l'île, page Eurêka et Bozja). Quand une confrontation critique ouvre ses inscriptions, une ligne dans le chat et dans l'application de bureau donne son nom, le temps restant et son lieu (zone et coordonnées du repère du jeu) ; un ALÉA qui commence sur l'île de même (nom, niveau, temps restant, lieu) ; le son des alarmes s'il est activé. Chacun est dit une fois tant qu'il dure. Rien pendant un combat (DEC-041) : ce qui s'est ouvert pendant ce temps est dit à la fin du combat, s'il est encore ouvert ; le panneau de l'île se cache aussi pendant un combat. Les confrontations viennent du conteneur DynamicEvent du directeur de l'île, lu avec l'état de l'île une fois par seconde ; le mode développeur écrit ce conteneur dans le journal (« Reading occultevents ») pour vérifier le sens du temps restant à chaque étape. Preuve : docs/evidence/0.1179-occult-alerts.md.
- Tests : OccultAlerts1179Tests. Verify.ps1 (agent) : 2046/2046, 0 avertissement, 0 erreur ; DLL 0.1179.0.0. Non validé en jeu.
### English
- Occult Crescent (X-189, user request of 11/12): alerts for the island's critical engagements and FATEs, on by default (switch in the island's tab, Eureka and Bozja page). When a critical engagement opens its registration, a line in the chat and in the desktop application gives its name, the time left and its place (zone and coordinates of the game's marker); a FATE starting on the island likewise (name, level, time left, place); the alarms' sound if it is on. Each one is said once while it lasts. Nothing during a fight (DEC-041): what opened meanwhile is said once the fight is over, if still open; the island panel also hides during a fight. The engagements come from the DynamicEvent container of the island's director, read with the island's state once a second; developer mode writes that container to the log (« Reading occultevents ») to check what the time left means at each stage. Evidence: docs/evidence/0.1179-occult-alerts.md.

## 0.1173.0
- Plan global, X-182 : Données partagées entre deux clients du jeu, ou deux versions du plugin le même jour (X-182, fin ; revue de la nuit du 12/11, constats N3 et N26). Banque : un fichier d'un personnage réécrit après la conversion par une ancienne version encore lancée est fusionné rangement par rangement, la lecture la plus récente de chacun gardée et les autres rangements conservés ; des lignes déjà en base sans marque de conversion sont jointes, jamais remplacées par le seul fichier. La décision « inchangé, pas réécrit » de la banque se prend désormais contre la base, sous le verrou du profil, et non sur la mémoire du client : un rangement oublié ou changé par l'autre client entre-temps est réécrit. Découvertes : un Discoveries.json réécrit après la conversion est fusionné dans Discoveries.db sans additionner les comptes (une base entière réenregistrée n'est pas doublée ; une case que seul le fichier connaît est ajoutée), puis mis de côté ; une copie déjà mise de côté n'est pas relue ; un nom déjà pris dans le dossier de côté reçoit un suffixe au lieu de bloquer le déplacement. Tests de comportement : fichiers réels, deux services sur la même base.
- Tests : ConcurrentData1173Tests. Verify.ps1 (agent) : 2030/2030, 0 avertissement, 0 erreur ; DLL 0.1173.0.0. Rien à essayer en jeu.
### English
- Data shared by two game clients, or two versions of the plugin the same day (X-182, end; night review of 11/12, findings N3 and N26). Bank: a character file written again after the conversion by an older version still running is merged storage by storage, the newest reading of each kept and the other storages staying; rows already in the database without a conversion mark are joined, never replaced by the file alone. The bank's « unchanged, not written again » decision is now taken against the database, under the profile's lock, not from the client's memory: a storage forgotten or changed by the other client meanwhile is written again. Discoveries: a Discoveries.json written again after the conversion is merged into Discoveries.db without adding counts up (a whole base saved again is not doubled; a cell only the file knows is added), then set aside; a copy already set aside is not read again; a name already taken in the set-aside folder gets a suffix instead of blocking the move. Behaviour tests: real files, two services on one database.
