## 0.1824.0
- Plan global, X-823 : Relecture de 0.1823 (I1), sécurité de la base partagée : la fusion automatique des comptes de confiance (tools/discoveries-trust.py) ne lisait que le nom de la branche, si bien qu'une demande de fusion venue d'un fork, nommée travailleur/discoveries-N, passait, et l'ensemble commun qu'elle apportait n'était contrôlé que par ses chemins. Désormais : la demande doit venir d'une branche du dépôt lui-même (isCrossRepository faux, dépôt de tête Shigu330/Tensho-Assistant), ouverte par le compte du travailleur (celui du propriétaire) ; les auteurs des commits ne sont pas lus (GitHub les déduit d'une adresse que n'importe qui peut écrire). Le contenu est vérifié par valeur : un sync de ce seul partage est rejoué hors ligne (union et rebuild de tools/discoveries-merge.py) sur les fichiers de Devloppement lus à un commit fixé, avec le gist lu à l'instant, et chaque fichier players/ et v3/ de la demande doit contenir ce que ce rejeu écrit (fichiers gzip comparés décompressés, index.json sans ses tailles et empreintes, qui doivent nommer les fichiers de la demande elle-même), sans fichier de plus ni de moins. Tout écart, ou un rejeu qui s'arrête : doute, pas de fusion. Auto-test de l'outil : 63 cas, dont un essai de bout en bout contre un faux GitHub (fork, autre auteur, fichier hors champ, ensemble commun ou fichier du joueur changé par valeur, fichier en plus ou en moins, index qui nomme d'autres octets : jamais fusionné ; même texte compressé autrement : fusionné). Essai à blanc réel sur la PR 54 : doute « pr-files », juste. README de tools et de community-discoveries mis à jour.
- Tests : DiscoveryOrigin1824Tests. Verify.ps1 (agent) : 4008/4008, 0 avertissement, 0 erreur ; DLL 0.1824.0.0. Rien à essayer en jeu.
### English
- Review of 0.1823 (I1), security of the shared set: the trusted accounts' automatic merge (tools/discoveries-trust.py) read only the branch's name, so a pull request from a fork named travailleur/discoveries-N passed, and the common set it brought was checked by its paths only. Now the pull request must come from a branch of the repository itself (isCrossRepository false, head repository Shigu330/Tensho-Assistant), opened by the worker's account (the owner's); the commits' authors are not read (GitHub derives them from an address anyone can write). The content is checked by value: a sync of that share alone is replayed offline (union and rebuild of tools/discoveries-merge.py) on Devloppement's files read at a pinned commit, with the gist just read, and every players/ and v3/ file of the pull request must hold what that replay writes (gzip files compared unpacked, index.json without its sizes and hashes, which must name the pull request's own files), no file more nor less. Any difference, or a replay that stops: a doubt, no merge. Tool selftest: 63 cases, including an end-to-end run against a made-up GitHub (a fork, another author, a file out of scope, a common set or player file changed by value, a file more or missing, an index naming other bytes: never merged; the same text packed otherwise: merged). Real dry run on PR 54: « pr-files » doubt, as expected. READMEs of tools and community-discoveries updated.

## 0.1823.0
- Plan global, X-805 : Décision de l'utilisateur du 22/11 (R12.2 et R20.6 complétées) : fusion automatique des découvertes partagées pour les comptes de confiance. Nouvel outil du mainteneur tools/discoveries-trust.py, pour le travailleur du portable : la liste des comptes de confiance est un fichier texte hors du dépôt (~/.tensho/trusted-accounts.txt, un identifiant GitHub par ligne, refusée dans le dépôt ; « init » la crée avec le compte du propriétaire du dépôt, sans jamais la réécrire). « merge N » fusionne la demande travailleur/discoveries-<ticket> seulement si tout passe : la demande (ouverte, base Devloppement, sans conflit, fichiers de ce ticket et de v3/ seulement, liste entière, CI verte), le ticket (partage ouvert, un gist, CC0-1.0, titre, auteur du ticket sur la liste, jamais celui de la demande, gist de cet auteur, pas de partage plus récent), le gist lu maintenant (au plus 5 % refusés, sortes connues, volume plausible), le fichier du joueur de la demande (ce ticket, cet identifiant, cette révision du gist notée ; aucun fait perdu, aucun venu d'ailleurs, du neuf). Fusion en squash épinglée sur le commit vérifié, « merged automatically » dans son titre, ticket commenté en anglais puis en français. Au moindre doute : pas de fusion, la demande commentée une fois avec la raison, ligne « TELL THE MAINTAINER ». Compte hors liste : rien ne change. Auto-test de l'outil (décision sur des cas inventés).
- Tests : DiscoveryTrust1823Tests. Verify.ps1 (agent) : 4006/4006, 0 avertissement, 0 erreur ; DLL 0.1823.0.0. Rien à essayer en jeu.
### English
- User decision of 22/11 (R12.2 and R20.6 completed): automatic merge of shared discoveries for trusted accounts. New maintainer tool tools/discoveries-trust.py, for the laptop worker: the list of trusted accounts is a text file outside the repository (~/.tensho/trusted-accounts.txt, one GitHub login per line, refused inside the repository; « init » creates it with the repository owner's account, never writing over it). « merge N » merges the pull request travailleur/discoveries-<issue> only when everything passes: the pull request (open, base Devloppement, no conflict, files of that ticket and of v3/ only, whole list, CI green), the ticket (open share, one gist, CC0-1.0, title, the ticket's author on the list, never the pull request's, gist owned by that author, no newer share), the gist read now (at most 5 % refused, known kinds, plausible volume), the pull request's player file (that ticket, login and gist revision noted; no fact lost, none from elsewhere, something new). Squash merge pinned on the checked commit, « merged automatically » in its title, the ticket commented in English then French. Any doubt: no merge, the pull request commented once with the reason, a « TELL THE MAINTAINER » line. An account not on the list: nothing changes. Tool selftest (decision on made-up cases).

## 0.1822.0
- Plan global, X-820 : Relecture 0.1819, mineurs. M1 : après un changement de compte GitHub sur le même profil, le gist fusionné de l'ancien compte était « supprimé » avec le jeton du nouveau ; GitHub répond 404 pour le gist secret d'un autre compte, compté comme « déjà supprimé », et l'état l'oubliait. L'état note maintenant le compte du gist à supprimer : seul ce compte le supprime ; un autre compte le garde noté, l'écrit dans le journal et le dit au joueur. M2 : les textes disaient « sans votre nom » et « fermer ce ticket retire votre nom » ; il faut en plus que le mainteneur retire le fichier de joueur, et le ticket fermé garde son titre public, l'historique git garde le fichier avec l'identifiant. Dit tel quel dans le plugin (avertissement, aides de connexion, d'échange, de déconnexion, page réseau), dans le ticket (anglais puis français) et le README. M3 écarté avec sa raison : depuis X-804 un gist ne garde que les nouveautés, un fait absent ne dit rien ; un fait reconnu faux sort de chaque fichier de joueur par une règle de l'outil (rebuild applique les règles du moment à chaque fichier) ou avec withdraw ; dit dans le README.
- Pour les joueurs : les textes du partage disent maintenant exactement ce que devient votre nom GitHub quand vous arrêtez de partager ; le gist du compte GitHub utilisé avant sur ce PC n'est plus compté comme supprimé quand il ne l'est pas.
- Tests : GistOwner1822Tests. Verify.ps1 (agent) : 4005/4005, 0 avertissement, 0 erreur ; DLL 0.1822.0.0. Non validé en jeu.
### English
- Review of 0.1819, minor findings. M1: after a change of GitHub account on the same profile, the merged gist of the account before was « deleted » with the new one's token; GitHub answers 404 for another account's secret gist, counted as « already gone », and the state forgot it. The state now notes the account of the gist to delete: only that account deletes it; another account keeps it noted, logs it and tells the player. M2: the texts said « without your name » and « closing this issue removes your name »; the maintainer still has to remove the player file, and the closed issue keeps its public title, git history keeps the file with the login. Said as it is in the plugin (warning, connect, exchange and disconnect help, network page), in the issue (English then French) and the README. M3 set aside with its reason: since X-804 a gist holds news only, a missing fact says nothing; a fact found wrong is taken out of every player file by a rule of the tool (rebuild applies the current rules to each file) or with withdraw; said in the README.
- For players: The sharing texts now say exactly what happens to your GitHub name when you stop sharing; a gist of the GitHub account you used before on this PC is no longer counted as deleted when it was not.

## 0.1820.0
- Plan global, X-819 : Relecture 0.1819, I1 : un gist créé pendant l'échange, suivi d'un échec du ticket (refus 403 ou 5xx, réseau coupé, application GitHub absente), était oublié : l'état de la rotation gardait le gist d'avant, l'échange suivant en créait un autre et le premier restait sur GitHub, jamais lié ni supprimé, avec les lieux exacts et les jours du joueur. L'état de la rotation note maintenant le gist dès que l'envoi échoue après sa création (et le ticket, s'il est à rouvrir) ; l'échange suivant réécrit ce gist au lieu d'en créer un, et un gist neuf après une fusion modifie le ticket à chaque essai jusqu'au bout. Tests de comportement contre un faux GitHub (modification du ticket refusée, ouverture refusée après un gist disparu, échec avant tout gist).
- Pour les joueurs : un échec de GitHub pendant le partage de vos découvertes ne laisse plus de copie oubliée en ligne : l'échange suivant la reprend.
- Tests : GistKept1820Tests. Verify.ps1 (agent) : 4002/4002, 0 avertissement, 0 erreur ; DLL 0.1820.0.0. Rien à essayer en jeu.
### English
- Review of 0.1819, I1: a gist made during the exchange, then a failure at the issue step (403 or 5xx refusal, network cut, GitHub App missing), was forgotten: the rotation's state kept the gist before, the next exchange made another and the first stayed on GitHub, never linked nor deleted, with the player's exact places and days. The rotation's state now notes the gist as soon as the upload fails after making it (and the issue, when it is to open again); the next exchange writes that gist again instead of making one, and a new gist after a merge edits the issue at every try until it is done. Behaviour tests against a fake GitHub (issue edit refused, issue opening refused after a gist gone, failure before any gist).
- For players: A GitHub failure while sharing your discoveries no longer leaves a forgotten copy of them online: the next exchange reuses it.
