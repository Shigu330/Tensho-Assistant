## 0.1554.0
- Plan global, X-589 : Audit externe du 18/11, famille « sources réseau », première partie (X-589) : chaque source finit dans un état terminal (données, copie expirée ou erreur retentée). A08 : LuminaSupplemental, une requête au-delà de ses 30 s sans copie finit en erreur retentée après 5 min (avant : « chargement » toute la session, jamais retenté). A09 : temps de touche de Teamcraft, une erreur est retentée après 5 min et la copie expirée est prise d'abord (avant : erreur gardée sans échéance). A12 : Universalis (comparaison des servants), une heure d'envoi qui n'est pas un nombre ou hors calendrier est inconnue, et toute autre erreur de la réponse termine la requête (avant : « chargement » gardé). A26 : GatherBuddy, le texte est vérifié avant d'être gardé : un index sans fichier ou sans poisson est un échec, jamais une copie vide gardée fraîche. Reste pour la partie suivante : A10, A11, A02, A07, A24.
- Pour les joueurs : les sources en ligne (sources d'objets, temps de touche des poissons, comparaison des prix des servants, poissons de GatherBuddy) ne restent plus « en chargement » après une erreur de réseau ou de données : elles disent l'erreur et réessaient plus tard.
- Livré : X-589 (critères restant à valider).
- Tests : NetworkEnds1554Tests. Verify.ps1 (agent) : 3133/3133, 0 avertissement, 0 erreur ; DLL 0.1554.0.0. Rien à essayer en jeu.
### English
- External audit of 18/11, family « network sources », first part (X-589): each source ends in a terminal state (data, an expired copy, or an error tried again). A08: LuminaSupplemental, a request past its 30 s without a copy ends in an error tried again after 5 min (before: « loading » for the session, never tried again). A09: Teamcraft's bite times, an error is tried again after 5 min and the expired copy is taken first (before: error kept with no deadline). A12: Universalis (retainer comparison), an upload time that is not a number or past the calendar is unknown, and any other error of the answer ends the request (before: « loading » kept). A26: GatherBuddy, the text is checked before it is kept: an index without files or without a fish is a failure, never an empty copy kept fresh. Left for the next part: A10, A11, A02, A07, A24.
- For players: Online sources (item sources, fish bite times, retainer price comparison, GatherBuddy fish) no longer stay « loading » after a network or data error: they show the error and try again later.
- Delivered: X-589 (criteria left to validate).

## 0.1553.0

- Pour les joueurs : le consentement de l'historique du chat, l'info-bulle de son réglage et la FAQ disent maintenant exactement ce qui est gardé : chaque message lu par la fenêtre de chat, aussi les canaux qu'aucun onglet ne montre et les joueurs cachés.

### English
- External audit of 18/11, A04 (the user's choice of 18/11: correct the text, not the code) (X-593): the chat history keeps every message the chat window reads, including those of channels no tab shows and those of the hidden players (the tabs and the hidden players only choose what is shown). The consent (« What: »), the tip of the setting « Keep the chat history on this PC » and the FAQ answer now say so in English and French, instead of « the messages of the tabs ». Behaviour unchanged.
- For players: The chat history's consent, its setting's tip and the FAQ now say exactly what is kept: every message the chat window reads, also channels no tab shows and hidden players.

## 0.1552.0
- Plan global, X-588 : Audit externe du 18/11, famille « découvertes : chargement et export » (X-588). A01 : la lecture de vos découvertes au démarrage (vos faits et la liste des sortes partagées) est retentée 5 fois à 10 s d'intervalle, chaque échec dit sur la page ; si elle échoue toujours, la page s'ouvre sans vos faits et rien n'est envoyé sur GitHub pendant la session (avant : page « en chargement » toute la session, erreur non observée ; DiscoveryStart). A17 : une sorte partagée dont la lecture échoue reste en attente (jamais réécrite), est dite sur la page et relue toutes les 30 s ; un import qui en a besoin s'arrête avant de rien joindre. A18 : l'export lit d'abord les sortes partagées encore sur le disque et nomme celles qui manquent (« ExportPartial ») au lieu de dire tout écrit. A19 : le résumé de la page Découvertes est recalculé seulement quand la base change (avant : tous les faits regroupés sous le verrou à chaque image).
- Pour les joueurs : la page Découvertes ne reste plus « en chargement » après une erreur de lecture : elle dit ce qui a échoué et réessaie ; un export dit quand des découvertes partagées y manquent.
- Tests : DiscoveriesLoad1552Tests. Verify.ps1 (agent) : 3127/3127, 0 avertissement, 0 erreur ; DLL 0.1552.0.0. Rien à essayer en jeu.
### English
- External audit of 18/11, family « discoveries: loading and export » (X-588). A01: the start's read of your discoveries (your facts and the shared kinds' list) is tried again 5 times 10 s apart, each failure said on the page; still failing, the page opens without your facts and nothing is sent to GitHub that session (before: page « loading » for the whole session, error unobserved; DiscoveryStart). A17: a shared kind whose read fails stays waiting (never written over), is said on the page and read again every 30 s; an import that needs it stops before joining anything. A18: the export first reads the shared kinds still on disk and names the missing ones (« ExportPartial ») instead of saying everything was written. A19: the Discoveries page's summary is worked out again only when the base changes (before: every fact grouped under the lock at each frame).
- For players: The Discoveries page no longer stays « loading » after a read error: it says what failed and tries again; an export says when shared discoveries are missing from it.

## 0.1551.0
- Plan global, X-587 : Audit externe du 18/11, famille « données du joueur après une erreur » (X-587). A16 : une base des découvertes qui n'a pas été lue en entier au démarrage (base SQLite qui ne s'ouvre pas, fichier mis de côté ou illisible) ne remplace plus le gist publié : DiscoveryStore.MineIncomplete, l'échange GitHub n'envoie rien (« ShareBlocked ») et reçoit toujours les données communes. A03 : le fichier des plans du Dédale bestial n'est plus jamais réécrit après une lecture ratée : tenu par un autre programme, il est relu toutes les 10 s sans rien écrire ; abîmé, il est mis de côté sous un nom daté avant tout nouveau fichier (BeastPlansFile). A14 : le journal des gils n'est marqué enregistré qu'après l'écriture réussie ; une écriture ratée garde sa copie, réécrite à l'enregistrement suivant, même après un changement de personnage (GilSaves). A20 : la copie SQLite de l'application de bureau n'est plus effacée quand c'est la base du plugin qui est abîmée (contrôle rapide de SQLite) ; une copie abîmée est refaite à côté puis prend sa place. A15 : MarketSeen.json a la même borne de 64 Mo en lecture et en écriture (les entrées les plus anciennes laissées de côté jusqu'à tenir) ; un fichier illisible est mis de côté sous un nom daté, jamais écrasé. A27 : un prix vu au tableau pendant un démarrage lent n'est plus écrasé par l'ancien du fichier (offres les plus récentes gardées, ventes jointes).
- Pour les joueurs : vos découvertes partagées, plans du Dédale bestial, journal des gils et prix du marché sont gardés après une erreur de lecture ou d'écriture (fichier tenu par un autre programme, fichier abîmé).
- Tests : AfterError1551Tests. Verify.ps1 (agent) : 3122/3122, 0 avertissement, 0 erreur ; DLL 0.1551.0.0. Rien à essayer en jeu.
### English
- External audit of 18/11, family « the player's data after an error » (X-587). A16: a discoveries base not read whole at start (a SQLite base that does not open, a file set aside or unreadable) no longer replaces the published gist: DiscoveryStore.MineIncomplete, the GitHub exchange sends nothing (« ShareBlocked ») and still receives the common data. A03: the beast labyrinth plans' file is never written again after a failed read: held by another program, it is read again every 10 s and nothing is written; damaged, it is set aside under a dated name before any new file (BeastPlansFile). A14: the gil journal is marked saved only after its write succeeded; a failed write keeps its copy, written again at the next save, also after a character change (GilSaves). A20: the desktop application's SQLite copy is no longer erased when the plugin's own base is the damaged one (SQLite quick check); a damaged copy is made again beside it, then takes its place. A15: MarketSeen.json has the same 64 MB bound in reading and writing (the oldest entries left out until it fits); an unreadable file is set aside under a dated name, never overwritten. A27: a price seen at the market board during a slow start is no longer overwritten by the file's older one (newest offers kept, sales joined).
- For players: Your shared discoveries, beast labyrinth plans, gil journal and market prices are kept safe after a read or write error (a file held by another program, a damaged file).
