## 0.1515.0

### English
- Changelog: in the « Pour les joueurs » line of 0.1511, the plugin's name gets its capital back (« Tensho n'affiche plus ses fenêtres… »). The tool writing that line lowered any first word after the colon, a proper name too; it now keeps the capital of a list of names (Tensho, Dalamud, Discord…), and the changelog's writing test accepts the same list (review of 0.1514, M4). ## 0.1513.0
- Plan global, X-535 : Carte : un clic gauche pose le drapeau par défaut (X-535, essai T-0.546-1 signalé par l'utilisateur le 17/11 : « clic sur la map pose pas de drapeau »). Le réglage « Clic gauche pour poser le drapeau » était désactivé par défaut depuis 0.546, et désactivé dans les réglages de l'utilisateur. Il est maintenant activé par défaut, comme sur la carte du jeu ; renommé (FlagOnClick devient FlagOnLeftClick) pour qu'une valeur enregistrée désactivée ne soit pas relue ; il se décoche toujours dans Paramètres › Carte. La règle du clic (endroit vide d'une carte de zone, bouton relâché, pas de glisser, aucune icône, lien, repère ni info-bulle de point de récolte ou de panorama sous la souris) est dans Maps.MapClickFlag. Choix (1) de la question posée à la maître par le relais 101, appliqué sans réponse avant la fin du relais ; l'option (2), garder le réglage désactivé, reste possible.
- Pour les joueurs : sur la carte Tensho, un clic gauche bref sur un endroit vide d'une carte de zone pose maintenant le drapeau par défaut, comme sur la carte du jeu (désactivable dans les réglages de la carte).
- Tests : MapClickFlag1513Tests. Verify.ps1 (agent) : 3011/3011, 0 avertissement, 0 erreur ; DLL 0.1513.0.0. Rien à essayer en jeu.
### English
- Map: a left click places the flag by default (X-535, test T-0.546-1 reported by the user on 17/11: « a click on the map places no flag »). The setting « Left click places the flag » was off by default since 0.546, and off in the user's settings. It is now on by default, as on the game's map; renamed (FlagOnClick becomes FlagOnLeftClick) so a value saved off is not read back; it can still be unticked in Settings › Map. The click's rule (an empty spot of a zone map, button released, no drag, no icon, link, bookmark nor gathering point or vista tooltip under the mouse) is in Maps.MapClickFlag. Choice (1) of relay 101's question to the master, applied without an answer before the end of the relay; option (2), keeping the setting off, stays possible.
- For players: On Tensho's map, a short left click on an empty spot of a zone map now places the flag by default, as on the game's map (it can be turned off in the map settings).

## 0.1512.0
- Plan global, X-540 : Relecture de 0.1508 à 0.1510, mineur M1 (X-540). La place des messages du chat du jeu était lue à chaque image où le chat du jeu est affiché, aussi option « Cacher les messages du chat du jeu » coupée (son défaut, donc chez tous les joueurs) et pendant une coupure du contenu classé (DEC-038 : tout Tensho se coupe) ; en mode développeur, sa ligne du journal s'écrivait à chaque changement, et une erreur de lecture arrêtait le cacheur (« Hiding the game chat's messages stopped ») chez qui ne s'en sert pas. La place n'est plus lue que tant que l'option est voulue (MainWindow.ChatGameMessagesOption, passée au cacheur), hors coupure classée (ChatHideWants.OptionReadsPlace) ; elle reste lue pendant que les messages sont rendus sous une fenêtre du jeu ou en combat (X-534 M1). M2 (X-532 noté fait sur un contrôle textuel) et M3 (menu des canaux lu par la seule visibilité de sa liste) : levés par la maître ; M3 reste à prouver en jeu par l'essai de X-533.
- Tests : ChatPlaceOption1512Tests. Verify.ps1 (agent) : 3009/3009, 0 avertissement, 0 erreur ; DLL 0.1512.0.0. Non validé en jeu.
### English
- Review of 0.1508 to 0.1510, minor M1 (X-540). The place of the game chat's messages was read in every frame the game's chat is shown, also with the option « Hide the game chat's messages » off (its default, so for every player) and during a competitive cut (DEC-038: all of Tensho stops); in developer mode its log line was written at each change, and a reading error stopped the hider (« Hiding the game chat's messages stopped ») for players who do not use it. The place is now read only while the option is wanted (MainWindow.ChatGameMessagesOption, given to the hider), outside a competitive cut (ChatHideWants.OptionReadsPlace); it is still read while the messages are given back under a game window or in combat (X-534 M1). M2 (X-532 marked done on a text check) and M3 (channel menu read by its list's visibility alone): lifted by the master; M3 stays to be proven in game by X-533's test.

## 0.1511.0
- Plan global, X-539 : Rien de Tensho avant la connexion d'un personnage (X-539, capture de l'écran titre par l'utilisateur, 17/11). Sur l'écran titre et la sélection du personnage, Tensho dessinait déjà ses fenêtres (« Suivi Tensho », la fenêtre de chat Tensho). Les fenêtres et les panneaux de Tensho attendent maintenant qu'un personnage soit connecté et chargé (UI.CharacterGate : connexion et joueur chargé) ; leur état ouvert ou fermé n'est jamais touché : après la connexion, les fenêtres de la dernière session reviennent telles quelles ; à la déconnexion (retour à l'écran titre), elles disparaissent sans perdre cet état. La commande /tensho sans personnage dit en une ligne qu'il faut d'abord se connecter avec un personnage. La coupure du contenu classé garde sa place, en premier.
- Pour les joueurs : Tensho n'affiche plus ses fenêtres sur l'écran titre et la sélection du personnage : elles reviennent comme vous les aviez laissées une fois votre personnage connecté.
- Tests : CharacterGate1511Tests. Verify.ps1 (agent) : 3007/3007, 0 avertissement, 0 erreur ; DLL 0.1511.0.0. Non validé en jeu.
### English
- Nothing of Tensho before a character is logged in (X-539, user capture of the title screen, 17/11). On the title screen and the character selection, Tensho already drew its windows (« Suivi Tensho », the Tensho chat window). Tensho's windows and panels now wait until a character is logged in and loaded (UI.CharacterGate: login and player loaded); their open or closed state is never touched: after the login, the last session's windows come back as they were; at the logout (back to the title screen), they leave without losing that state. The /tensho command without a character says in one line to log in with a character first. The competitive cut keeps its place, first.
- For players: Tensho no longer shows its windows on the title screen and the character selection: they come back as you left them once your character is logged in.

## 0.1510.0
- Plan global, X-534 : Relecture de 0.1505 à 0.1507, mineurs (X-534). M1 : la place des messages du chat du jeu n'était lue que pendant qu'ils étaient cachés ; quand une fenêtre du jeu qui couvrait la fenêtre de chat Tensho (« Se cacher ») se fermait, ou à la fin d'un combat avec « Masquer en combat », la fenêtre Tensho était dessinée une image à la place du joueur avant de reprendre celle des messages (clignement), et si cette place-là était couverte par une autre fenêtre du jeu, elle se jugeait couverte et les messages du jeu restaient affichés. La place est maintenant lue à chaque image où le chat du jeu est affiché, aussi pendant que les messages sont rendus (ChatHideWants.ReadsPlace) ; la fenêtre ne s'en sert que pendant qu'ils sont cachés. M2 : le contrat de ChatHideWants.Of disait « contenu classé : toujours rendus » alors que le cacheur tient (Hold) tant que la fenêtre du chat du jeu n'est pas affichée ; une seule règle par image, ChatHideWants.InFrame (chat du jeu non affiché : tenu ; sinon contenu classé : rendus ; sinon le souhait), appliquée par le cacheur ; le contrat de Of le dit.
- Pour les joueurs : le chat Tensho ne clignote plus ailleurs quand une fenêtre du jeu posée dessus se ferme, pendant que les messages du chat du jeu sont cachés.
- Tests : ChatGameResume1510Tests. Verify.ps1 (agent) : 3005/3005, 0 avertissement, 0 erreur ; DLL 0.1510.0.0. Non validé en jeu.
### English
- Review of 0.1505 to 0.1507, minor findings (X-534). M1: the place of the game chat's messages was read only while they were hidden; when a game window covering Tensho's chat window (« Hide ») closed, or at the end of a fight with « Hide in combat », Tensho's window was drawn one frame at the player's own place before taking the messages' place again (a blink), and if that place was covered by another game window it judged itself covered and the game's messages stayed shown. The place is now read in every frame the game's chat is shown, also while the messages are given back (ChatHideWants.ReadsPlace); the window uses it only while they are hidden. M2: ChatHideWants.Of's contract said « competitive content: always given back » while the hider holds (Hold) as long as the game's chat window is not shown; one rule per frame now, ChatHideWants.InFrame (game chat not shown: held; else competitive content: given back; else the wish), applied by the hider; Of's contract says so.
- For players: The Tensho chat no longer blinks elsewhere when a game window over it closes, while the game chat's messages are hidden.
