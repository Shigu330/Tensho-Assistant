## 0.1746.0
- Plan global, X-758 : Chat de Tensho, menu du jeu d'un joueur loin (X-758, suite de D-202 b et X-715) : analyse écrite de la mesure de la sonde (essai T-0.1718-1, 21/11 entre 18 h 43 et 18 h 44, 5 clics). Le clic envoie au gestionnaire externe n° 2 de UIModule (sans nom) le type (lien de joueur, envoyé comme 10), trois valeurs (la 2e est toujours le monde d'origine ; la 1re vaut 14, 16 ou 30, les numéros des canaux équipe, linkshell 1 et cri, lecture probable), le groupe (numéro de la ligne dans le journal du jeu), le nom et le panneau ; jamais le content id : le jeu le retrouve dans sa propre ligne (3 clics sur 5). Aucune façon sûre : aucune fonction nommée n'ouvre ce menu pour un joueur loin ; imiter le clic, c'est appeler un gestionnaire sans nom avec un numéro de ligne du journal du jeu que Tensho ne garde pas (risque d'un autre joueur, « Signaler » compris ; plantage possible après une mise à jour). Tensho garde ses voies nommées pour un joueur loin (message privé dans la zone de saisie, invitation, fiche d'aventurier) ; demande d'ami, liste noire et signaler restent au chat du jeu. Recommandé : garder ainsi (D-203 a, réécrite pour l'utilisateur). Rien n'est envoyé au jeu. ChatMenuMeasure1746Tests (2) : aucun gestionnaire externe de l'interface du jeu appelé par le plugin (cliquet) ; l'analyse écrite, les cinq clics dans les deux moitiés. Preuve docs/evidence/0.1746-chat-player-menu-measure.md.
- Tests : ChatMenuMeasure1746Tests. Verify.ps1 (agent) : 3741/3741, 0 avertissement, 0 erreur ; DLL 0.1746.0.0. Rien à essayer en jeu.
### English
- Tensho's chat, the game's menu of a player far away (X-758, following D-202 b and X-715): written analysis of the probe's measure (test T-0.1718-1, 21/11 between 18:43 and 18:44, 5 clicks). The click sends to UIModule's external handler number 2 (unnamed) the type (player link, sent as 10), three values (the 2nd is always the home world; the 1st is 14, 16 or 30, the numbers of the party, linkshell 1 and yell channels, a likely reading), the group (the line's number in the game's log), the name and the panel; never the content id: the game finds it in its own line (3 clicks of 5). No safe way: no named function opens that menu for a player far away; imitating the click means calling an unnamed handler with a number of a line of the game's log that Tensho does not keep (risk of another player, « Report » included; a crash possible after a game update). Tensho keeps its named routes for a player far away (tell in the typing box, invitation, adventurer plate); friend request, blacklist and report stay with the game's chat. Recommended: keep it so (D-203 a, rewritten for the user). Nothing is sent to the game. ChatMenuMeasure1746Tests (2): no external handler of the game's interface called by the plugin (ratchet); the analysis written, the five clicks in both halves. Evidence docs/evidence/0.1746-chat-player-menu-measure.md.

## 0.1745.0
- Plan global, X-685 : Mémoire (X-685, partie 2 ; D-206 a, choix de l'utilisateur du 21/11) : Tensho enregistre ses réglages lui-même, dans %APPDATA%\XIVLauncher\pluginConfigs\TenshoAssistant\Settings.json, avec System.Text.Json (SettingsJson, SettingsFile), et plus par Dalamud (Newtonsoft avec noms de types : Newtonsoft et TypeDescriptor, partagés par tout le processus du jeu, gardaient pour de bon chaque copie déchargée de Tensho). Le fichier de Dalamud (pluginConfigs\TenshoAssistant.json) est lu une fois au premier chargement (noms « $type » retirés), puis laissé tel quel. Même forme que Newtonsoft : champs publics (couleurs), objets et tables remplis sur place (défauts des tailles d'icônes gardés), noms sans casse. Chaque enregistrement, sous un verrou partagé par les clients du jeu, relit le fichier et fusionne à trois voies : le changement d'un autre client et les noms inconnus (Tensho plus récent) gardés, une entrée retirée reste retirée ; écrit en entier, version d'avant en .bak ; une écriture qui échoue ne change rien, est dite une fois, et l'enregistrement suivant écrit tout ; un fichier illisible est mis à part, jamais écrasé sans être vu. Application de bureau : lit le nouveau fichier par le lecteur du plugin et sa garde (adresses Discord retirées), l'ancien tant qu'il n'y a pas le nouveau ; le lien local suit le nouveau fichier. Plus de Newtonsoft dans le plugin. SettingsFile1745Tests (11) : plus de 300 membres remplis à toute profondeur, lus comme Newtonsoft les lisait ; aller-retour exact ; deux clients (l'un après l'autre et 25 enregistrements chacun en même temps) ; écriture qui échoue ; noms inconnus ; retraits ; fichier illisible ; copie des tests déchargée libérée (témoin Newtonsoft gardé) ; bureau ; câblage. Vrai fichier de l'utilisateur (78 Ko, 230 réglages) comparé sur ce PC par un test jamais commité : aucune différence. Tableau de bord relu : la ligne mémoire n'a pas de seuil ; les Mo de la barre sont le tas géré de tout le processus. Tests existants modifiés : ConfigRoundTrip1328Tests, SettingsSaver1164Tests, LinkLive1114Tests (raison écrite). Preuve docs/evidence/0.1745-settings-file.md.
- Pour les joueurs : Tensho enregistre maintenant ses réglages dans son propre fichier (l'ancien est lu une fois et laissé tel quel) : recharger le plugin ne garde plus l'ancienne copie dans la mémoire du jeu.
- Tests : SettingsFile1745Tests. Verify.ps1 (agent) : 3739/3739, 0 avertissement, 0 erreur ; DLL 0.1745.0.0. Non validé en jeu.
### English
- Memory (X-685, part 2; D-206 a, the user's choice of 21/11): Tensho saves its settings itself, in %APPDATA%\XIVLauncher\pluginConfigs\TenshoAssistant\Settings.json, with System.Text.Json (SettingsJson, SettingsFile), no longer through Dalamud (Newtonsoft with type names: Newtonsoft and TypeDescriptor, shared by the whole game process, kept every unloaded copy of Tensho for good). Dalamud's file (pluginConfigs\TenshoAssistant.json) is read once at the first load (« $type » names taken out), then left as it was. Same shape as Newtonsoft's: public fields (colours), objects and tables filled in place (the icon sizes' defaults kept), names of any case. Each save, under a lock shared by the game clients, reads the file again and merges three ways: another client's change and unknown names (a newer Tensho) kept, an entry removed stays removed; written whole, the version before as .bak; a write that fails changes nothing, is said once, and the next save writes everything; an unreadable file is kept aside, never written over unseen. Desktop app: reads the new file through the plugin's reader and its guard (Discord addresses taken out), the former one while there is no new one; the local link follows the new file. No Newtonsoft left in the plugin. SettingsFile1745Tests (11): more than 300 members filled at any depth, read as Newtonsoft read them; exact round trip; two clients (one after the other, and 25 saves each at the same time); a write that fails; unknown names; removals; an unreadable file; an unloaded copy of the tests collected (Newtonsoft control kept); desktop; wiring. The user's real file (78 KB, 230 settings) compared on this PC by a test never committed: no difference. Dashboard read again: the memory line has no threshold; the bar's megabytes are the whole process's managed heap. Existing tests changed: ConfigRoundTrip1328Tests, SettingsSaver1164Tests, LinkLive1114Tests (reason written). Evidence docs/evidence/0.1745-settings-file.md.
- For players: Tensho now saves its settings in a file of its own (the old one is read once and left as it was): reloading the plugin no longer keeps the previous copy in the game's memory.
