# Journal des versions / Changelog

Résumé par version, en français puis `### English` (partie anglaise obligatoire depuis 0.219.0) ; la partie anglaise sert aussi de corps
aux commits et aux notes de release sur GitHub. Preuves citées : docs/evidence/.

## 0.1339.0
- Plan global, X-351 : Carte, icônes fixes à déblocage, sonde (R06) : au chargement de la 0.1338, la liste de la carte du jeu ne contenait qu'une icône sans bit sur 50 de la carte 14 (Ul'dah, facteur d'échelle 200) : la conversion des positions de la liste du jeu (monde × 16) n'a été prouvée qu'à Mor Dhona (facteur 100). Quand la liste du jeu ne correspond à aucune carte, le journal écrit désormais aussi, une fois par changement, les données brutes (facteur d'échelle, décalages, icônes de la feuille et de la liste du jeu, 80 au plus de chaque) pour trouver la règle de position.
- Tests : MapMarkerShown1338Tests. Verify.ps1 (agent) : 2515/2515, 0 avertissement, 0 erreur ; DLL 0.1339.0.0. Rien à essayer en jeu.
### English
- Map, fixed icons with an unlock, probe (R06): when 0.1338 loaded, the game's map list held only one of the 50 icons without a bit of map 14 (Ul'dah, size factor 200): the position rule of the game's list (world × 16) was proven at Mor Dhona only (factor 100). When the game's list matches no map, the log now also writes, once per change, the raw data (size factor, offsets, icons of the sheet and of the game's list, 80 at most of each) to find the position rule.

## 0.1333.0
- Plan global, X-171 : Deux clients du jeu sur le même profil, dernière partie (audit GPT du 12/11) : le dossier du cache (DataCache-v1) est commun aux deux clients, mais la file d'écriture et le verrou de disque de « Vider le cache » (X-142, 0.1122) ne valaient que dans un client. L'autre client pouvait écrire pendant la copie puis voir son fichier effacé, ou perdre une écriture dont la purge retirait le fichier temporaire. Désormais chaque écriture du cache (fichier temporaire, remplacement, rangement), le rapport de patch et la purge (copie puis retrait) tiennent un verrou du profil (DataCache-v1.lock, à côté du dossier, jamais retiré) : une écriture de l'autre client demandée pendant la purge attend puis reste après elle. Un fichier que l'autre client lit un instant est retiré après un court nouvel essai ; un fichier lu puis retiré par l'autre client compte comme absent, pas comme une erreur. Si le verrou reste pris trop longtemps (15 s), l'écriture échoue sans rien écrire et la purge échoue sans rien retirer, et le message le dit. L'attente du verrou s'arrête au déchargement du plugin. Nouveau test TwoClientsCache1333 (deux caches sur le même dossier : écriture pendant la purge, verrou tenu, fichier lu un instant). X-171 est fini.
- Tests : TwoClientsCache1333Tests. Verify.ps1 (agent) : 2504/2504, 0 avertissement, 0 erreur ; DLL 0.1333.0.0. Rien à essayer en jeu.
### English
- Two game clients on the same profile, last part (GPT audit of 11/12): the cache folder (DataCache-v1) is shared by both clients, but the write queue and the disk lock of « Empty the cache » (X-142, 0.1122) held within one client only. The other client could write during the copy and then see its file erased, or lose a write whose temporary file the purge removed. Now each cache write (temporary file, replace, trim), the patch report and the purge (copy, then removal) hold a lock of the profile (DataCache-v1.lock, beside the folder, never removed): a write by the other client asked during the purge waits, then stays after it. A file the other client reads for an instant is removed after a short retry; a file read and removed by the other client counts as missing, not as an error. When the lock stays taken too long (15 s), the write fails without writing anything and the purge fails without removing anything, and the message says so. The wait for the lock ends when the plugin unloads. New test TwoClientsCache1333 (two caches on the same folder: a write during the purge, a held lock, a file read for an instant). X-171 is finished.
