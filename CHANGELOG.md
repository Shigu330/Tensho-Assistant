## 0.1873.0
- Plan global, X-868 : Relecture 0.1871, M2 (déjà là avant le bloc), sur le cliquet des fins de ligne (Pending1865Tests). Un découpage dont le \n est l'un des séparateurs écrits dans l'appel est trouvé, à n'importe quelle place : plusieurs séparateurs (« Split(';','\n') »), un tableau (« new[]{'\n'} », « new char[]{…} », « new string[]{…} ») ou une collection (« Split(['\n']) »). Un découpage dont les séparateurs prennent aussi le \r passe toujours. Écarté avec sa raison (commentaire de NewlineSearch) : des séparateurs rangés dans une variable ou un champ (leur valeur est écrite ailleurs, et aucun test d'aujourd'hui ne découpe ainsi une lecture brute). L'en-tête de RawNewline1871Tests dit maintenant exactement ce qui est couvert et ce qui est écarté. Le cliquet élargi ne trouve aucune nouvelle lecture dans les tests. Tests : RawNewline1873Tests (2).
- Tests : RawNewline1873Tests. Verify.ps1 (agent) : 4137/4137, 0 avertissement, 0 erreur ; DLL 0.1873.0.0. Rien à essayer en jeu.
### English
- Review 0.1871, M2 (there before the block), on the line-ending ratchet (Pending1865Tests). A split whose \n is one of the separators written in the call is found, at any place: several separators (« Split(';','\n') »), an array (« new[]{'\n'} », « new char[]{…} », « new string[]{…} ») or a collection expression (« Split(['\n']) »). A split whose separators also take the \r still passes. Set aside with its reason (comment of NewlineSearch): separators held in a variable or a field (their value is written elsewhere, and no test of today splits a raw read that way). The header of RawNewline1871Tests now says exactly what is covered and what is set aside. The wider ratchet finds no new read in the tests. Tests: RawNewline1873Tests (2).

## 0.1872.0
- Plan global, X-867 : Relecture 0.1871, mineurs M1 et M3, sur le cliquet des fins de ligne (Pending1865Tests). M1 : un découpage sur \n ne passe plus que si le \r ou le Trim vient du découpage lui-même jusqu'à la fin de son instruction (premier « ; » du code, sur sa ligne ou la suivante) : un \r ou un Trim écrit avant le découpage, ou dans l'instruction suivante, ne le laisse plus passer. Écarté avec sa raison (commentaire de Handled) : un Trim ou un \r après le découpage dans la même instruction mais sur une autre expression (il faudrait un analyseur C#, et dans les tests d'aujourd'hui ce qui suit un découpage dans son instruction porte sur ses morceaux). M3 : CodeOnly lit « @$"…" » comme une chaîne verbatim, comme « $@"…" » : une telle chaîne qui finit par une barre oblique inverse ne blanchit plus le reste de la ligne, et une lecture écrite après elle est trouvée. Tests : RawNewline1872Tests (2).
- Tests : RawNewline1872Tests. Verify.ps1 (agent) : 4135/4135, 0 avertissement, 0 erreur ; DLL 0.1872.0.0. Rien à essayer en jeu.
### English
- Review 0.1871, minor M1 and M3, on the line-ending ratchet (Pending1865Tests). M1: a split on \n now passes only when the \r or the Trim comes from the split itself to the end of its statement (first « ; » of the code, on its line or the next): a \r or a Trim written before the split, or in the next statement, no longer lets it pass. Set aside with its reason (comment of Handled): a Trim or a \r after the split in the same statement but on another expression (it would need a C# parser, and in the tests of today what follows a split in its statement works on its pieces). M3: CodeOnly reads « @$"…" » as a verbatim literal, like « $@"…" »: such a literal ending with a backslash no longer blanks the rest of the line, and a read written after it is found. Tests: RawNewline1872Tests (2).

## 0.1871.0
- Plan global, X-866 : Relecture 0.1870, mineurs M1 et M2, sur le cliquet des fins de ligne (Pending1865Tests). M1 : l'exemption « un \n en tête d'extrait se trouve aussi dans \r\n » ne vaut plus que pour Contains, IndexOf, LastIndexOf et EndsWith ; StartsWith et Split sont trouvés avec un \n n'importe où, en chaîne ou en caractère (« Split('\n') ») : un texte CRLF ne commence jamais par \n, et un découpage sur \n laisse un \r au bout de chaque morceau. Un découpage passe s'il tient compte du \r (\r parmi les séparateurs, TrimEnd('\r'), Trim(), TrimEnd() ou TrimEntries). Le cas de RawNewline1870Tests qui inscrivait « un split sur \n seul passe » dit maintenant le contraire. M2 : la classe d'une aide de lecture brute est le type dont le corps la contient (class, struct, record, record struct ou interface, types imbriqués joints par des points), cherché dans le code seul : un « class » écrit dans un commentaire ou une chaîne ne la nomme plus. Passage complet sur les cas voisins, écrits dans RawNewline1871Tests : Replace avec un extrait « …x\n… » (le texte reste tel quel) est trouvé ; une lecture ou une aide écrite dans un commentaire ou une chaîne n'en est plus une ; chaînes verbatim et brutes reconnues. Écartés avec leur raison, dans le commentaire du test : appels Regex (un \n de motif peut être le texte « \\n » d'un JSON, et \s ou \r? avant lui prend le \r), « == » ou Equals contre une lecture entière (aucun cas), lectures autres que File.ReadAllText (textes analysés, pas cherchés), aide imbriquée appelée par son nom court. Le cliquet élargi a trouvé six lectures brutes découpées sur \n (SECURITY.md, sources du plugin, fichiers d'historique écrits par le test) : elles sont normalisées (ReplaceLineEndings), ce qu'elles vérifient ne change pas. Tests : RawNewline1871Tests (6), RawNewline1870Tests, Pending1865Tests.
- Tests : RawNewline1871Tests. Verify.ps1 (agent) : 4133/4133, 0 avertissement, 0 erreur ; DLL 0.1871.0.0. Rien à essayer en jeu.
### English
- Review 0.1870, minor M1 and M2, on the line-ending ratchet (Pending1865Tests). M1: the exemption « a \n that starts the snippet is also in \r\n » now holds for Contains, IndexOf, LastIndexOf and EndsWith only; StartsWith and Split are found with a \n anywhere, as a string or a character (« Split('\n') »): a CRLF text never starts with \n, and a split on \n leaves a \r at the end of each piece. A split passes when it takes the \r into account (\r among the separators, TrimEnd('\r'), Trim(), TrimEnd() or TrimEntries). The RawNewline1870Tests case that wrote down « a split on \n alone passes » now says the opposite. M2: the class of a raw-read helper is the type whose body holds it (class, struct, record, record struct or interface, nested types joined by dots), looked for in the code only: a « class » written in a comment or a string no longer names it. Full pass over the neighbour cases, written in RawNewline1871Tests: Replace with a « …x\n… » snippet (the text stays as it was) is found; a read or a helper written in a comment or a string is no longer one; verbatim and raw literals are recognised. Set aside with their reason, in the test's comment: Regex calls (a pattern's \n may be the text « \\n » of a JSON file, and \s or \r? before it takes the \r), « == » or Equals against a whole read (no case), reads other than File.ReadAllText (texts parsed, not searched), a nested helper called by its short name. The wider ratchet found six raw reads split on \n (SECURITY.md, plugin sources, history files written by the test): they are normalised (ReplaceLineEndings), what they check does not change. Tests: RawNewline1871Tests (6), RawNewline1870Tests, Pending1865Tests.

## 0.1870.0
- Plan global, X-864 : Relecture 0.1868, constat antérieur M2. Le cliquet des fins de ligne (Pending1865Tests) ne voyait que « .Contains(…) » : une lecture brute cherchée par IndexOf, LastIndexOf, StartsWith, EndsWith ou Split avec un extrait « …x\n… » lui échappait (une vérification d'absence « IndexOf(…)<0 » y serait toujours vraie sur le runner en CRLF), comme une lecture chaînée (« File.ReadAllText(…).Trim().Contains(…) ») et une fonction d'aide d'un autre fichier. Il voit maintenant ces six recherches ; les appels chaînés entre la lecture et la recherche, ou entre une variable et sa recherche (« x.Trim().IndexOf(…) ») ; une aide dont la lecture est chaînée ; et une aide d'un autre fichier appelée « Classe.Lecture(…) » quand elle est internal ou public (une aide private ne peut pas être appelée ailleurs). Une normalisation n'importe où dans la chaîne l'exempte toujours. Il a trouvé une lecture brute de plus : DiscoveryHeader1827Tests cherchait « …merged 1\n » au début de merged.txt (fichier écrit par l'outil pendant le test, pas extrait par Git : sans défaut aujourd'hui) ; sa lecture est normalisée. Le CHANGELOG 0.1868 décrivait déjà exactement ce que voyait le cliquet alors. Limites gardées, écartées avec leur raison : arguments entre parenthèses dans une chaîne d'appels sur une variable, lectures par StreamReader ou ReadAllTextAsync, extraits en chaîne verbatim ou brute (aucun cas dans les tests). Tests : RawNewline1870Tests (3), Pending1865Tests, RawNewline1868Tests.
- Tests : RawNewline1870Tests. Verify.ps1 (agent) : 4127/4127, 0 avertissement, 0 erreur ; DLL 0.1870.0.0. Rien à essayer en jeu.
### English
- Review 0.1868, pre-existing finding M2. The line-ending ratchet (Pending1865Tests) saw only « .Contains(…) »: a raw read searched by IndexOf, LastIndexOf, StartsWith, EndsWith or Split with a « …x\n… » snippet escaped it (an absence check « IndexOf(…)<0 » would always be true on the CRLF runner), as did a chained read (« File.ReadAllText(…).Trim().Contains(…) ») and a helper of another file. It now sees these six searches; the calls chained between the read and the search, or between a variable and its search (« x.Trim().IndexOf(…) »); a helper whose read is chained; and a helper of another file called « Class.Read(…) » when it is internal or public (a private helper cannot be called elsewhere). A normalisation anywhere in the chain still lets it pass. It found one more raw read: DiscoveryHeader1827Tests looked for « …merged 1\n » at the start of merged.txt (a file the tool writes during the test, not checked out by Git: no fault today); its read is normalised. The 0.1868 CHANGELOG already described exactly what the ratchet saw then. Limits kept, set aside with their reason: arguments with parentheses in a chain of calls on a variable, reads through StreamReader or ReadAllTextAsync, snippets in verbatim or raw strings (no case in the tests). Tests: RawNewline1870Tests (3), Pending1865Tests, RawNewline1868Tests.
