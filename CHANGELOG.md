# Journal des versions / Changelog

Résumé par version, en français puis `### English` (partie anglaise obligatoire depuis 0.219.0) ; la partie anglaise sert aussi de corps
aux commits et aux notes de release sur GitHub. Preuves citées : docs/evidence/.
Chaque version a été compilée et testée par `scripts/Verify.ps1` ; la validation en jeu est indiquée quand l'utilisateur l'a rapportée.
Ce fichier garde la dernière release et les versions qui suivent ; les plus anciennes sont dans [docs/changelog/](docs/changelog/)
(déplacées par `tools/changelog.py archive`, un fichier par centaine de versions).

### English
- Visual sort of the bags (Items › Organisation, Tensho's button on the inventory, Bank › Character): a zone over several bags also fills them in the order 1, 3, 2, 4 (X-321, user report of 11/14, test T-0.1172-1, captures of the game's inventory and Tensho's bank). - For players: Bag sorting: a zone that covers several bags now fills them in the game's reading order (left column first), like the rest.

## 0.1321.0
- Plan global, X-322 : Carte, suite de 0.1320 : sur la carte que le jeu a construite, c'est sa propre liste qui décide des icônes à déblocage (X-322). Relevé en jeu de 0.1320 (dalamud.log du 14/11 11:39:48, Mor Dhona, docs/evidence/0.1320-map-marker-unlock.md) : l'icône du signalement (bit 44) n'est pas dans la liste du jeu, cause confirmée ; mais la lecture du bit par IsUnlockLinkUnlocked ne suit le jeu que sur 8 icônes de 9 : l'icône du bit 83 (60467, X 28.0 Y 13.7 environ) est dessinée par le jeu alors que cette lecture la dit verrouillée, et 0.1320 la cachait. Désormais : sur la carte construite par le jeu (AgentMap.CurrentMapId), une icône à bit est dessinée si le jeu la liste (même icône, même pixel ; MapMarkerUnlock.GameList, gardée tant qu'elle ne change pas) ; sur une autre carte, la lecture du bit (sa seule erreur vue cache, ne montre jamais une icône absente) ; inconnu : cachée. L'auto-contrôle « map icon unlocks » dit l'accord de la lecture du bit (« agrees on N of M ») sans être suspect, puisque la carte suit la liste du jeu. Test MapMarkerGameList1321 (3).
- Tests : MapMarkerGameList1321Tests. Verify.ps1 (agent) : 2469/2469, 0 avertissement, 0 erreur ; DLL 0.1321.0.0. Non validé en jeu.
### English
- Map, follow-up of 0.1320: on the map the game has built, its own list decides the icons with an unlock (X-322). Reading in the game of 0.1320 (dalamud.log of 11/14 11:39:48, Mor Dhona, docs/evidence/0.1320-map-marker-unlock.md): the icon of the report (bit 44) is not in the game's list, cause confirmed; but the bit's reading through IsUnlockLinkUnlocked follows the game on 8 icons of 9 only: the icon of bit 83 (60467, about X 28.0 Y 13.7) is drawn by the game while that reading says locked, and 0.1320 hid it. Now: on the map the game has built (AgentMap.CurrentMapId), an icon with a bit is drawn when the game lists it (same icon, same pixel; MapMarkerUnlock.GameList, kept while unchanged); on another map, the bit's reading (its one error seen hides, never shows a missing icon); unknown: hidden. The « map icon unlocks » self-check says the bit reading's agreement (« agrees on N of M ») without being suspect, since the map follows the game's list. Test MapMarkerGameList1321 (3).

## 0.1320.0
- Plan global, X-322 : Carte : une icône fixe du jeu qui n'apparaît qu'après un déblocage n'est plus dessinée avant (X-322, signalement de l'utilisateur du 14/11 à Mor Dhona, essai T-0.829-1 : icône « Échangeur » seule en X 21.4 Y 5.5, absente de la carte du jeu). Ce n'était plus Cristiana (écartée depuis 0.1307, journal « 11 shown, 2 left out ») mais l'icône fixe MapMarker 108.46 (icône 60935), dont la colonne MapMarkerUnlockedBit vaut 44 : le jeu ne la dessine qu'une fois ce déblocage acquis ; 446 icônes du jeu ont un tel bit. Tensho lit ce bit (MapIconMarker.UnlockBit), lit en jeu toutes les 2 s les bits débloqués (UIState.IsUnlockLinkUnlocked, fonction résolue vérifiée) et ne dessine l'icône, sur la carte et dans la liste des marchands, que si son bit est débloqué ; inconnu (hors du jeu) : cachée (MapMarkerUnlock.Visible). Auto-contrôle « map icon unlocks » et ligne de journal « Map icon unlocks on map N » : pour la carte construite par le jeu, chaque icône à bit, présente ou non dans la liste du jeu (AgentMap.MapMarkers, position monde × 16), contre son bit ; « DISAGREE » si la lecture du bit ne suit pas le jeu (preuve docs/evidence/0.1320-map-marker-unlock.md). Test MapMarkerUnlock1320 (4).
- Pour les joueurs : Carte : les icônes que le jeu ne montre qu'une fois débloquées (certains échanges) n'apparaissent plus avant que vous les ayez débloquées.
- Tests : MapMarkerUnlock1320Tests. Verify.ps1 (agent) : 2466/2466, 0 avertissement, 0 erreur ; DLL 0.1320.0.0. Non validé en jeu.
### English
- Map: a fixed game icon that appears only after an unlock is no longer drawn before it (X-322, user report of 11/14 at Mor Dhona, test T-0.829-1: an icon « Exchange » alone at X 21.4 Y 5.5, absent from the game's map). It was no longer Cristiana (left out since 0.1307, log « 11 shown, 2 left out ») but the fixed icon MapMarker 108.46 (icon 60935), whose column MapMarkerUnlockedBit is 44: the game draws it only once that unlock is gained; 446 icons of the game have such a bit. Tensho reads that bit (MapIconMarker.UnlockBit), reads in the game every 2 s the unlocked bits (UIState.IsUnlockLinkUnlocked, resolved function checked) and draws the icon, on the map and in the vendor list, only when its bit is unlocked; unknown (outside the game): hidden (MapMarkerUnlock.Visible). Self-check « map icon unlocks » and log line « Map icon unlocks on map N »: for the map the game has built, each icon with a bit, listed or not in the game's list (AgentMap.MapMarkers, world position × 16), against its bit; « DISAGREE » when the bit's reading does not follow the game (evidence docs/evidence/0.1320-map-marker-unlock.md). Test MapMarkerUnlock1320 (4).
- For players: Map: icons the game only shows once unlocked (some exchange shops) no longer appear before you unlock them.

## 0.1319.0
- Plan global, X-320 : Journal des gils : moins de variations dans « Autre » (X-320, signalement de l'utilisateur du 14/11, essai T-0.351-1). Relevé (docs/evidence/0.1319-gil-other.md) : depuis 0.775 (07/11), aucune dépense n'est plus classée « Autre » (achat, vente, réparation et téléportation ont leur catégorie) ; les 10 446 gils dépensés « Autre » de la capture du 13/11 sont des lignes plus anciennes, gardées telles quelles. Les gains « Autre » relevés dans dalamud.log ont trois causes, maintenant classées : récompense d'ALÉA (fenêtre FateReward), rubrique du carnet d'objectifs achevée (message du jeu LogMessage 3780) et gils d'un monstre vaincu (message 557, seulement quand aucune fenêtre ni autre message ne dit autre chose). Messages lus par identifiant (toutes langues), 5 s ; ces trois catégories seulement pour un gain. Nouvelles catégories ALÉA (récompenses), Monstres vaincus, Carnet d'objectifs, ajoutées à la fin (numéros enregistrés inchangés). « Autre » garde les cas sans fenêtre ni message connus (par exemple +12 000 après un écran de chargement). Mode développeur : la ligne « Gil other » dit aussi les messages entendus. Test GilOther1319 (3).
- Pour les joueurs : Journal des gils : les récompenses d'ALÉA, les gils des monstres vaincus et les récompenses du carnet d'objectifs ont leur catégorie au lieu de « Autre ».
- Tests : GilOther1319Tests. Verify.ps1 (agent) : 2462/2462, 0 avertissement, 0 erreur ; DLL 0.1319.0.0. Non validé en jeu.
### English
- Gil journal: fewer changes in « Other » (X-320, user report of 11/14, test T-0.351-1). Findings (docs/evidence/0.1319-gil-other.md): since 0.775 (11/07) no spending is classified « Other » any more (buying, selling, repair and teleport have their category); the 10,446 gil spent « Other » of the 11/13 capture are older entries, kept as they are. The « Other » gains found in dalamud.log have three causes, now classified: a FATE's reward (window FateReward), a challenge log entry done (game message LogMessage 3780) and a defeated monster's gil (message 557, only when no window nor other message tells otherwise). Messages read by id (any language), 5 s; these three categories for a gain only. New categories FATEs (rewards), Defeated monsters, Challenge log, added last (saved numbers unchanged). « Other » keeps the cases with no known window or message (e.g. +12,000 after a loading screen). Developer mode: the « Gil other » line also says the messages heard. Test GilOther1319 (3).
- For players: Gil journal: FATE rewards, gil from defeated monsters and challenge log rewards get their own categories instead of « Other ».

## 0.1318.0
- Plan global, X-323 : Eurêka et Bozja › Météo et nuit : chaque monstre retrouve sa prochaine fenêtre (X-323, signalement de l'utilisateur du 14/11 sur 0.1317 : toutes les lignes des quatre zones disaient « Aucune dans les 28 prochaines heures », monstres « nuit » compris). Cause : la page demandait 72 périodes d'un coup au catalogue météo, qui en donne 24 au plus (WeatherCatalog.Forecast lève une exception au-delà) ; l'exception était rattrapée et la page restait sans prévision depuis 0.1241. EurekaNotoriousBoard.Forecast demande les 72 périodes (environ 28 h) par tranches de 24, contiguës. L'auto-contrôle « Eureka notorious monsters » calcule aussi en jeu les fenêtres depuis le catalogue lu (EurekaNotoriousBoard.ForecastCheck) : suspect si un monstre « nuit » n'a pas de fenêtre dans les 70 min réelles. Test EurekaForecast1318 (3), de comportement sur une prévision connue (tirage du jeu, WeatherCatalog.Target, sur une table de météo faite pour le test).
- Pour les joueurs : Eurêka : les fenêtres de météo et de nuit des monstres notoires s'affichent de nouveau au lieu de « Aucune dans les 28 prochaines heures ».
- Tests : EurekaForecast1318Tests. Verify.ps1 (agent) : 2459/2459, 0 avertissement, 0 erreur ; DLL 0.1318.0.0. Non validé en jeu.
### English
- Eureka and Bozja › Weather and night: each monster has its next window again (X-323, user report of 11/14 on 0.1317: every row of the four zones said « none in the next 28 hours », night monsters included). Cause: the page asked the weather catalogue for 72 periods at once, and it gives 24 at most (WeatherCatalog.Forecast throws above); the exception was caught and the page had no forecast since 0.1241. EurekaNotoriousBoard.Forecast asks for the 72 periods (about 28 hours) 24 at a time, contiguous. The « Eureka notorious monsters » self-check also computes the windows in the game from the catalogue read (EurekaNotoriousBoard.ForecastCheck): suspect when a night monster has no window within 70 real minutes. Test EurekaForecast1318 (3), a behaviour test on a known forecast (the game's roll, WeatherCatalog.Target, on a weather table made for the test).
- For players: Eureka: the weather and night windows of notorious monsters show again instead of « none in the next 28 hours ».
