## 0.1302.0
- Plan global, X-284 : Points mineurs de la relecture du bloc 0.1278 (X-284). M1 : les plans d'équipe du Dédale bestial s'enregistraient sur le fil du jeu, pendant le dessin ; depuis 0.1275, AtomicFile réessaie jusqu'à environ 750 ms quand un autre programme tient le fichier (un antivirus qui le lit), ce qui pouvait geler le jeu autant (R07). Le texte est maintenant fait sur place et le fichier écrit hors du fil du jeu (BeastTeams.SaveLater, par un BackgroundWriter, dans l'ordre ; la dernière écriture attendue à la fermeture). Test de comportement : fichier tenu par un autre, l'appelant repart tout de suite, les plans sont écrits une fois le fichier libre, les derniers gardés, aucun fichier temporaire laissé. M2 : les images de référence n'avaient pas l'état « erreur » des pages ; point d'accroche dans le plugin (MainWindow.ForgetSheetPages : les pages qui lisent leurs feuilles une fois les oublient) et l'application de bureau donne pour deux images des feuilles illisibles, comme après une mise à jour du jeu (R08), puis les rend : AlliedSocieties-error et RelicWeapons-error ; une image d'erreur qui ne montre pas d'erreur, ou qui attend encore, est refusée (ReferenceErrors.ShownFor). M4 : une entrée de quarantaine fautive fait échouer le passage des tests, mais la dernière ligne disait quand même « N/N passed » ; elle dit maintenant que le passage a échoué (ParallelTests.CountLine). M3 (une page jamais immobile arrête maintenant la publication) est dans l'outil de l'agent.
- Pour les joueurs : Dédale bestial : les plans d'équipe s'enregistrent sans jamais faire attendre le jeu.
- Tests : ReviewMinor1302Tests. Verify.ps1 (agent) : 2412/2412, 0 avertissement, 0 erreur ; DLL 0.1302.0.0. Non validé en jeu.
### English
- Minor points of the review of block 0.1278 (X-284). M1: the beastmaster's team plans were saved on the game's thread, while drawing; since 0.1275 AtomicFile tries again for up to about 750 ms when another program holds the file (an antivirus reading it), which could freeze the game as long (R07). The text is now made on the spot and the file written off the game's thread (BeastTeams.SaveLater, through a BackgroundWriter, in order; the last write waited for at unload). Behaviour test: a file held by another, the caller goes on at once, the plans are written once the file is free, the last ones kept, no temporary file left. M2: the reference pictures lacked the pages' « error » state; a hook in the plugin (MainWindow.ForgetSheetPages: the pages that read their sheets once forget them) and the desktop application gives two pictures sheets that cannot be read, as after a game update (R08), then gives them back: AlliedSocieties-error and RelicWeapons-error; an error picture that shows no error, or still waits, is refused (ReferenceErrors.ShownFor). M4: a wrong quarantine entry fails the test run, but the last line still said « N/N passed »; it now says the run failed (ParallelTests.CountLine). M3 (a page never still now stops the publication) is in the agent's tool.
- For players: Beastmaster: the team plans are saved without ever pausing the game.

Les images qui suivaient l'heure (météo, rappels, pêche en mer, jardin d'essai) sont refaites à l'heure fixe et attendent l'accord de l'utilisateur.

### English
- Reference pictures at a fixed time (X-282, review of block 0.1278, I2): the pages that follow the hour or the day (weather forecasts, reminder countdowns, the trial garden, the ocean fishing timetable, the next draw) changed from one capture to the next, and their pictures had been given tolerances far above the measure (weather: 25 % of changed area allowed for 0.09 % measured), which would have let a real change through. ## 0.1300.0
- Plan global, X-285 : Images de référence sans erreur (X-285, vu par l'utilisateur dans la galerie le 13/11) : plusieurs pages de l'application de bureau montraient une erreur au lieu de leur contenu (« Les feuilles des peuples n'ont pas pu être lues… ») ou un chargement sans fin, et les images de référence protégeaient cet état. Liste dressée par les images elles-mêmes : chaque image note les clés de texte d'erreur ou d'attente de l'image prise (LocalizationManager.KeyRead, Desktop/ReferenceErrors.cs) ; 7 pages en erreur (Peuples alliés, Grandes Compagnies, Félicité insulaire, Livraisons particulières, Carnaval masqué, Armes reliques, Pêche en mer) et 11 en attente sans fin. Cause : les fonctions qui lisent seulement les feuilles du jeu n'étaient données qu'en jeu (Plugin.cs). Elles sont maintenant données par une seule méthode, MainWindow.UseSheetLoaders, appelée par le plugin et par l'application de bureau (lexique, peuples, Grandes Compagnies, île, livraisons, carnaval, reliques, pêche en mer, aléas, contenus de terrain, donjons profonds) ; l'horaire de la pêche en mer passe dans Gathering/OceanScheduleLoader. Sans la lecture du personnage, la page Grandes Compagnies charge ses feuilles avec les noms de grades habituels. Là où une page montre ce que le jeu détient du joueur (peuples, Grandes Compagnies, île, livraisons, carnaval, livre des reliques), l'application dit « Lu dans le jeu » au lieu de rien. Les pages dont les données viennent d'un lecteur du jeu (collections, magie bleue, quêtes, Triple Triade, dresseur, livraisons spéciales, découvertes) disent « Lu dans le jeu » dans l'application au lieu d'un chargement sans fin. Une image dessine la page tant qu'elle attend encore (20 s au plus) ; la publication refuse une image qui montre une erreur ou une attente sans fin (images.py). Les images de référence sont refaites et attendent l'accord de l'utilisateur.
- Pour les joueurs : Application de bureau : pêche en mer, aléas, contenus de terrain, donjons profonds et armes reliques montrent leur contenu ; les pages qui demandent le jeu disent « Lu dans le jeu » au lieu d'une erreur ou d'un chargement sans fin.
- Tests : ReferenceErrors1300Tests. Verify.ps1 (agent) : 2405/2405, 0 avertissement, 0 erreur ; DLL 0.1300.0.0. Non validé en jeu.
### English
- Reference pictures without errors (X-285, seen by the user in the gallery on 13/11): several pages of the desktop application showed an error instead of their content (« The allied societies' sheets could not be read… ») or a load that never ended, and the reference pictures protected that state. The list made by the pictures themselves: each picture notes the keys of the error or waiting texts of the frame taken (LocalizationManager.KeyRead, Desktop/ReferenceErrors.cs); 7 pages in error (Allied societies, Grand Companies, Island Sanctuary, Custom deliveries, Masked Carnivale, Relic weapons, Ocean fishing) and 11 waiting forever. Cause: the functions that read only the game's sheets were given in the game only (Plugin.cs). They are now given by one method, MainWindow.UseSheetLoaders, called by the plugin and the desktop application (lexicon, allied societies, Grand Companies, island, deliveries, carnivale, relics, ocean fishing, fates, field content, deep dungeons); the ocean fishing timetable moves into Gathering/OceanScheduleLoader. Without the character's reading, the Grand Companies page loads its sheets with the grades' usual names. Where a page shows what the game holds of the player (allied societies, Grand Companies, island, deliveries, carnivale, relic book), the application says « Read in the game » instead of nothing. The pages whose data comes from a reader of the game (collections, blue magic, quests, Triple Triad, beastmaster, special deliveries, discoveries) say « Read in the game » in the application instead of a load that never ends. A picture draws the page while it still waits (20 s at most); the publication refuses a picture that shows an error or a wait that never ends (images.py). The reference pictures are taken again and wait for the user's approval.
- For players: Desktop app: ocean fishing, fates, field content, deep dungeons and relic weapons show their content; the pages that need the game say « Read in the game » instead of an error or an endless load.
