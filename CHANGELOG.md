# Journal des versions / Changelog

Résumé par version, en français puis `### English` (partie anglaise obligatoire depuis 0.219.0) ; la partie anglaise sert aussi de corps
aux commits et aux notes de release sur GitHub. Preuves citées : docs/evidence/.
Chaque version a été compilée et testée par `scripts/Verify.ps1` ; la validation en jeu est indiquée quand l'utilisateur l'a rapportée.
Ce fichier garde la dernière release et les versions qui suivent ; les plus anciennes sont dans [docs/changelog/](docs/changelog/)
(déplacées par `tools/changelog.py archive`, un fichier par centaine de versions).

## 0.1170.0
- Plan global, X-186 : Découvertes partagées, format d'échange v3 : le plugin ignore désormais un champ qu'il ne connaît pas quand il lit le fichier commun (v3/), au lieu de refuser la ligne ; un champ ajouté plus tard ne demandera donc pas de version 4 (X-186, choix de l'utilisateur du 12/11, constat N31 de la revue de la nuit). Une ligne qui contient Own ou Key (la part propre d'un joueur, seuls champs liés à la vie privée), quelle que soit la casse, reste refusée en entier. L'outil de fusion reste strict sur les gists des joueurs (tout autre nom fait refuser la ligne). Le README de community-discoveries le dit, en anglais et en français.
- Tests : ExchangeFields1170Tests. Verify.ps1 (agent) : 2016/2016, 0 avertissement, 0 erreur ; DLL 0.1170.0.0. Rien à essayer en jeu.
### English
- Shared discoveries, v3 exchange format: the plugin now ignores a field it does not know when it reads the common file (v3/), instead of refusing the line; a field added later will therefore not need a version 4 (X-186, user's choice of 11/12, finding N31 of the night review). A line holding Own or Key (a player's own part, the only privacy-related fields), in any case, is still refused whole. The merge tool stays strict on the players' gists (any other name refuses the line). The community-discoveries README says so, in English and French.

## 0.1169.0
- Plan global, X-182 : Données du joueur : deux clients du jeu, ou deux versions du plugin le même jour, ne s'effacent plus leurs données (X-182, en partie ; constats N3, N4, N9, N11, N27 et N28 de la revue de la nuit du 12/11). Voyages des sous-marins et aéronefs : chaque enregistrement n'écrit plus que les voyages changés, par leur clé, sans jamais vider la table ; deux clients sur deux compagnies gardent les voyages l'un de l'autre ; les voyages de plus de 180 jours (et au-delà de 5 000) s'enlèvent à part. Hauts faits : chaque relevé ne remplace celui enregistré que s'il est plus récent ; un client resté ouvert ne reprend plus à l'autre ce qu'il a vu depuis. Un ancien fichier (voyages, hauts faits, journal des gils) réécrit après la conversion par une version plus ancienne encore lancée est fusionné, plus mis de côté sans être lu ; une copie déjà mise de côté n'est pas relue. La conversion lit l'ancien fichier dans une transaction immédiate : un second client qui charge en même temps attend, puis voit tout. Un ancien fichier n'est déplacé qu'une fois la base écrite sur le disque (point de contrôle complet), sinon au démarrage suivant. Conversion des découvertes : nom temporaire propre à chaque conversion, jamais effacé par une autre instance ; la première base complète reste. Reste de X-182 : la banque (fichier réécrit après la conversion, décision « inchangé » prise sur la mémoire) et un fichier des découvertes réécrit après la conversion.
- Tests : ConcurrentData1169Tests. Verify.ps1 (agent) : 2013/2013, 0 avertissement, 0 erreur ; DLL 0.1169.0.0. Non validé en jeu.
### English
- Player data: two game clients, or two versions of the plugin the same day, no longer erase each other's data (X-182, in part; findings N3, N4, N9, N11, N27 and N28 of the night review of 11/12). Submarine and airship voyages: each save writes only the voyages that changed, by their key, never emptying the table; two clients on two companies keep each other's voyages; voyages older than 180 days (and beyond 5,000) are removed apart. Achievements: each reading replaces the saved one only when newer; a client left open no longer takes back from the other what it saw since. A file of before (voyages, achievements, gil journal) written again after the conversion by an older version still running is merged, no longer set aside unread; a copy already set aside is not read again. The conversion reads the file of before in an immediate transaction: a second client loading at the same time waits, then sees everything. A file of before is moved only once the database is written to the disk (full checkpoint), else at the next start. Conversion of the discoveries: a temporary name of its own for each conversion, never removed by another instance; the first whole base stays. Left of X-182: the bank (file written again after the conversion, the « unchanged » decision taken from memory) and a discoveries file written again after the conversion.

## 0.1164.0
- Plan global, X-177 : Saccades (X-177, étape 2) : les réglages s'enregistrent hors du fil du jeu. Les lignes de mesure de 0.1162 montrent que l'enregistrement des réglages par Dalamud prenait 64 à 71 ms sur le fil du jeu à chaque fois, et 371 à 648 ms la première fois après un chargement, alors que mettre les réglages en texte prend environ 2 ms (mesuré sur une copie des réglages de l'utilisateur, 63 Ko). Désormais, seul le texte est fait sur le fil du jeu ; une copie en est refaite à part, vérifiée (elle doit redonner exactement le même texte, sinon elle n'est pas écrite) et enregistrée hors du fil du jeu. Une seule écriture à la fois, dans l'ordre, la dernière en date seulement : une écriture ancienne ne passe jamais après une plus récente. Au moindre doute (copie différente, écriture refusée), Tensho revient à l'ancienne façon, sur le fil du jeu, et le dit une fois dans le journal. À l'arrêt du plugin, ce qui reste est écrit. Le préparateur du texte est chauffé au chargement hors du fil du jeu, pour que le premier enregistrement ne soit pas lent. Les trois autres enregistrements directs (sources des alarmes, zones météo confirmées, demande du jour de la Grande Compagnie) passent par le même chemin. Les autres saccades relevées aujourd'hui (lecteurs, barre de rappel) n'arrivent qu'au chargement du plugin.
- Tests : SettingsSaver1164Tests. Verify.ps1 (agent) : 1993/1993, 0 avertissement, 0 erreur ; DLL 0.1164.0.0. Non validé en jeu.
### English
- Hitches (X-177, step 2): the settings are saved off the game's thread. The measuring lines of 0.1162 show that Dalamud's save of the settings took 64 to 71 ms on the game's thread each time, and 371 to 648 ms the first time after a load, while turning the settings into text takes about 2 ms (measured on a copy of the user's settings, 63 KB). Now only the text is made on the game's thread; a copy of it is rebuilt apart, checked (it must give back exactly the same text, otherwise it is not written) and saved off the game's thread. One write at a time, in order, the latest only: an older write never lands after a newer one. At the slightest doubt (different copy, refused write), Tensho goes back to the old way, on the game's thread, and says so once in the log. When the plugin stops, what is left is written. The text maker is warmed at load off the game's thread, so the first save is not slow. The three other direct saves (alarm sources, confirmed weather zones, today's Grand Company request) go the same way. The other hitches seen today (readers, reminder bar) only happen when the plugin loads.
