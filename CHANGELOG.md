# Journal des versions / Changelog

Résumé par version, en français puis `### English` (partie anglaise obligatoire depuis 0.219.0) ; la partie anglaise sert aussi de corps
aux commits et aux notes de release sur GitHub. Preuves citées : docs/evidence/.
Chaque version a été compilée et testée par `scripts/Verify.ps1` ; la validation en jeu est indiquée quand l'utilisateur l'a rapportée.
Ce fichier garde la dernière release et les versions qui suivent ; les plus anciennes sont dans [docs/changelog/](docs/changelog/)
(déplacées par `tools/changelog.py archive`, un fichier par centaine de versions).

## 0.1183.0

- Tests : MapNotice1183Tests. Verify.ps1 (agent) : 2057/2057, 0 avertissement, 0 erreur ; DLL 0.1183.0.0. Non validé en jeu.
### English
- The map on M says so (X-253, « first player » review of 11/12, finding B6; user's choice: Tensho's map stays on M by default, but Tensho says so). The first time the M key opens Tensho's map instead of the game's, a chat line says so and where to turn it off (Settings › Map › « Replace the game map (M key) »); once only, remembered in the settings. New FAQ question « M opens another map: how do I get the game's back? ». The answer to « Does Tensho play for me? » now names the two settings that act without a click: the map on M (on by default) and wearing the title chosen for a job (off by default).

## 0.1182.0
- Plan global, X-252 : Déclaration sur l'IA et notes de release vraies (X-252, revue « premier joueur » du 12/11, constats B5 et G2 ; choix de l'utilisateur : le texte seulement, releases inchangées). README et CONTRIBUTING (deux langues) ne disent plus que les releases attendent la validation en jeu ; ils décrivent la pratique : chaque release est compilée et testée automatiquement, chargée une fois en jeu avec son auto-contrôle (ce que disent ses notes), les essais détaillés viennent ensuite en campagnes, et le CHANGELOG dit pour chaque version si elle a été validée en jeu. Les notes que voit un joueur (installateur de Dalamud, release GitHub) sont désormais la ligne « Pour les joueurs » de chaque version depuis la dernière release, en anglais puis en français, sans identifiants internes ni changements du mode développeur, avec un lien vers le CHANGELOG ; une version sans cette ligne ne change rien de visible. « (X-121) » retiré du README. Le script de release refait aussi les index produits (preuves, liens) avant son commit de repo.json, pour ne plus laisser d'index périmé après une release.
- Pour les joueurs : Les notes de version sont désormais courtes et en mots de joueur ; le détail reste dans le journal des versions.
- Tests : PlayerNotes1182Tests. Verify.ps1 (agent) : 2055/2055, 0 avertissement, 0 erreur ; DLL 0.1182.0.0. Rien à essayer en jeu.
### English
- True AI disclosure and release notes (X-252, « first player » review of 11/12, findings B5 and G2; user's choice: the text only, releases unchanged). README and CONTRIBUTING (both languages) no longer say releases wait for in-game validation; they describe the practice: each release is built and tested automatically, loaded once in game with its self-check (which its notes say), the detailed in-game tests come after in campaigns, and the CHANGELOG says for each version whether it was validated in game. The notes a player sees (Dalamud's installer, GitHub release) are now each version's « For players » line since the last release, in English then French, without internal identifiers nor developer-mode changes, with a link to the CHANGELOG; a version without that line changes nothing visible. « (X-121) » removed from the README. The release script also writes the produced indexes (evidence, links) again before its repo.json commit, so a release no longer leaves an index out of date.
- For players: Release notes are now short and in players' words; the details stay in the changelog.

The warning before « Connect GitHub » and the Credits page now say that no character name or id is sent, but that a fish caught or a bite carries the character's exact spot (with the day, it tells where you fished that day); the Credits page says the common base is read without an account, on « Exchange now » or with the automatic exchange. ## 0.1179.0
- Plan global, X-189 : Île de Lunule (X-189, demande de l'utilisateur du 12/11) : alertes des confrontations critiques et des ALÉA de l'île, activées par défaut (interrupteur dans l'onglet de l'île, page Eurêka et Bozja). Quand une confrontation critique ouvre ses inscriptions, une ligne dans le chat et dans l'application de bureau donne son nom, le temps restant et son lieu (zone et coordonnées du repère du jeu) ; un ALÉA qui commence sur l'île de même (nom, niveau, temps restant, lieu) ; le son des alarmes s'il est activé. Chacun est dit une fois tant qu'il dure. Rien pendant un combat (DEC-041) : ce qui s'est ouvert pendant ce temps est dit à la fin du combat, s'il est encore ouvert ; le panneau de l'île se cache aussi pendant un combat. Les confrontations viennent du conteneur DynamicEvent du directeur de l'île, lu avec l'état de l'île une fois par seconde ; le mode développeur écrit ce conteneur dans le journal (« Reading occultevents ») pour vérifier le sens du temps restant à chaque étape. Preuve : docs/evidence/0.1179-occult-alerts.md.
- Pour les joueurs : Île de Lunule : alertes dans le chat quand une confrontation critique ouvre ses inscriptions ou qu'un ALÉA commence, avec le lieu et le temps restant ; rien pendant un combat.
- Tests : OccultAlerts1179Tests. Verify.ps1 (agent) : 2046/2046, 0 avertissement, 0 erreur ; DLL 0.1179.0.0. Non validé en jeu.
### English
- Occult Crescent (X-189, user request of 11/12): alerts for the island's critical engagements and FATEs, on by default (switch in the island's tab, Eureka and Bozja page). When a critical engagement opens its registration, a line in the chat and in the desktop application gives its name, the time left and its place (zone and coordinates of the game's marker); a FATE starting on the island likewise (name, level, time left, place); the alarms' sound if it is on. Each one is said once while it lasts. Nothing during a fight (DEC-041): what opened meanwhile is said once the fight is over, if still open; the island panel also hides during a fight. The engagements come from the DynamicEvent container of the island's director, read with the island's state once a second; developer mode writes that container to the log (« Reading occultevents ») to check what the time left means at each stage. Evidence: docs/evidence/0.1179-occult-alerts.md.
- For players: Occult Crescent: chat alerts when a critical engagement opens its registration or a FATE starts, with the place and the time left; nothing during a fight.
