# Journal des versions / Changelog

Résumé par version, en français puis `### English` (partie anglaise obligatoire depuis 0.219.0) ; la partie anglaise sert aussi de corps
aux commits et aux notes de release sur GitHub. Preuves citées : docs/evidence/.
Chaque version a été compilée et testée par `scripts/Verify.ps1` ; la validation en jeu est indiquée quand l'utilisateur l'a rapportée.
Ce fichier garde la dernière release et les versions qui suivent ; les plus anciennes sont dans [docs/changelog/](docs/changelog/)
(déplacées par `tools/changelog.py archive`, un fichier par centaine de versions).

## 0.1139.0
- Plan global, X-173 : Journal des gils en SQLite (X-173, première famille ; choix de l'utilisateur du 12/11) : il passe dans le fichier de données du joueur, TenshoData.db, une base SQLite à la racine du dossier de configuration du plugin, où entreront les autres familles une à une (choix provisoire D-141 : les découvertes gardent leur propre fichier pour l'instant). Le journal d'un personnage est enregistré en entier en une seule transaction (au plus une fois par minute) : un arrêt au milieu laisse l'enregistrement d'avant entier. Le fichier d'avant (GilJournal/<id>.json) est converti la première fois que son personnage est chargé (ses entrées et une marque « converti » écrites ensemble), puis déplacé, jamais effacé, dans GilJournal/before-sqlite-<date>/ ; un fichier d'avant illisible reste en place et le journal n'est pas réécrit, comme avant ; un fichier de données abîmé ou d'une version plus récente n'est jamais remplacé (journal indisponible pour la séance) ; si le fichier de données ne peut pas être créé, les fichiers JSON restent utilisés comme avant. Le lien local n'envoie plus l'avis « gil-journal » (l'application de bureau ne lit pas encore ce journal). SECURITY.md (deux moitiés) décrit le nouveau fichier.
- Tests : GilJournalSqlite1139Tests. Verify.ps1 (agent) : 1907/1907, 0 avertissement, 0 erreur ; DLL 0.1139.0.0. Non validé en jeu.
### English
- Gil journal in SQLite (X-173, first family; user's choice of 12/11): it moves into the player's data file, TenshoData.db, one SQLite database at the root of the plugin's configuration folder, where the other families will enter one at a time (provisional choice D-141: the discoveries keep their own file for now). A character's journal is saved whole in one transaction (at most once a minute): a stop in the middle leaves the save of before whole. The file of before (GilJournal/<id>.json) is converted the first time its character is loaded (its entries and a « converted » mark written together), then moved, never removed, into GilJournal/before-sqlite-<date>/; an unreadable file of before stays in place and the journal is not written over, as before; a damaged data file or one of a newer version is never replaced (journal unavailable for the session); when the data file cannot be created, the JSON files stay in use as before. The local link no longer sends the « gil-journal » notice (the desktop application does not read that journal yet). SECURITY.md (both halves) describes the new file.

## 0.1138.0
- Plan global, X-175 : Échange GitHub, préparation de la GitHub App (X-175, première partie) : une seule bascule (Discoveries/GitHubSignIn.cs) entre l'application OAuth d'aujourd'hui (droits gist et public_repo) et une GitHub App aux droits minimaux (tickets de ce seul dépôt, gists du joueur), dont l'identifiant est encore vide : tant qu'il l'est, rien ne change. Une fois l'App en place : connexion par appareil sans droit demandé, jeton de 8 heures renouvelé avant un envoi (jeton de renouvellement chiffré par Windows comme le jeton, jamais dans une sauvegarde ni le journal), renouvellement refusé : déconnexion propre et message ; App non installée sur le dépôt : message clair, rien d'autre envoyé ; un ancien jeton OAuth est oublié et le joueur reconnecte. L'identifiant du gist est noté avant le ticket (un ticket refusé ne crée plus un deuxième gist). Gist toujours secret. SECURITY.md (deux moitiés) dit ce qui vaut aujourd'hui et ce qui vaudra avec l'App. Reste : la création de l'App par l'utilisateur (guide pas à pas fourni), puis son identifiant dans une version.
- Tests : GitHubApp1138Tests. Verify.ps1 (agent) : 1899/1899, 0 avertissement, 0 erreur ; DLL 0.1138.0.0. Non validé en jeu.
### English
- GitHub exchange, GitHub App preparation (X-175, first part): one switch (Discoveries/GitHubSignIn.cs) between today's OAuth app (gist and public_repo scopes) and a GitHub App with least permissions (issues of this repository only, the player's gists), whose client id is still empty: while it is, nothing changes. Once the App is in place: device sign-in with no scope asked, an 8-hour token refreshed before an upload (refresh token protected by Windows like the token, never in a backup or the log), refresh refused: clean disconnection and a message; App not installed on the repository: a clear message, nothing else sent; an old OAuth token is forgotten and the player connects again. The gist id is noted before the issue (a refused issue no longer creates a second gist). The gist stays secret. SECURITY.md (both halves) says what holds today and what will hold with the App. Left: the user creates the App (step-by-step guide provided), then its id in a version.

## 0.1137.0
- Plan global, X-174 : Échange des découvertes, format v3 (X-174, DEC-052 qui remplace DEC-042 sur le format) : le fichier commun devient community-discoveries/v3/, un index.json et un fichier kind-NN.jsonl.gz par sorte (JSON par lignes, compressé), chacun avec son empreinte SHA-256 et sa taille. Le plugin lit d'abord l'index, ne télécharge que les sortes dont l'empreinte a changé, vérifie empreinte et taille avant de lire, lit en flux avec des bornes (32 Mo compressés, 256 Mo décompressés, 64 Ko par ligne, 200 000 faits par sorte) ; une ligne mauvaise est écartée et comptée, plus de 5 % refusent le fichier ; l'empreinte d'une sorte n'est notée qu'une fois ses faits enregistrés (règle de X-166). Tant que v3 manque ou ne se lit pas, l'ancien discoveries.json (v2) est lu comme avant. Le gist du joueur devient lui aussi un index et un fichier par sorte (construits de ce que vous avez relevé, X-167) ; l'ancien fichier unique en est retiré au premier envoi. L'outil de fusion lit les gists v2 et v3, reconstruit v2 et v3 (sortie identique pour les mêmes faits ; auto-test 25 cas) ; le jeu v3 du dépôt est construit depuis le ticket n° 43 (24 sortes, 1 967 faits). README des découvertes, SECURITY.md et DECISIONS dans les deux moitiés.
- Tests : ExchangeV31137Tests. Verify.ps1 (agent) : 1892/1892, 0 avertissement, 0 erreur ; DLL 0.1137.0.0. Non validé en jeu.
### English
- Discoveries exchange, v3 format (X-174, DEC-052 replacing DEC-042 on the format): the common file becomes community-discoveries/v3/, an index.json and one kind-NN.jsonl.gz file per kind (JSON lines, compressed), each with its SHA-256 hash and size. The plugin reads the index first, downloads only the kinds whose hash changed, checks hash and size before reading, reads as a stream within bounds (32 MB compressed, 256 MB decompressed, 64 KB per line, 200,000 facts per kind); a bad line is left out and counted, more than 5 % refuse the file; a kind's hash is noted only once its facts are saved (X-166 rule). While v3 is missing or unreadable, the old discoveries.json (v2) is read as before. The player's gist also becomes an index and one file per kind (built from what you read yourself, X-167); the old single file is removed from it at the first upload. The merge tool reads v2 and v3 gists and rebuilds both v2 and v3 (same bytes for the same facts; self-test 25 cases); the repository's v3 set is built from issue 43 (24 kinds, 1,967 facts). Discoveries README, SECURITY.md and DECISIONS in both halves.

## 0.1136.0
- Plan global, X-172 : Découvertes en SQLite (X-172, choix de l'utilisateur du 12/11). Essai d'abord (rapport dans les preuves de X-172, outil tools/SqliteTrialProbe) à 100 000 et 1 million de relevés : une sauvegarde de 1 000 changements prend 0,07 à 0,1 s au lieu de 0,7 à 4 s (fichiers entiers réécrits), avec 18 Mo de mémoire au lieu de 164 Mo à 1,5 Go ; fichier presque deux fois plus petit ; lecture complète aussi rapide ; aucun dégât sur 20 arrêts brutaux ; une lecture par un autre processus (l'application de bureau) ne fait plus échouer les sauvegardes du jeu ; plus de borne de 64 Mo. Les découvertes sont donc maintenant dans Discoveries.db : une ligne par fait, seules les lignes changées écrites, en une transaction ; un échec garde les changements à écrire. Au premier chargement, Discoveries.json et Shared/ sont convertis une fois puis gardés intacts dans « before-sqlite-<date> » ; une base qui existe mais ne s'ouvre pas n'est jamais remplacée (rien n'est enregistré pendant la session) ; si la conversion échoue, les fichiers JSON restent utilisés. Le cache des données téléchargées reste en fichiers : l'essai y montre SQLite plus lent (choix provisoire D-140). Bibliothèques Microsoft.Data.Sqlite 10.0.14 et SQLitePCLRaw 2.1.14 (SQLite 3.54, e_sqlite3.dll native à côté de la DLL ; versions au-dessus de celles signalées vulnérables), déclarées dans README et SECURITY.md, portées par le paquet et l'application de bureau. Suite de 0.1133 : un fait relevé avant que sa sorte partagée soit lue est de nouveau joint à la copie partagée, ses imports gardés.
- Tests : DiscoveriesSqlite1136Tests. Verify.ps1 (agent) : 1886/1886, 0 avertissement, 0 erreur ; DLL 0.1136.0.0. Non validé en jeu.
### English
- Discoveries in SQLite (X-172, the user's choice of 12/11). A trial first (report in the X-172 evidence, tool tools/SqliteTrialProbe) at 100,000 and 1 million facts: a save of 1,000 changes takes 0.07 to 0.1 s instead of 0.7 to 4 s (whole files written again), with 18 MB of memory instead of 164 MB to 1.5 GB; the file is almost half the size; a full read is as fast; no damage over 20 hard stops; a read by another process (the desktop application) no longer makes the game's saves fail; no 64 MB bound any more. The discoveries are therefore now in Discoveries.db: one row per fact, only the changed rows written, in one transaction; a failure keeps the changes to write. At the first load, Discoveries.json and Shared/ are converted once then kept untouched in « before-sqlite-<date> »; a database that exists but does not open is never replaced (nothing is saved for the session); if the conversion fails, the JSON files stay in use. The download cache stays in files: the trial shows SQLite slower there (provisional choice D-140). Libraries Microsoft.Data.Sqlite 10.0.14 and SQLitePCLRaw 2.1.14 (SQLite 3.54, native e_sqlite3.dll beside the DLL; versions above those flagged vulnerable), declared in README and SECURITY.md, carried by the package and the desktop application. Follow-up of 0.1133: a fact seen before its shared kind is read is again joined to the shared copy, its imports kept.
