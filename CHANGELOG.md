# Journal des versions / Changelog

Résumé par version, en français puis `### English` (partie anglaise obligatoire depuis 0.219.0) ; la partie anglaise sert aussi de corps
aux commits et aux notes de release sur GitHub. Preuves citées : docs/evidence/.
Chaque version a été compilée et testée par `scripts/Verify.ps1` ; la validation en jeu est indiquée quand l'utilisateur l'a rapportée.
Ce fichier garde la dernière release et les versions qui suivent ; les plus anciennes sont dans [docs/changelog/](docs/changelog/)
(déplacées par `tools/changelog.py archive`, un fichier par centaine de versions).

## 0.1318.0
- Plan global, X-323 : Eurêka et Bozja › Météo et nuit : chaque monstre retrouve sa prochaine fenêtre (X-323, signalement de l'utilisateur du 14/11 sur 0.1317 : toutes les lignes des quatre zones disaient « Aucune dans les 28 prochaines heures », monstres « nuit » compris). Cause : la page demandait 72 périodes d'un coup au catalogue météo, qui en donne 24 au plus (WeatherCatalog.Forecast lève une exception au-delà) ; l'exception était rattrapée et la page restait sans prévision depuis 0.1241. EurekaNotoriousBoard.Forecast demande les 72 périodes (environ 28 h) par tranches de 24, contiguës. L'auto-contrôle « Eureka notorious monsters » calcule aussi en jeu les fenêtres depuis le catalogue lu (EurekaNotoriousBoard.ForecastCheck) : suspect si un monstre « nuit » n'a pas de fenêtre dans les 70 min réelles. Test EurekaForecast1318 (3), de comportement sur une prévision connue (tirage du jeu, WeatherCatalog.Target, sur une table de météo faite pour le test).
- Pour les joueurs : Eurêka : les fenêtres de météo et de nuit des monstres notoires s'affichent de nouveau au lieu de « Aucune dans les 28 prochaines heures ».
- Tests : EurekaForecast1318Tests. Verify.ps1 (agent) : 2459/2459, 0 avertissement, 0 erreur ; DLL 0.1318.0.0. Non validé en jeu.
### English
- Eureka and Bozja › Weather and night: each monster has its next window again (X-323, user report of 11/14 on 0.1317: every row of the four zones said « none in the next 28 hours », night monsters included). Cause: the page asked the weather catalogue for 72 periods at once, and it gives 24 at most (WeatherCatalog.Forecast throws above); the exception was caught and the page had no forecast since 0.1241. EurekaNotoriousBoard.Forecast asks for the 72 periods (about 28 hours) 24 at a time, contiguous. The « Eureka notorious monsters » self-check also computes the windows in the game from the catalogue read (EurekaNotoriousBoard.ForecastCheck): suspect when a night monster has no window within 70 real minutes. Test EurekaForecast1318 (3), a behaviour test on a known forecast (the game's roll, WeatherCatalog.Target, on a weather table made for the test).
- For players: Eureka: the weather and night windows of notorious monsters show again instead of « none in the next 28 hours ».

## 0.1314.0
- Plan global, X-171 : Deux clients du jeu sur un même profil : la banque affichée suit ce que l'autre client enregistre (X-171, cache de la banque entre deux clients). Avec le fichier de données, chaque changement (capture, oubli, effacement d'un personnage) relit tous les personnages tels qu'ils sont enregistrés, dans la même prise du verrou du profil (PerCharacterBankStore.Apply) : la banque montrée par un client contient les personnages que l'autre a enregistrés depuis, et plus ceux qu'il a effacés. Avant, les autres personnages restaient tels que ce client les avait chargés jusqu'au rechargement suivant (rien n'était perdu sur le disque : seul l'affichage retardait). Sans fichier de données (fichiers par personnage d'avant 0.1149), rien ne change. Les deux cas de l'audit du 12/11 sur la banque étaient déjà traités et testés (chargement repris quand le verrou est tenu, X-170 en 0.1142 ; « inchangé » décidé contre le fichier, 0.1173). Test de comportement TwoClientsBank1314 (2) : deux magasins et deux services sur un vrai fichier de données ; sans la relecture, les deux échouent. Reste au plan : purge du cache partagé (données retéléchargeables).
- Pour les joueurs : Deux clients du jeu sur un même profil : la banque de chacun montre les personnages enregistrés par l'autre.
- Tests : TwoClientsBank1314Tests. Verify.ps1 (agent) : 2448/2448, 0 avertissement, 0 erreur ; DLL 0.1314.0.0. Rien à essayer en jeu.
### English
- Two game clients on one profile: the bank shown follows what the other client saves (X-171, bank cache between two clients). With the data file, each change (a capture, a forget, a character erased) reads every character back as saved, under the same hold of the profile's lock (PerCharacterBankStore.Apply): the bank one client shows holds the characters the other saved since, and no longer those it erased. Before, the other characters stayed as this client had loaded them until the next reload (nothing was lost on disk: only the display lagged). Without the data file (per-character files from before 0.1149), nothing changes. The two bank cases of the 11/12 audit were already handled and tested (load tried again while the lock is held, X-170 in 0.1142; « unchanged » decided against the file, 0.1173). Behaviour test TwoClientsBank1314 (2): two stores and two services on a real data file; without the read-back, both fail. Left in the plan: the shared cache purge (data that can be downloaded again).
- For players: Two game clients on one profile: each one's bank now shows the characters the other one saved.
