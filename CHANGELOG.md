## 0.1817.0
- Plan global, X-804 : Décision de l'utilisateur du 22/11 vers 14 h 35 (après l'explication des risques et des cas PlayerScope et Memoria) : le gist de découvertes d'un joueur, lié par son ticket public, ne garde ses observations avec lieu exact et jour que jusqu'à leur fusion. L'outil de fusion note dans l'en-tête du fichier du joueur le gist et la révision fusionnés (« Gist », « Revision »), ne relit jamais cette révision (sync : « already merged »), et garde les faits d'un joueur par clé (union : un gist de nouveautés seules ne retire rien de v3/) ; la note survit à chaque réécriture du fichier. Le plugin (GistRotation, état github-merged.json sous son propre verrou github.rotate.lock partagé par les clients du profil) lit cette note sur main sans compte ; quand elle désigne son dernier envoi, ces faits sont connus fusionnés, un nouveau gist ne reçoit que les nouveautés (fait nouveau, ou niveaux, valeurs, HQ ou jours changés), le ticket est modifié pour y renvoyer (un nouveau ticket seulement s'il a disparu), puis l'ancien gist est supprimé en entier (supprimer seulement son contenu laisserait les anciennes révisions) ; rien de nouveau : le gist est supprimé, le ticket gardé pour le suivant (« ShareMerged ») ; une suppression refusée est retentée à l'échange suivant ; un fait pas encore fusionné reste toujours dans le gist. Les champs du gist sont repris du disque sous le verrou (un autre client du profil a pu tourner). Avertissement du premier partage, aide de connexion, ticket (en et fr), README, page réseau et DEC-052 mis à jour. Tests de comportement : faux GitHub (fusion confirmée : nouveau gist avec les nouveautés, ticket modifié, ancien gist supprimé dans cet ordre ; rien de nouveau ; note d'une autre révision : rien supprimé ; suppression refusée puis retentée ; deux clients en même temps : un seul nouveau gist, aucun nouveau ticket) et auto-test de l'outil (faits gardés dans v3/, révision notée jamais relue, note gardée).
- Pour les joueurs : découvertes partagées : une fois vos découvertes dans la base commune, votre gist est supprimé et un nouveau ne garde que les nouveautés.
- Tests : GistRotation1817Tests. Verify.ps1 (agent) : 3997/3997, 0 avertissement, 0 erreur ; DLL 0.1817.0.0. Non validé en jeu.
### English
- User decision of 22/11 around 14 h 35 (after the risks and the cases of PlayerScope and Memoria were explained): a player's discoveries gist, linked from their public issue, keeps their sightings with exact place and day only until they are merged. The merge tool notes in the player file's header the gist and revision merged (« Gist », « Revision »), never reads that revision again (sync: « already merged »), and keeps a player's facts by key (union: a gist of news only removes nothing from v3/); the note survives every rewrite of the file. The plugin (GistRotation, state github-merged.json under its own lock github.rotate.lock shared by the profile's clients) reads that note from main without any account; when it names its last upload, those facts are known merged, a new gist gets only what is new (a new fact, or changed levels, values, HQ or days), the issue is edited to link it (a new issue only when it is gone), then the old gist is deleted whole (emptying it would leave the old revisions); nothing new: the gist is deleted, the issue kept for the next one (« ShareMerged »); a refused deletion is tried again at the next exchange; a fact not merged yet always stays in the gist. The gist fields are taken from disk under the lock (another client of the profile may have rotated). First-share warning, connect help, issue (en and fr), README, network page and DEC-052 updated. Behaviour tests: fake GitHub (merge confirmed: new gist with the news, issue edited, old gist deleted in that order; nothing new; a note of another revision: nothing deleted; deletion refused then retried; two clients at once: one new gist, no new issue) and the tool's selftest (facts kept in v3/, noted revision never read again, note kept).
- For players: Shared discoveries: once your discoveries are in the common base, your gist is deleted and a new one keeps only what is new.

## 0.1816.0

L'avertissement avant le premier partage, l'aide de la connexion et de la déconnexion, l'aide de l'échange, la page réseau, le ticket de chaque joueur (en et fr) et le README des découvertes disent : « ce que vous partagez reste dans la base commune, sans votre nom, même si vous arrêtez de partager ». DEC-052 complétée. Test de comportement dans l'auto-test de l'outil (un joueur seul sur un fait se retire : le fait reste, compté comme avant, dans un fichier sans identifiant ni ticket ; reconstruit encore : rien ne change).
- Pour les joueurs : découvertes partagées : l'avertissement dit que ce que vous partagez reste dans la base commune, sans votre nom, même si vous arrêtez de partager.
- Tests : DiscoveryWithdraw1816Tests. Verify.ps1 (agent) : 3991/3991, 0 avertissement, 0 erreur ; DLL 0.1816.0.0. Non validé en jeu.
### English
- User decision of 22/11 around 14 h 20 (after D-220, « the goal is a complete shared base »): when a player withdraws, the merge tool now only removes their numbered file (the link with their GitHub account) and keeps their facts, those only they had included, without any name: `withdraw` gives them to `rebuild` as an anonymous file `players/withdrawn-<random>.jsonl.gz` (no issue nor login, a random name), written after the common set, which counts like a player file (one import per fact; still left out when far outside the others' levels). The warning before the first share, the connect and disconnect help, the exchange help, the network page, each player's issue (en and fr) and the discoveries README say: « what you share stays in the common base, without your name, even if you stop sharing ». DEC-052 completed. Behaviour test in the tool's selftest (a player alone on a fact withdraws: the fact stays, counted as before, in a file without login nor issue; rebuilt again: nothing changes).
- For players: Shared discoveries: the warning says that what you share stays in the common base, without your name, even if you stop sharing.

## 0.1814.0
- Plan global, X-807 : Relecture du bloc 0.1803 à 0.1806 (X-807), mineurs M1 à M4. M1 : `sync` de l'outil de fusion n'écrit plus lui-même les fichiers des joueurs avant `rebuild` : il les lui donne (`pending`), `rebuild` les lit à la place du disque et ne les écrit qu'une fois l'ensemble commun écrit ; un arrêt (garde contre git HEAD, sortie 2) laisse donc chaque fichier tel qu'il était, comme le disent le message « nothing written » et le README. M2 : une seule constante PRODUCER pour la mesure de `fit_bytes` et pour l'écriture (« t » mesurait 25 octets de moins), et `v3_build` refuse un fichier de genre de plus de 32 Mio compressés avant d'écrire (une telle entrée ferait refuser tout l'index au plugin). M3 : le README des découvertes (en et fr) et DEC-052 disent que les plugins jusqu'à 0.1804 refusent tout l'ensemble commun dès qu'un genre dépasse 200 000 faits ; l'outil le signale (WARN) au lieu de borner (l'ensemble compte environ 3 000 faits). M4 : nouvelle image de référence « Discoveries-trial » (base d'essai DiscoveryTrial : colonne « Joueurs », « vu par N joueurs », « vu par un seul joueur », ordre par joueurs). Tests de comportement dans l'auto-test de l'outil (arrêt dans le rebuild de sync : aucun fichier réécrit ni créé ; fichier mesuré égal au fichier écrit ; refus au-delà de la borne).
- Tests : DiscoveryReview1814Tests. Verify.ps1 (agent) : 3988/3988, 0 avertissement, 0 erreur ; DLL 0.1814.0.0. Rien à essayer en jeu.
### English
- Review of the block 0.1803 to 0.1806 (X-807), minors M1 to M4. M1: the merge tool's `sync` no longer writes the player files itself before `rebuild`: it gives them to it (`pending`), `rebuild` reads them instead of the disk and writes them only once the common set is written; a stop (the guard against git HEAD, exit 2) therefore leaves every file as it was, as the « nothing written » message and the README say. M2: one PRODUCER constant for `fit_bytes`' measure and for the write (« t » measured 25 bytes fewer), and `v3_build` refuses a kind file over 32 MiB compressed before writing (such an entry would make the plugin refuse the whole index). M3: the discoveries README (en and fr) and DEC-052 say that the plugins up to 0.1804 refuse the whole common set once one kind passes 200,000 facts; the tool warns (WARN) instead of bounding (the set holds about 3,000 facts). M4: a new reference picture « Discoveries-trial » (trial base DiscoveryTrial: the « Players » column, « seen by N players », « seen by one player only », order by players). Behaviour tests in the tool's selftest (a stop in sync's rebuild: no file rewritten nor created; the file measured equals the file written; refused over the bound).
