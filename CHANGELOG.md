## 0.1171.0
- Plan global, X-181 : Échange GitHub des découvertes, jeton de l'application GitHub (X-181, constats N2, N7, N8, N29 et N30 de la revue de la nuit du 12/11). Deux clients du jeu qui renouvellent le jeton en même temps ne se déconnectent plus : un renouvellement à la fois par profil (fichier de verrou partagé) ; sous ce verrou, les fichiers sont relus et une paire déjà renouvelée par l'autre client est reprise sans redemander à GitHub ; un refus ne déconnecte que si les fichiers tiennent encore le jeton refusé, jamais une paire neuve de l'autre client. « Déconnecter » pendant un renouvellement : rien n'est gardé, aucun fichier de jeton ne revient, rien n'est envoyé ensuite. Un renouvellement accepté par GitHub n'est plus perdu : sa requête a son propre délai, sans dépendre de l'arrêt du plugin (le déchargement l'attend quelques secondes) ; la paire est gardée en mémoire d'abord, puis écrite, et une écriture refusée est refaite avant l'usage suivant. Une réponse 401 avec un jeton de renouvellement en main : un renouvellement forcé et un seul nouvel envoi avant de déconnecter. Après une reconnexion avec un autre compte GitHub, un gist et un ticket propres à ce compte (le login du gist est noté). Correction de X-182 (0.1169), trouvée par la CI de 0.1170 : un second client qui charge pendant la conversion ne plante plus quand le premier déplace l'ancien fichier sous lui (rien n'est écrit, la conversion de l'autre fait foi) ; le test de comportement le rejoue 20 fois.
- Tests : GitHubToken1171Tests, ConcurrentData1169Tests. Verify.ps1 (agent) : 2023/2023, 0 avertissement, 0 erreur ; DLL 0.1171.0.0. Non validé en jeu.
### English
- GitHub exchange of the discoveries, GitHub App token (X-181, findings N2, N7, N8, N29 and N30 of the night review of 11/12). Two game clients renewing the token at once no longer sign each other out: one renewal at a time per profile (shared lock file); under that lock the files are read again and a pair already renewed by the other client is taken without asking GitHub again; a refusal signs out only when the files still hold the refused token, never the other client's new pair. « Disconnect » during a renewal: nothing is kept, no token file comes back, nothing is sent afterwards. A renewal GitHub accepted is no longer lost: its request has its own deadline, independent of the plugin's stop (unloading waits a few seconds for it); the pair is kept in memory first, then written, and a refused write is retried before the next use. A 401 answer with a refresh token in hand: one forced renewal and one more upload before signing out. After reconnecting with another GitHub account, a gist and an issue of that account's own (the gist's login is noted). Fix of X-182 (0.1169), found by the CI of 0.1170: a second client loading during the conversion no longer fails when the first moves the old file under it (nothing is written, the other's conversion holds); the behaviour test replays it 20 times.

## 0.1164.0
- Plan global, X-177 : Saccades (X-177, étape 2) : les réglages s'enregistrent hors du fil du jeu. Les lignes de mesure de 0.1162 montrent que l'enregistrement des réglages par Dalamud prenait 64 à 71 ms sur le fil du jeu à chaque fois, et 371 à 648 ms la première fois après un chargement, alors que mettre les réglages en texte prend environ 2 ms (mesuré sur une copie des réglages de l'utilisateur, 63 Ko). Désormais, seul le texte est fait sur le fil du jeu ; une copie en est refaite à part, vérifiée (elle doit redonner exactement le même texte, sinon elle n'est pas écrite) et enregistrée hors du fil du jeu. Une seule écriture à la fois, dans l'ordre, la dernière en date seulement : une écriture ancienne ne passe jamais après une plus récente. Au moindre doute (copie différente, écriture refusée), Tensho revient à l'ancienne façon, sur le fil du jeu, et le dit une fois dans le journal. À l'arrêt du plugin, ce qui reste est écrit. Le préparateur du texte est chauffé au chargement hors du fil du jeu, pour que le premier enregistrement ne soit pas lent. Les trois autres enregistrements directs (sources des alarmes, zones météo confirmées, demande du jour de la Grande Compagnie) passent par le même chemin. Les autres saccades relevées aujourd'hui (lecteurs, barre de rappel) n'arrivent qu'au chargement du plugin.
- Tests : SettingsSaver1164Tests. Verify.ps1 (agent) : 1993/1993, 0 avertissement, 0 erreur ; DLL 0.1164.0.0. Non validé en jeu.
### English
- Hitches (X-177, step 2): the settings are saved off the game's thread. The measuring lines of 0.1162 show that Dalamud's save of the settings took 64 to 71 ms on the game's thread each time, and 371 to 648 ms the first time after a load, while turning the settings into text takes about 2 ms (measured on a copy of the user's settings, 63 KB). Now only the text is made on the game's thread; a copy of it is rebuilt apart, checked (it must give back exactly the same text, otherwise it is not written) and saved off the game's thread. One write at a time, in order, the latest only: an older write never lands after a newer one. At the slightest doubt (different copy, refused write), Tensho goes back to the old way, on the game's thread, and says so once in the log. When the plugin stops, what is left is written. The text maker is warmed at load off the game's thread, so the first save is not slow. The three other direct saves (alarm sources, confirmed weather zones, today's Grand Company request) go the same way. The other hitches seen today (readers, reminder bar) only happen when the plugin loads.
