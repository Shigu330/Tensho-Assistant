# Journal des versions / Changelog

Résumé par version, en français puis `### English` (partie anglaise obligatoire depuis 0.219.0) ; la partie anglaise sert aussi de corps
aux commits et aux notes de release sur GitHub. Preuves citées : docs/evidence/.
Chaque version a été compilée et testée par `scripts/Verify.ps1` ; la validation en jeu est indiquée quand l'utilisateur l'a rapportée.
Ce fichier garde la dernière release et les versions qui suivent ; les plus anciennes sont dans [docs/changelog/](docs/changelog/)
(déplacées par `tools/changelog.py archive`, un fichier par centaine de versions).

## 0.1280.0
- Plan global, X-01 : Lourdeur (X-01), suite de 0.1279, mesurée au chargement de 0.1279 : la première partie de l'échauffement (code des panneaux avec ce qu'il appelle) atteignait sa borne de 8000 méthodes et n'était pas compilée quand les 3 s de la porte sont arrivées (panneaux ouverts à la borne, première image 147 ms contre 152 à 338 avant). Sonde hors du jeu de la DLL : 391 méthodes de panneaux, 1604 avec leurs appelés directs, 3688 au niveau suivant, jusqu'à 12 762 ; en jeu une méthode se compile en 1,1 ms environ. Borne ramenée à 2000 méthodes, les plus proches d'abord ; la ligne « Panels opened » dit combien étaient compilées au moment de l'ouverture.
- Tests : PanelGate1279Tests. Verify.ps1 (agent) : 2345/2345, 0 avertissement, 0 erreur ; DLL 0.1280.0.0. Rien à essayer en jeu.
### English
- Sluggishness (X-01), continued from 0.1279, measured at the load of 0.1279: the warm-up's first part (the panels' code with what it calls) reached its 8000-method cap and was not compiled when the gate's 3 s came (panels opened at the bound, first frame 147 ms against 152 to 338 before). Offline probe of the DLL: 391 panel methods, 1604 with their direct callees, 3688 at the next level, up to 12,762; in the game a method compiles in about 1.1 ms. Cap brought down to 2000 methods, the nearest first; the « Panels opened » line says how many were compiled when the gate opened.

## 0.1279.0
- Plan global, X-01 : Lourdeur (X-01) : la première image des panneaux et barres libres à chaque chargement (152 à 338 ms mesurés dans dalamud.log le 13/11, sur 38 chargements, avec un avertissement HITCH de Dalamud chaque fois) n'était que de la compilation à la première exécution. L'échauffement compile d'abord le code des panneaux, des barres et de la boucle des observateurs avec ce qu'il appelle dans le plugin : nouveau lecteur des appels (Diagnostics/CallGraph.cs : IL lu, méthodes du plugin suivies, code générique fermé sur un type du plugin compris, constructeurs statiques, borne de 8000 méthodes, arrêt demandé avant chaque méthode). Les panneaux libres et la boucle des observateurs attendent que ce code soit compilé, 3 s au plus après le chargement (Diagnostics/PanelGate.cs, décision de l'utilisateur du 13/11 ; observateurs compris, D-148) ; une ligne « Panels opened … » donne le moment et le temps de leur première image. Mesuré par test : une méthode compilée d'avance avec ce qu'elle appelle ne compile plus rien à son premier appel (sa jumelle froide : 8 méthodes).
- Pour les joueurs : Au lancement du jeu ou à une mise à jour de Tensho, ses panneaux apparaissent une à deux secondes plus tard au lieu de figer l'image un instant.
- Tests : PanelGate1279Tests. Verify.ps1 (agent) : 2345/2345, 0 avertissement, 0 erreur ; DLL 0.1279.0.0. Non validé en jeu.
### English
- Sluggishness (X-01): the first frame of the free panels and bars at each load (152 to 338 ms measured in dalamud.log on 11/13, over 38 loads, with a Dalamud HITCH warning each time) was only first-run compiling. The warm-up now compiles first the code of the panels, the bars and the observers' pass with what it calls in the plugin: new call reader (Diagnostics/CallGraph.cs: IL read, the plugin's methods followed, generic code closed over a plugin type included, static constructors, bounded at 8000 methods, a stop asked before each method). The free panels and the observers' pass wait until that code is compiled, 3 s at most after the load (Diagnostics/PanelGate.cs, the user's decision of 11/13; observers included, D-148); a line « Panels opened … » gives the moment and the time of their first frame. Measured by a test: a method compiled ahead with what it calls compiles nothing on its first call (its cold twin: 8 methods).
- For players: When the game starts or Tensho updates, its panels appear a second or two later instead of freezing the picture for a moment.

## 0.1278.0
- Plan global, X-271 : Outillage (R37) : images de référence des pages de l'application de bureau. Nouveau mode `--references=<dossier> [--compare=<dossier>]` : le vrai plugin dessine chaque page dans une fenêtre cachée (jamais affichée), avec des réglages neufs (aucune donnée du joueur), horloges de l'en-tête coupées et numéro de version fixe (0.0.0) pour que l'image ne change pas à chaque version ; 63 images : état de chargement de trois pages avant les catalogues, chaque page de l'application, l'accueil dans les six thèmes, deux petites fenêtres (navigation repliée), le jardin d'essai dans ses deux vues, le tableau de bord avec une heure d'essai. Chaque image est prise quand la page ne bouge plus (trois images pareilles de suite). Comparaison avec tolérance : SSIM (Wang et al., 2004) par blocs de 8 × 8 sur la luminance, moyenne et part de l'image changée, image des différences ; lecteur PNG (cinq filtres). Mesure : 59 images sur 63 identiques d'une exécution à l'autre ; les autres suivent l'heure d'Eorzéa (météo, récolte, alarmes). Durée : environ 25 s.
- Tests : DesktopImages1278Tests. Verify.ps1 (agent) : 2337/2337, 0 avertissement, 0 erreur ; DLL 0.1278.0.0. Rien à essayer en jeu.
### English
- Tooling (R37): reference images of the desktop application's pages. New mode `--references=<folder> [--compare=<folder>]`: the real plugin draws each page in a hidden window (never shown), with new settings (no player data), the header's clocks off and a fixed version number (0.0.0) so the picture does not change with each version; 63 pictures: the loading state of three pages before the catalogues, every page of the application, the home page in the six themes, two small windows (folded navigation), the trial garden in its two views, the dashboard with a trial hour. Each picture is taken once the page is still (three frames alike in a row). Comparison with tolerance: SSIM (Wang et al., 2004) over 8 x 8 blocks of the luminance, the mean and the part of the picture changed, a diff picture; a PNG reader (five filters). Measured: 59 of 63 pictures identical from one run to the next; the others follow Eorzea time (weather, gathering, alarms). Time: about 25 s.

- Tests : Reload1276Tests. Verify.ps1 (agent) : 2332/2332, 0 avertissement, 0 erreur ; DLL 0.1277.0.0. Rien à essayer en jeu.
### English
- Tooling (R19.3), follow-up of 0.1276: the trial of 0.1276 (player in a duty, simulated) showed the pre-push hook running Verify.ps1 with no switch and building where the game loads, so reloading the game during the duty. Verify.ps1 now reads TENSHO_NORELOAD=1 (set by the publication while the player is busy, inherited by git and its hook) as -NoReload, never for a release.

## 0.1276.0
- Plan global, X-268 : Outillage (R19.3) : quand le joueur est en mission, en pêche en mer ou en contenu classé, une version se publie quand même sans recharger le jeu : Verify.ps1 -NoReload compile le plugin dans artifacts\noreload\ (propriété TenshoOutputPath du csproj), toutes les vérifications tournent sur cette compilation, et la publication libre suivante recompile là où le jeu charge. Verify.ps1 refuse -Release avec -NoReload (une release est toujours compilée là où le jeu la charge), et une compilation faite à part n'est jamais reprise pour celle du jeu. Côté agent : dernière version d'un relais prête à publier par publish.sh --last, sauvegarde et contexte dits à la fin de chaque version, release et annonce refusées hors de la session maître.
- Tests : Reload1276Tests. Verify.ps1 (agent) : 2331/2331, 0 avertissement, 0 erreur ; DLL 0.1276.0.0. Rien à essayer en jeu.
### English
- Tooling (R19.3): while the player is in a duty, an ocean voyage or competitive content, a version is still published without reloading the game: Verify.ps1 -NoReload builds the plugin into artifacts\noreload\ (csproj property TenshoOutputPath), every check runs on that build, and the next free publish builds again where the game loads it. Verify.ps1 refuses -Release with -NoReload (a release is always built where the game loads it), and a build made beside the game is never taken for the game's one.

## 0.1275.0
- Plan global, X-267 : Outillage (R36) : tous les tests tournent en parallèle, une classe par fil, les classes trouvées seules (plus de liste à tenir dans Program.cs), quarantaine datée et classes [SerialTests] prévues ; Verify.ps1 les lance pendant la publication et le dessin de l'application de bureau (tests : 106 s l'un après l'autre, 16 s en parallèle). Le test fragile « Disk cache survives a new instance… » (CI rouge de 0.1267) est corrigé à la cause : un fichier tenu un instant par un autre programme faisait échouer l'écriture du cache local ; le remplacement est maintenant réessayé (AtomicFile.OverwriteWhenFree, pour le cache et toute écriture atomique). Une course dans un test de l'enregistrement des réglages, révélée par le parallèle, est corrigée. publish.sh refuse un test existant modifié ou retiré, ou un compte de tests en baisse, sans raison écrite (scripts/agent/oracle.py).
- Tests : Parallel1275Tests. Verify.ps1 (agent) : 2330/2330, 0 avertissement, 0 erreur ; DLL 0.1275.0.0. Rien à essayer en jeu.
### English
- Tooling (R36): every test runs in parallel, one class per thread, classes found by themselves (no list to keep in Program.cs any more), dated quarantine and [SerialTests] classes provided; Verify.ps1 runs them while the desktop application is published and drawn (tests: 106 s one after the other, 16 s in parallel). The flaky test « Disk cache survives a new instance… » (red CI of 0.1267) is fixed at its cause: a file held an instant by another program made the local cache's write fail; the replace is now tried again (AtomicFile.OverwriteWhenFree, for the cache and every atomic write). A race in a test of the settings saver, shown by the parallel run, is fixed.

## 0.1274.0
- Plan global, X-264 : X-264, suite (constat du journal du jeu après 0.1269 à 0.1273) : la part « StateBar » de la première image après un chargement était passée d'environ 4 ms à 7 à 11 ms. Cause : depuis les jauges, l'échantillonnage de l'historique était appelé dès la première image, seulement pour ressortir aussitôt (le délai de 20 s du démarrage), mais cet appel faisait compiler son code sur le fil du jeu. Plus rien du tableau de bord n'est appelé avant le délai de démarrage : le battement ressort d'abord. Le tableau de bord ouvert par le joueur lit toujours tout de suite ; l'historique commence toujours 20 s après le chargement. La première image elle-même n'avait pas bougé hors du bruit (186 à 214 ms sur ces versions, 165 à 213 ms avant). Test : DashboardFirstFrame1274Tests.
- Tests : DashboardFirstFrame1274Tests. Verify.ps1 (agent) : 2323/2323, 0 avertissement, 0 erreur ; DLL 0.1274.0.0. Rien à essayer en jeu.
### English
- X-264, follow-up (found in the game's log after 0.1269 to 0.1273): the « StateBar » part of the first frame after a load had gone from about 4 ms to 7 to 11 ms. Cause: since the gauges, the history's sampling was called from the first frame, only to return at once (the 20 s start delay), but that call had its code compiled on the game's thread. Nothing of the dashboard is called before the start delay any more: the tick returns first. The dashboard opened by the player still reads at once; the history still starts 20 s after the load. The first frame itself had not moved beyond the noise (186 to 214 ms on these versions, 165 to 213 ms before). Test: DashboardFirstFrame1274Tests.
