## 0.1720.0
- Plan global, X-473 : Fenêtre de chat Tensho, info-bulles des actions (X-473, demande de l'utilisateur du 15/11 ; lignes « pieces of a combat line » lues le 21/11, T-0.1715-2). Le jeu ne lie aucune action : dans une ligne de combat, le nom d'une action est un texte coloré (couleur mise, lueur, texte, lueur, couleur ôtée). Le lecteur distingue désormais une couleur mise d'une couleur ôtée (UIForegroundPayload, ChatPayloadKind.Colour) ; dans une ligne de combat, hors d'un lien, un texte coloré seul devient le nom d'une action (ChatSegmentKind.ActionName), dessiné comme le texte du message, gardé comme texte par l'historique. Au survol : icône, nom et description (feuilles Action et ActionTransient, langue du client), seulement si le nom désigne une seule action à coup sûr : ligne d'un joueur → actions des joueurs de ce nom (hors JcJ), sinon toutes les actions de ce nom ; lignes de la feuille qui diffèrent → pas d'info-bulle (ChatActionTips, pur). Table des noms faite une fois au premier survol, sur un fil à part. Infos-bulles des statuts et des actions par un seul dessin (DrawChatGameTip). Avec 0.1715 (statuts), 0.1627 (joueurs) et X-683 (objets), le point est complet ; restent les essais en jeu. Preuve docs/evidence/0.1720-chat-action-names.md.
- Pour les joueurs : fenêtre de chat : dans les lignes de combat, survoler le nom d'une action montre son icône et sa description, comme dans le jeu.
- Tests : ChatActions1720Tests. Verify.ps1 (agent) : 3660/3660, 0 avertissement, 0 erreur ; DLL 0.1720.0.0. Non validé en jeu.
### English
- Tensho chat window, the actions' tooltips (X-473, the user's request of 15/11; « pieces of a combat line » lines read on 21/11, T-0.1715-2). The game links no action: in a combat line, an action's name is a coloured text (colour on, glow, text, glow, colour off). The reader now tells a colour on from a colour off (UIForegroundPayload, ChatPayloadKind.Colour); in a combat line, outside a link, a coloured text alone becomes an action's name (ChatSegmentKind.ActionName), drawn as the message's text, kept as text by the history. On hover: icon, name and description (Action and ActionTransient sheets, the client's language), only when the name is one action for sure: a player's line → the players' actions of that name (not PvP), else every action of that name; rows that differ → no tooltip (ChatActionTips, pure). The table of names is made once at the first hover, on a thread of its own. The statuses' and actions' tooltips drawn by one method (DrawChatGameTip). With 0.1715 (statuses), 0.1627 (players) and X-683 (items), the point is complete; the in-game tests remain. Evidence docs/evidence/0.1720-chat-action-names.md.
- For players: Chat window: in the combat lines, hovering an action's name shows its icon and description, as in the game.

## 0.1719.0
- Plan global, X-225 : Page Rappels, tours éthéréens de la compagnie (X-225, demande de l'utilisateur du 12/11 ; relevé en jeu du 21/11, essai T-0.1234-1). La fenêtre de la base de tour éthéréen (AetherialWheel) est lue une fois par seconde tant qu'elle est ouverte : pour chaque emplacement, le tour posé et sa charge (disposition lue le 21/11 et vérifiée à chaque lecture : au plus 6 emplacements, un objet qui est un tour de la feuille AetherialWheel, chargé ou non, une charge de 0 à 100 ; sinon rien n'est lu, dit une fois). Chaque tour est gardé par maison avec le moment où il sera chargé, d'après les heures du jeu (20, 45 ou 70 selon le grade) : vu au moment de l'installer, l'heure exacte ; sinon d'après sa charge, entre (99 − p) % et (101 − p) % des heures, l'écart resserré à chaque nouveau pourcentage. Nouvelle ligne « Tours éthéréens » de la page Rappels (en charge, chargés, prochaine fin ; tour par tour : chargé, chargé à, ou chargé entre deux heures) ; les alarmes automatiques (réglage commun, activé par défaut) sonnent à l'heure la plus tardive de chaque tour ; un tour retiré perd son alarme ; Discord suit la case de la ligne. Mots du jeu (Addon 8458, 8630, 8640). Preuve 0.1234 complétée ; inventaire : fenêtre AetherialWheel et HousingManager.GetCurrentHouseId.
- Pour les joueurs : rappels : une nouvelle ligne « Tours éthéréens » dit quand chaque tour de la base de la compagnie sera chargé (lu quand vous ouvrez la base), avec une alarme automatique.
- Tests : AetherialWheels1719Tests. Verify.ps1 (agent) : 3655/3655, 0 avertissement, 0 erreur ; DLL 0.1719.0.0. Non validé en jeu.
### English
- Reminders page, the company's aetherial wheels (X-225, the user's request of 12/11; in-game reading of 21/11, test T-0.1234-1). The wheel stand's window (AetherialWheel) is read once a second while it is open: each slot's wheel and charge (layout read on 21/11 and checked at each reading: at most 6 slots, an item that is a wheel of the AetherialWheel sheet, primed or not, a charge from 0 to 100; else nothing is read, said once). Each wheel is kept per house with when it is primed, from the game's hours (20, 45 or 70 by grade): seen being set, the exact time; otherwise from its charge, between (99 − p) % and (101 − p) % of the hours, the bounds narrowed at each new percent. New « Aetherial wheels » row of the Reminders page (charging, primed, next end; wheel by wheel: primed, primed at, or primed between two times); the automatic alarms (the common setting, on by default) ring at each wheel's latest time; a wheel taken off loses its alarm; Discord follows the row's box. The game's words (Addon 8458, 8630, 8640). Evidence 0.1234 completed; inventory: the AetherialWheel window and HousingManager.GetCurrentHouseId.
- For players: Reminders: a new « Aetherial wheels » row says when each wheel on the company's stand is primed (read when you open the stand), with an automatic alarm.

## 0.1718.0
- Plan global, X-715 : Fenêtre de chat Tensho, menu du jeu d'un joueur loin (X-715, choix D-202 b de l'utilisateur du 21/11 : mesurer d'abord). Sonde en mode développeur, en lecture seule : un crochet sur LogViewer.HandleLinkClick (signature de FFXIVClientStructs, pointeur vérifié d'abord), actif seulement en mode développeur, copie les champs du lien cliqué dans le chat du jeu (type, numéro, index, groupe, trois valeurs) puis appelle toujours la fonction du jeu avec ce qu'elle a reçu ; le menu que le jeu ouvre ensuite depuis son chat est lu par IContextMenu de Dalamud et comparé au clic (moitiés de l'identifiant de contenu, monde, identifiant d'objet). Jamais un nom ni un identifiant entier dans le journal (petites valeurs telles quelles, grandes par leurs trois derniers chiffres hexadécimaux) ; 40 lignes au plus par session ; rien pendant une coupure (JcJ, contenus classés). Inventaire des points sensibles aux mises à jour : quatre crochets. Preuve docs/evidence/0.1718-chat-link-click-probe.md ; décision qui suit la mesure (imiter ou non, pour et contre) : D-203.
- Tests : ChatLinkProbe1718Tests. Verify.ps1 (agent) : 3650/3650, 0 avertissement, 0 erreur ; DLL 0.1718.0.0. Non validé en jeu.
### English
- Tensho chat window, the game's menu of a player far away (X-715, the user's choice D-202 b of 21/11: measure first). A developer-mode probe, read-only: a hook on LogViewer.HandleLinkClick (FFXIVClientStructs' signature, pointer checked first), on in developer mode only, copies the fields of the link clicked in the game's chat (type, id, index, group, three values), then always calls the game's function with what it was given; the menu the game then opens from its chat is read through Dalamud's IContextMenu and compared with the click (halves of the content id, world, object id). Never a name nor a whole identifier in the log (small values as they are, large ones by their last three hexadecimal digits); 40 lines at most per session; nothing during a cut (PvP, ranked contents). Inventory of what a game update can break: four hooks. Evidence docs/evidence/0.1718-chat-link-click-probe.md; the decision after the measure (imitate or not, pros and cons): D-203.

## 0.1717.0
- Plan global, X-717 : Fenêtre de chat Tensho, relecture du bloc 0.1713 à 0.1716 (X-717). M1 : les joueurs mis en avant (et les joueurs cachés) forment un ensemble découpé une fois, redécoupé seulement quand leur liste change (ChatPlayerSet) : chaque ligne dessinée cherche son auteur d'un coup au lieu de redécouper la liste à chaque image et de la parcourir nom par nom (jusqu'à environ 250 noms depuis 0.1716, trois fois par ligne, et encore pour chaque fenêtre détachée) ; même réponse qu'avant (nom avant le monde ou nom entier, sans tenir compte des majuscules). M2 : la fenêtre de chat garde un onglet dans chaque contexte : quand le profil d'un contexte ne montre que des onglets détachés, le premier reste dans la fenêtre de chat (sa propre fenêtre se cache, son numéro est gardé) ; un onglet ne se détache plus s'il est le dernier que le contexte montre dans la fenêtre de chat ; dans les réglages, « Retirer » est grisé pour le dernier onglet resté dans la fenêtre de chat, avec la raison. M3 : l'avis « liste pleine » sous la boîte disparaît dès que le texte tapé change ou que la liste change par un autre chemin (menu d'un joueur).
- Pour les joueurs : fenêtre de chat : elle garde un onglet dans chaque contexte, le dernier onglet qui y reste ne peut plus être retiré, et l'avis « liste pleine » disparaît dès que la liste ou le texte tapé change.
- Tests : ReviewMinors1717Tests. Verify.ps1 (agent) : 3646/3646, 0 avertissement, 0 erreur ; DLL 0.1717.0.0. Non validé en jeu.
### English
- Tensho chat window, review of block 0.1713 to 0.1716 (X-717). M1: the players put forward (and the hidden ones) form a set cut once, cut again only when their list changes (ChatPlayerSet): each line drawn looks its sender up at once instead of cutting the list again at each frame and walking it name by name (up to about 250 names since 0.1716, three times per line, and again for each detached window); same answer as before (name before the world or whole name, capitals ignored). M2: the chat window keeps a tab in every context: when a context's profile shows only detached tabs, the first stays in the chat window (its own window hides, its number is kept); a tab is no longer detached when it is the last the context shows in the chat window; in the settings, « Remove » is greyed for the last tab left in the chat window, with the reason. M3: the « list full » line under the box goes as soon as the text typed changes or the list changes another way (a player's menu).
- For players: Chat window: it keeps a tab in every context, the last tab left in it can no longer be removed, and the « list full » warning goes away once the list or the text typed changes.
